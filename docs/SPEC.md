# 개발 명세 — 은우 북카드 (영어책 학습 카드 생성 웹앱)

> 이 문서가 앱 전체의 개발 명세다. AI 호출의 상세 구현 원본은 `docs/harness/english.md`(AI 하네스 명세).
> 명세에 없는 결정은 "가족용 소규모 앱, 단순함 우선" 원칙으로 판단하고, 판단 내용을 README에 남긴다.

## 0. 제품 한 줄 요약

초등학생 아이가 읽을 영어책의 표지 사진을 올리거나 제목을 입력하면, 그 책에 맞는 학습 카드(필수 단어장 + 한/영 대화 질문 + 읽기 전/중/후 활동)를 생성하고, 만든 카드를 '서재'에 쌓아 아이의 읽기 이력을 관리하는 가족용 웹앱.

## 1. 배경과 절대 원칙

- 사용자: 엄빠(관리자)와 초등학생 아이 '은우'. UI 언어는 한국어.
- **본문 취급 원칙 (최우선):**
  - **본문 이미지는 요약 생성의 근거로만 쓰고, 원문을 그대로 옮겨 적지 않는다.** 부모가 손에 든 책을 찍어 올리는 것은 허용하되, 카드에 남는 것은 우리말 요약·질문뿐이다.
    - 이 규칙을 남기는 이유는 저작권이 아니라 **제품 품질**이다 — 부모가 원하는 건 아이를 이끌 한국어 맥락이지 영어 원문이 아니다. 원문은 이미 책으로 손에 들고 있다. 카드에 영어 본문을 그대로 박으면 카드만 두꺼워지고 실사용 가치가 없다.
    - 예외: 제목·챕터 제목·등장인물 이름은 구조 정보이므로 그대로 써도 된다.
    - 이 규칙은 **책 → 학습 카드**에 걸린다. 가족이 가진 **교재를 학습용으로 옮기는** 기능 — 영어단어장 정복(§14-2)과 아빠의 영어 표현집(§20) — 은 판독이 곧 원문 전사다(목적이 다르다). 그 둘도 사진 원본은 저장하지 않고, 아빠의 영어 교재 전사본은 공개 저장소에 넣지 않는다(§20-6).
  - **업로드된 원본 사진은 저장하지 않는다.** 판독·요약 후 버린다 (개인정보 최소화이자 비용·구조 문제 — 30장×200KB면 권당 6MB, Firestore 문서 상한 1MB. 요약 텍스트만 남기면 권당 수 KB다).
  - 학습 카드는 메타데이터(제목, 저자, AR/Lexile 지수, 단어 수, 주제, 공개된 소개글), 뒤표지·책날개 소개글, 본문/목차 사진의 우리말 요약을 근거로 **새로 창작한다.**
  - AI 생성 프롬프트에 "영어 원문을 그대로 옮겨 적지 말 것"·"받은 근거를 넘어서는 내용을 지어내지 말 것" 가드레일을 반드시 포함한다. zod에서도 영어 원문 전사를 실제로 거부한다(연속 영어 8단어).
  - 외부 사이트의 본문·데이터 스크래핑 코드를 작성하지 않는다 (AR BookFinder 등 크롤링 금지 — 스티커 판독과 수동 입력으로 해결).
- 가족용 개인 도구다. 로그인 없음(비공개 URL 운영). 과설계 금지.

## 2. 기술 스택 (확정)

- Next.js (App Router, TypeScript), 모바일 우선 반응형 — 엄빠가 폰으로 표지를 찍어 올리는 것이 기본 시나리오
- 스타일: Tailwind CSS (참고 디자인 재현이 더 쉬우면 CSS Modules 병용 가능)
- AI: OpenAI API — 표지 판독(vision)과 카드 생성 모두. Responses API(현행 표준) 사용, 출력은 Structured Outputs(json_schema, strict: true)로 강제. 모델 ID는 하드코딩하지 말고 env `OPENAI_MODEL`로 받되, 기본값은 OpenAI 공식 문서에서 확인한 비전(이미지 입력)과 Structured Outputs를 모두 지원하는 최신 모델로 설정
- 책 식별: Google Books API(기본) + Open Library API(폴백)
- DB: Firestore (Native mode)
- 배포: GCP Cloud Run (region: asia-northeast3 서울). 소스 배포(`gcloud run deploy --source .`) 기준으로 README 작성
- 비밀값: Cloud Run 환경변수 또는 Secret Manager. API 키를 클라이언트 번들에 절대 노출하지 않는다. 모든 외부 API 호출은 서버(route handler)에서만. `.env.example` 제공, 실제 키 커밋 금지

## 3. 핵심 플로우

```
[입력] 표지 사진 1~3장 (표지 / 정보 스티커 / 뒤표지)  또는  제목(+저자) 텍스트
   ↓
(1) 판독 — OpenAI vision (호출 A)
    사진에서 추출: 제목, 저자, 시리즈, AR 지수, Lexile, 단어 수,
    AR 퀴즈번호, 픽션/논픽션 (한국 원서몰 스티커에 이 정보가 인쇄되어 있음)
    + 뒤표지·책날개 소개글(blurbText) — 출판사가 쓴 실제 줄거리라 카드 품질에 직결
   ↓
(2) 식별 — Google Books API (제목+저자 검색)
    확보: ISBN, 소개글(description), 카테고리, 썸네일 URL
    실패 시 Open Library 폴백, 둘 다 실패 시 판독값만으로 진행
   ↓
(2′) [선택] 본문·목차 촬영 — OpenAI vision (호출 A′)
    본문 사진 N장(그림책 펼침면 12~16장) 또는 목차 사진 1~2장 → 장면별 우리말 요약
    사진 6장씩 배치로 나눠 병렬 호출. 사진은 저장하지 않고 요약만 남긴다
    건너뛰면 (3)이 메타데이터·소개글만으로 진행한다 — 이 단계는 카드 생성의 전제가 아니다
   ↓
(3) 생성 — OpenAI API (호출 B)
    §6 스키마의 학습 카드 JSON 생성 (§7 프롬프트 명세)
    근거: 메타데이터 + 공개 소개글 + blurbText + 장면 요약
   ↓
(4) 렌더링·저장 — 카드 화면 표시, Firestore 저장, 인쇄 지원
```

- 진행 UI: "표지 읽는 중 → 책 확인 중 → (본문 읽는 중) → 카드 만드는 중" 상태 표시
- 근거가 두꺼울수록 줄거리를 길게 쓴다(3~4 → 8~10문장). 근거가 얇은데 늘리면 환각이 늘어나므로 근거의 **양**(장면 수)에서 구간을 계산해 조건부로만 늘린다 (docs/harness/english.md §3-2)
- 제목만 입력한 경우: (1) 생략, (2)부터 시작. AR/Lexile을 얻지 못하면 소개글·대상 연령으로 레벨을 추정하고 카드에 "레벨 추정" 배지를 표시한다

## 4. 화면 명세 (3페이지)

### 4-1. 홈 `/`

- 큰 버튼 2개: "표지 사진으로 만들기"(`<input type="file" accept="image/*" capture="environment" multiple>` **최대 3장 — 표지 / 정보 스티커 / 뒤표지**), "책 이름으로 만들기"(제목 필수, 저자 선택)
  - 상한이 3장인 이유: 뒤표지 소개글(blurbText)이 줄거리의 실질 근거인데, 2장이면 사용자가 정보 스티커를 포기해야만 뒤표지를 찍을 수 있다. 세 면은 서로 대체 불가한 정보를 담는다
  - 무엇을 찍어야 하는지 UI에 안내한다. 3장을 다 찍을 필요는 없다 — 있는 것만 찍어도 된다
- 최근 만든 카드 3개 미리보기 (표지 썸네일 + 제목 + AR 칩)

### 4-2. 카드 `/card/[id]`

§8 디자인 그대로. 구성 순서:

1. 북헤더: 이모지 커버, 제목, 저자·시리즈, 메타 칩(AR / Lexile / 단어 수 / 픽션·논픽션)
2. 이 책은? (2문장 소개 + 레벨 설명 1문장)
3. 줄거리 미리보기 (storyOutlineKo 3~10문장, 결말 미공개 — 논픽션은 "내용 미리보기" 제목. 근거 배지는 storySource로 판정: 예상 / 소개글 기반 / 목차 기반 / 본문 확인. 필드가 없는 기존 카드는 섹션 생략)
4. [sceneDigest가 있을 때만] 장면별 메모 — 라벨(예 "1~2쪽" / "3장: Pooh와 꿀단지") + 우리말 요약 + 그 자리에서 던질 질문(askKo). `confidence: "low"`는 재촬영 안내, `gapBefore: true`는 "사진이 빠졌을 수 있어요" 표시
   - **기본 접힘(`<details>`), 인쇄에서는 제외한다.** 버그가 아니라 의도된 결정이니 되돌리지 말 것:
     - 카드는 A4 **1~2쪽 인쇄물**이다(아래 인쇄 항목). 그림책 펼침면 16장이면 장면도 16개라, 장면마다 요약 + 질문을 카드 본문에 펼치면 그것만으로 목표 분량을 넘긴다. 그러면 카드가 아니라 책이 된다
     - 인쇄물에는 확장된 `storyOutlineKo`(최대 10문장)가 이미 들어간다 — 줄거리 맥락은 종이에도 남는다. 이 10문장이 분량 다이얼의 절대 상한인 이유가 여기다(A4 1~2쪽)
     - 장면 메모는 **책장을 넘기며 그 자리에서 보는** 물건이라(askKo가 핵심) 손에 든 화면 쪽이 실사용에 맞다. 종이로 뽑아 두면 지금 몇 쪽인지 눈으로 찾아야 한다
   - 누락 안내에 **개수를 쓰지 않는다** ("한 장면이 빠졌어요" ✗ / "이 사이가 비어 있어요" ○). `gapBefore`는 불리언이라 연속 누락도 마커가 1개이고, 마지막 배치가 실패하면 마커 자체가 없다(docs/harness/english.md §2A-5). 정확한 범위는 촬영 직후 검토 화면에서 `failedBatchCount`와 배치 범위로 따로 알린다
5. STEP 1 읽기 전 워밍업 (2개)
6. STEP 2 필수 단어장 (12개, 표: 단어·한글발음 / 뜻 / 쉬운 영어 풀이 / 예문) + 엄빠 티칭 포인트 박스
7. STEP 3 읽으면서 미션 (3개)
8. STEP 4 읽고 나서 대화 (8개, 유형 태그 + 영어 질문 + 한국어 질문 + 부모용 힌트)
9. [논픽션만] 엄빠 찬스: 재미있는 사실 (4개, 영/한)
10. 확장 놀이 (2개)

- 단어마다 스피커 버튼: Web Speech API(speechSynthesis, en-US)로 발음 재생 — 외부 API·비용 없음
- "읽어주기 영상 찾기": 원래는 `https://www.youtube.com/results?search_query={제목 저자 read aloud}` 검색 결과를 새 탭으로 여는 링크였다(API 불필요). **지금은 이 자리가 카드 생성 중 낭독 영상 자동 검색·선택 → 자막 grounding → 챕터 리더로 확장됐다 — §14-1 참조.**
- 인쇄 버튼: A4 세로, 책당 1~2쪽 목표의 인쇄 CSS
- "다시 생성" 버튼: 같은 책으로 새 카드 생성(기존 카드 유지)

### 4-3. 서재 `/library`

- 카드 목록: 표지 썸네일, 제목, AR, 만든 날짜. 제목 검색
- 상단 요약: 총 권수, 최근 30일 권수, AR 레벨 추이 미니 차트 (읽은 날짜 x AR 지수 — 간단한 인라인 SVG로 충분, 차트 라이브러리 금지)
- 읽음 기록: 카드 화면의 "오늘 읽었어요" 체크 → readings에 기록, 별점(1~5) 선택

## 5. 데이터 모델 (Firestore)

```
books/{bookId}
  title, author, series?, isbn?, arLevel?: number, lexile?: number,
  wordCount?: number, arQuizNo?: string, isFiction: boolean,
  topic: string, coverUrl?, googleBooksId?, levelEstimated: boolean, createdAt,
  blurbText?: string,              // 호출 A가 뒤표지·책날개에서 읽은 소개글
  sceneKind?: 'toc' | 'pages',     // 아래 sceneDigest의 출처
  sceneDigest?: SceneDigestItem[]  // 호출 A′의 장면별 요약 (§6)

cards/{cardId}
  bookId, content: Card(§6 JSON), model: string, createdAt

readings/{readingId}
  bookId, readAt, rating?: number, noteKo?: string
```

- 업로드된 사진 원본은 판독 후 저장하지 않는다(§1). 표지 이미지는 Google Books 썸네일 URL을 사용
- `blurbText`·`sceneDigest`를 **books에 보관하는 이유**: "다시 생성"이 사진 재업로드 없이 같은 근거로 돌아야 한다. 사진을 저장하지 않으므로 요약이 유일한 사본이다
- `sceneDigest`는 카드에도 복사해 저장한다(`cards.content.sceneDigest`) — 카드는 만든 시점의 근거를 그대로 담은 스냅샷이어야 나중에 book이 갱신돼도 카드 내용과 어긋나지 않는다
- Firestore 접근은 서버에서만(Admin SDK + Cloud Run 서비스 계정 ADC). 클라이언트 직접 접근 없음 → 보안 규칙은 전체 차단으로 단순화

## 6. 학습 카드 콘텐츠 JSON 스키마

TypeScript 타입으로 그대로 구현하고, zod로 런타임 검증하라.

```ts
interface Card {
  bookIntroKo: string;          // "이 책은?" 2문장. 아이 흥미 유발형
  levelNoteKo: string;          // AR 수치를 부모에게 쉽게 풀어주는 1문장
  storyOutlineKo?: string;      // 줄거리 미리보기 (논픽션은 내용 소개, 결말 미공개). 분량은 근거의 양에서 계산한다 — metadata 3~4 / blurb 4~6 / toc·pages는 장면 수 N에서 ⌈N/2⌉+2 ~ N+2 (3~10문장 경계, harness/english.md §3-2). 신규 생성엔 필수 — 기존 저장 카드에는 없음
  storySource?: StorySource;    // 줄거리의 근거 두께. 배지: 예상 / 소개글 기반 / 목차 기반 / 본문 확인
  /** @deprecated storySource로 대체. 구 저장 카드를 읽기 위해서만 남긴다 — 배지 판정은 resolveStorySource() */
  storyIsGuess?: boolean;
  sceneDigest?: SceneDigestItem[];  // 호출 A′의 장면별 요약. 호출 B의 출력이 아니라 라우트가 붙여 넣는다
  beforeReading: { ko: string }[];   // 2개. 표지 추리 놀이 1개 포함
  vocab: VocabItem[];                // 12개 (AR<2면 10개)
  teachingTipKo: string;             // 발음·문법 등 티칭 포인트 1개
  whileReading: { ko: string }[];    // 3개. 몸놀이·미션형
  questions: QuestionItem[];         // 8개 (AR<2면 6개)
  funFacts?: { en: string; ko: string }[]; // 논픽션만 4개. 일반 상식 수준의 사실
  activities: { titleKo: string; descKo: string }[]; // 2개. 몸으로 노는 확장 놀이
}

interface VocabItem {
  word: string;
  pronKo: string;               // 한글 발음 표기, 예: "팩"
  meaningKo: string;            // 한글 뜻
  easyEn: string;               // 아이 눈높이 영영 풀이, 예: "a wolf family"
  exampleEn: string;            // 새로 창작한 간단 예문 (책 문장 아님)
  difficulty: 'basic' | 'challenge';  // challenge는 2~3개만
  isCore?: boolean;             // 제목·주제의 핵심 단어 1개에 표시
}

interface QuestionItem {
  type: '사실확인'|'인물'|'배경'|'사건'|'인과'|'감정'|'예측'|'결말'|'비교'|'상상'|'내생각'|'나와연결';
  en: string;                   // 아이에게 그대로 읽어줄 쉬운 영어 질문
  ko: string;                   // 자연스러운 우리말 질문 (직역 금지)
  hintKo?: string;              // 부모용 힌트·정답·코칭 팁 (절반 정도만)
}

type StorySource = 'metadata' | 'blurb' | 'toc' | 'pages';  // 근거의 두께 (얇은 → 두꺼운 순)

interface SceneDigestItem {
  seq: number;                  // 촬영 순서 (1부터, 병합 시 다시 매김)
  labelKo: string;              // "1~2쪽" 또는 "3장: Pooh와 꿀단지"
  summaryKo: string;            // 1~3문장 우리말 요약 (영어 원문 전사 아님)
  askKo?: string | null;        // 그 장면에서 부모가 던질 질문 1개 — 이 기능의 핵심 가치
  confidence?: 'high'|'medium'|'low' | null;  // low면 재촬영 유도
  gapBefore?: boolean | null;   // 앞 장면과 이어지지 않음 (사진 누락·순서 뒤바뀜). 메우려 지어내지 않는다
}
```

- 질문 8개는 책 전체 기준이라 부모가 "언제 던질지"를 판단해야 한다. `askKo`는 장면에 붙어 그 부담을 없앤다 — 이 필드가 본문 촬영 기능의 핵심 가치다

## 7. AI 호출 명세

**구현 원본은 저장소의 `docs/harness/english.md`(AI 하네스 명세)다. 그 문서의 시스템 프롬프트·JSON Schema·공통 래퍼 규칙을 그대로 코드로 옮겨라(`lib/ai/` 모듈).** 아래는 요약이다.

### 7-1. 표지 판독 (vision, 호출 A)

- 입력: 이미지 1~3장 (표지 / 정보 스티커 / 뒤표지, base64 data URL). 출력: books 필드 형태의 JSON — Structured Outputs(json_schema, strict: true)로 강제
- 판독 대상: 표지의 제목·저자·시리즈 + 정보 스티커의 AR 지수, Lexile, 단어 수(Word Count), AR 퀴즈번호, Fiction/NonFiction 표기 (한국 원서몰 스티커에 이 항목들이 인쇄되어 있음)
- 뒤표지·책날개 소개글(blurbText)도 함께 판독한다 — 출판사가 쓴 실제 줄거리라 카드 품질에 직결된다. 표지 사진은 지금까지 메타데이터만 뽑고 버려졌다. 이 판독을 살리려면 상한이 3장이어야 한다(§4-1)
- 스티커가 없으면 있는 정보만 채우고 나머지는 null

### 7-1′. 본문·목차 판독 (vision, 호출 A′)

- 입력: 본문/목차 사진 N장. 출력: 장면별 요약 배열(`SceneDigestItem[]`) — 사진 6장씩 배치로 나눠 병렬 호출
- 상세는 docs/harness/english.md §2A. 배치 실패는 그 배치의 사진만 잃고 나머지 장면은 살린다
- 프롬프트 필수 요건: 영어 원문 전사 금지(§1), 못 읽은 장면은 confidence를 낮출 것, 페이지 누락(gapBefore)을 지어내 메우지 말 것, 마지막 구간은 결말을 흐릴 것
- 본문 사진을 호출 B에 그대로 붙이지 않은 이유: 이미지 토큰이 한 호출에 몰리고 모델이 뒷장을 소홀히 보며 실패 시 전량 재시도가 된다. 2단계로 나누면 "다시 생성"이 사진 재업로드 없이 저장된 요약만으로 된다

### 7-2. 카드 생성

시스템 프롬프트 완성본은 docs/harness/english.md에 있다. 아래 템플릿은 핵심 요건 요약이니, 구현 후 빠진 요건이 없는지 대조용으로 써라:

- 마지막 질문은 책을 아이의 일상과 연결하는 질문으로 마무리한다.

[논픽션 전용]

- 외부 사이트 크롤링·스크래핑
- 로그인·회원 시스템, 다국어 UI, 상태관리·차트 라이브러리 추가
- 모델 ID 하드코딩, 클라이언트에서 직접 AI 호출, API 키 노출
- 교재 사진·전사본(아빠의 영어 표현집 가져오기 파일 등)을 저장소나 `public/`에 넣기 — 저장소는 공개이고, `public/`의 정적 파일은 PIN 게이트를 거치지 않는다. 교재는 git 밖(`data/private/`)에 두고 앱의 "파일로 가져오기"로만 넣는다(§20-6)

## 14. 확장 기능 (2026-08 — §1~13 기본 흐름 위에 얹힌 것)

> AI 호출·프롬프트·JSON Schema·zod·grounding 규칙의 상세는 모두 `docs/harness/english.md`에 있다(호출 F 챕터화·호출 G 단어 뜻·단어장 판독/정의 등). 여기서는 제품 수준의 흐름과 경계만 적는다.

### 14-1. 유튜브 낭독 자막 grounding + 챕터 리더

표지·소개글만으로 줄거리를 **예측**하던 카드가 조악했던 문제(환각)를 실제 본문에 붙여 해결한다.

- **낭독 영상 자동 검색**: 판독으로 제목·저자가 정해지면 그 값으로 낭독 영상을 검색(`lib/youtube-search.ts`, YouTube Data API v3)해 **상위 3개 후보**를 보여주고 사용자가 하나를 탭한다. 첫 결과를 자동 채택하지 않는 것은 **엉뚱한 책에 grounding되는 것을 막기 위함**(사람이 표지를 보고 고른다). 후보 메타는 영상시간 · 게시자 순으로 표시. 건너뛰기 가능(그러면 §3 기본 경로).
- **자막 fetch**: 고른 영상의 자막을 **Supadata**(`lib/youtube-transcript.ts`, 서버 전용)로 가져온다. 클라우드 IP 차단·Whisper 폴백을 호스팅 API가 처리한다 — **우리가 직접 유튜브를 스크래핑하지 않는다**(§13의 "크롤링·스크래핑 금지"와 무관, 유료 API 호출이다).
- **grounding**: 자막이 있으면 storySource 등급에서 transcript가 **최상위**가 되어 카드 줄거리·질문이 실제 본문에 붙는다("낭독 확인" 배지).
- **챕터 리더**(자막이 있으면 **항상** 생성): 목차가 있으면 챕터별로, 없으면 "전체" 한 블록으로, **영어 원문(문장 단위) + 한글 해석**을 보여준다. 코드가 각 챕터 문장이 자막의 부분 문자열인지 검사(`groundChapters`)해 프롬프트 밖 환각을 막는다. 카드 생성 직후 클라이언트가 `/api/chapterize`를 best-effort로 자동 호출(실패해도 카드는 남는다).
- **단어 더블탭**: 챕터 리더의 영어 단어를 두 번 탭하면 **그 문장 맥락의 한글 뜻**(호출 G)·발음(TTS)·"**모은 단어**" 단어장 담기. 모은 단어장은 get-or-create(멱등)로 하나만 두고 단어장 정복의 시험·오답노트에 편입된다.
- **라우트**: `/api/youtube-search`(후보 검색) · `/api/card`(youtubeUrl 선택 — 있으면 자막 fetch 후 grounding, 없으면 §3과 바이트 동일) · `/api/chapterize`(bookId → chapters) · `/api/word-meaning`(호출 G) · `/api/english/vocab/collected/add-word`(모은 단어). 데이터 모델은 `BookRecord`에 `transcript`·`youtubeUrl`·`chapters`(nullable) 추가.

### 14-2. 영어단어장 정복

교재(예: 능률 VOCA류, DAY 20개)를 앱으로 옮겨 **판독 → 시험 → 오답노트**까지 돌리는 별도 기능. 축은 "**판독 = 책 원문 전사 / AI 창작 = 영영 정의·이모지만**"이다 — 예문·뜻은 책 원문을 보존한다.

- **판독**(`/api/english/vocab/extract`, vision): DAY 사진 2~4장을 판독해 단어·발음기호·품사·뜻(번호 보존)·예문(영/한)·유의어를 **원문 그대로 전사**한다. 밀집·2단 조판 정확도가 성패라 few-shot으로 예문 누락을 막았다.
- **영영 정의 + 이모지**(호출 D, `/api/english/vocab/[id]/enrich`): 판독 직후 자동 생성. **정의는 시험이 매달리므로 한 번 생성되면 불변**(재생성은 `definitionEn === null`인 단어만 채운다). 이모지 없으면 첫 글자 배지.
- **뷰·TTS**: 표/카드 토글, 단어·예문 읽어주기(`lib/speech.ts`).
- **시험**(`/api/english/vocab/[id]/quiz`): **영영 정의 제시 → 영단어 5지선다**(정답1 + 같은 DAY 오답4, 셔플). 즉시 피드백·발음. 세션은 별도 컬렉션에 저장(전사본 불변).
- **오답노트**: DAY 안(`[id]/wrong`)과 DAY 넘어(`/english/vocab/wrong`) 두 층. **연속 2회 정답이면 졸업**(`lib/vocab-mastery.ts`).
- **라우트**: `/api/english/vocab/*`(extract·route·[id]·enrich·quiz·rename·add-word·collected) · 화면 `/english/vocab/*`(목록·상세·quiz·wrong·new). 순수 함수(병합·보기 생성·졸업·복습)는 `lib/vocab-*.ts`에 두고 오프라인 eval로 잠근다.
- **경로 규약**: 수학 접두사 규약을 따라 `/english/vocab/*` · `/api/english/vocab/*`.

## 15. 확장 기능 (2026-09 — §14 위에 더 얹은 것)

> 세 기능 모두 **AI 무관·클라이언트+스토어 중심**. AI 호출·프롬프트는 안 늘었다.

### 15-1. 목록 순서변경 (서재·단어장·수학 공통)

기록 목록의 **관리 모드**에 삭제만 있던 것에 **드래그 순서변경**을 더했다.

- **게이트 = 관리 모드 재사용**: 관리 모드에서만 각 줄에 **드래그 핸들(≡) + ↑/↓ 버튼**(+키보드)이 나타난다. 평소엔 스크롤·열기만 — 모바일 세로 스크롤↔드래그 충돌을 관리 모드 게이트로 피한다.
- **저장**: 각 레코드에 `sortIndex: number | null`(필수 nullable). 재배치하면 그 목록 전체를 0..n으로 재색인해 저장. 정렬은 `sortIndex` null 먼저(`createdAt` 역순=**새 항목이 맨 위**) → 나머지 오름차순. 생성부는 sortIndex를 안 매긴다(스토어가 매김) — 하위호환.
- **공유 프리미티브**: `components/use-reorder.ts`(포인터 드래그+자동스크롤+키보드+낙관적 되돌림) · `lib/reorder-contract.ts`(범용 `{orderedIds}`) 하나로 세 목록을 굴린다. 라우트 `/api/library/reorder` · `/api/english/vocab/reorder` · `/api/math/reorder`. 라이브러리 추가 없음.
- **수학 필터 게이트**: 수학 목록은 필터(전체/틀린 문제/보류)가 있어, **'전체'가 아닐 때는 재배치 비활성**(부분 목록만 재색인하면 인덱스가 충돌). 삭제는 어느 필터에서도 유지. 서재는 검색 중 비활성, 단어장은 필터가 없어 게이트가 관리 모드 하나뿐.

### 15-2. 읽어주기(TTS) 속도 조절

읽어주기 속도를 **천천히(0.7)·보통(0.9, 기본)·빠르게(1.1)** 3단 분절 버튼으로 고른다.

- 슬라이더가 아니라 버튼: 아이+폰 맥락이라 큰 탭 타깃이 낫고, 세로 스크롤 목록 안 가로 슬라이더는 스크롤과 충돌한다. 속도는 3~4단이면 충분.
- **전역 값 하나**(`lib/speech.ts` `getTtsRate`/`setTtsRate`, localStorage 영속) — 6개 읽어주기 화면(카드·챕터리더·단어장·시험·오답)이 공유한다(같은 단어가 화면마다 다른 목소리로 들리면 안 된다는 원칙). 컨트롤은 `components/tts-speed-control.tsx`, 챕터 리더·단어장 상단에 배선. 기본 0.9라 안 건드리면 기존과 동일.

### 15-3. 단어장 유의어·반의어 연결 + 관계 문제 시험

특정 단어의 **특정 뜻**에 유의어/반의어를 붙이고(AI 추천 후보에서 골라 단어장에 **새로 추가**하거나, 이미 있으면 연결), 그 관계를 시험 문제로 낸다(§14-2 단어장 정복 확장).

- **의미별 연결**: 모델이 이미 뜻을 `meanings[].related`로 담으므로(교재 판독분), 여기에 **사용자 연결**을 더한다. `VocabRelated`에 `source:"book"|"user"` + `linkedNo`·`linkedMeaningIndex`(필수 nullable) 추가. **AI 추출 JSON Schema·프롬프트는 무변경** — 판독분은 코드 정규화가 `source:"book"`으로 채운다(spec-sync 무영향).
- **양쪽 상호 기록**: `applyVocabLink`(공용 순수함수, 양 백엔드)가 두 뜻의 related에 대칭 기록·멱등. 추가·연결은 `/api/english/vocab/[id]/add-related`, 해제는 `/link` DELETE. 엔트리 식별은 배열 인덱스(교재 번호 `no`는 손입력 null·중복 가능이라 유일 식별 불가), 저장 매칭은 `word`+`meaningIndex`.
- **후보 추천 + 추가·연결** (호출 H, `docs/harness/english.md` §11): 각 뜻 옆 "＋ 유의어/반의어 추가" → 종류를 고르면 `suggestRelatedWords`가 **그 뜻에 맞는 실제 후보**(영단어+우리말뜻, 표제어·중복·굴절형 제외)를 5~6개 제시하고 **직접 입력**도 된다. 고르면 `/add-related`가 이미 있으면 연결만, 없으면 **단어장에 새로 추가(→호출 D 자동 보강, best-effort)→연결**한다 — 유의어·반의어가 단어장에 없어도 고를 수 있다(기존 "책 항목만 나열" 피커의 한계를 없앤 재작업). 사용자 연결분만 표식+해제(교재 판독 유의어는 표시만).
- **관계 문제 시험**: `buildRelationQuestions`로 **"X의 유의어는?/반대말은?"** 5지선다(정답=연결어, 오답=같은 DAY 단어, `buildChoices` 재사용). **내가 연결한 것만**(`source:"user"`) 출제. 관계 결과는 `VocabQuizRecord{mode:"relation"}` 별도 저장 → def→word 숙련도·오답노트·졸업에 **무오염**(오프라인 eval이 반례로 잠금).

## 16. 자연스러운 발음 — 클라우드 TTS (2026-09)

### 16-0. 왜 바꾸나

지금까지 발음은 브라우저 `speechSynthesis`(Web Speech API)였다. 공짜고 즉시 나지만 **기기가 고르는 기본 음성이 대개 압축(compact) 엔진**이라 딱딱하게 들린다 — 특히 속도를 낮추면("천천히") 더 로봇 같다. 아이가 따라 말하고 아빠가 발음을 익히는 앱에서 **부자연스러운 발음은 잘못 배우게 한다.**

그래서 **서버에서 OpenAI TTS로 합성**해 들려준다. 새 업체·새 비밀값이 없다(이미 쓰는 `OPENAI_API_KEY`).

**비용은 실질적으로 무시할 만하다** — 단어 하나가 10자 안팎이라 수천 번 눌러도 몇 백 원이다. 다만 **같은 문장을 반복 합성하지 않도록 캐시**한다.

### 16-1. 설계

- **라우트** `POST /api/tts` `{ text, lang, speed }` → 오디오(mp3) 바이트. 기존 PIN 게이트(`proxy.ts`)로 자동 보호된다.
- **서버** `lib/tts.ts` — OpenAI audio API 호출. `lib/ai/client.ts`(Structured Outputs 전용 관문)와 **섞지 않는다**: 스키마도 zod도 없는 다른 성격의 호출이다.
- **클라이언트** `lib/speech.ts`가 단일 관문을 유지한다. `speak(text, lang)`의 **시그니처를 바꾸지 않는다** — 안에서 클라우드 → 실패 시 기기 음성으로 간다. 그래야 6개 영어 화면과 일본어 화면이 **한 줄도 안 바뀐다**.
- **캐시**: `${lang}:${speed}:${text}` 키로 메모리 Map(세션 내). 같은 단어를 연타하거나 시험에서 다시 들을 때 재합성하지 않는다.
- **속도**: 기존 3단(천천히 0.7 · 보통 0.9 · 빠르게 1.1)을 OpenAI `speed` 파라미터로 넘긴다. 압축 음성과 달리 느려도 자연스러움이 덜 깨진다.
- **길이 상한**: 한 번에 합성할 텍스트에 상한을 둔다(사고성 대용량·비용 폭주 방지). 넘으면 기기 음성으로 폴백한다.

### 16-2. 폴백이 핵심이다

**앱이 조용해지면 안 된다.** 다음 경우 **기기 음성(`speechSynthesis`)으로 조용히 되돌아간다**:

- `OPENAI_API_KEY`가 없다(로컬 데모·키 미설정) → 지금까지와 똑같이 동작
- 네트워크·API 실패, 오디오 재생 실패
- 텍스트가 상한을 넘음

폴백은 **사용자에게 에러를 띄우지 않는다** — 발음이 조금 딱딱해질 뿐 학습은 이어진다.

### 16-3. 지연

첫 재생에 합성 시간(대략 1초 안팎)이 든다. 캐시가 이후를 덮는다. 재생 중 버튼에 로딩 상태를 표시하되, **연타해도 겹쳐 울리지 않게** 기존 규약(재생 전 취소)을 유지한다.

### 16-4. 적용 범위

`lib/speech.ts`를 쓰는 **모든 화면**이 자동으로 좋아진다 — 영어(카드 단어·챕터 리더 문장·단어장·시험·오답노트)와 일본어(단어·예문·한자·대화·시험 피드백) 전부. 화면 코드는 바꾸지 않는다.

### 16-5. 이후 보강 — 언어별 엔진 · 기기 음성 품질 · 영속 캐시 (2026-09-19~20, 코드 기준 추가 기록)

§16-1~16-4 이후 실사용 피드백으로 세 가지가 더해졌다. 동작의 진실 원천은 `lib/speech.ts`·`lib/tts-cache.ts`다.

- **엔진은 언어별로 고른다.** 청취 비교에서 영어는 클라우드가, 일본어는 기기 음성(Kyoko)이 피치 액센트가 살아 더 자연스러웠다 — 그래서 언어 베이스마다 `cloud`/`device`를 사용자가 고른다(`localStorage` `tts-engine-{en|ja|ko}`). 기본값 `DEFAULT_ENGINE = { en: "cloud", ja: "device", ko: "cloud" }`(ko는 §18-3). device로 바꾸면 그 언어는 클라우드 호출이 0이다(진행 중 프리페치도 끊는다). 설정 UI는 `components/tts-engine-control.tsx`(단어장·챕터 리더·일본어 단어장·해설 듣기 바).
- **기기 음성은 품질 순으로 고른다.** `utterance.lang`만 주면 브라우저가 대개 압축(compact) 음성을 잡는다 — 그 언어 음성을 품질 순으로 정렬해 가장 좋은 것을 쓰고(`rankVoicesForLang`), 사용자가 직접 고를 수도 있다(`tts-voice-{lang}`).
- **합성 오디오는 두 겹으로 캐시한다.** 1차 메모리 Map(세션, 200개), 2차 **IndexedDB 영속 캐시**(`lib/tts-cache.ts` — 앱을 닫았다 열어도 재합성·재요금 없음, LRU 1000개·50MB). 옛 목소리가 섞이지 않게 `GET /api/tts`의 `voice|model|i{지시 버전}`을 **지문**으로 삼아 바뀌면 통째로 비운다(§18-3의 버전 규칙). 지문 조회가 일시 실패하면 세션당 3회까지 다시 시도하고, 그동안은 메모리만 쓴다(§18-2).
- **프리페치**: 화면에 보이는 문장을 미리 합성해 첫 재생 지연(~1.3초)을 없앤다 — 한 번에 최대 90개, 동시성 2, device 언어는 하지 않는다(`prefetchSpeech`).
- **단발 재생도 탭 안에서 iOS 잠금을 푼다 · 설정 변경 시 프리페치 재실행 · 폰 진단 캡션 (2026-09-25).** iPhone Safari에서 일본어 엔진을 클라우드로 두면 🔊가 무음이던 신고의 원인은 두 고리였다 — `speak()`가 합성(~1초)을 기다린 뒤 `new Audio().play()`를 불러 iOS가 탭 밖 재생으로 막았고(NotAllowedError), 대체 기기 음성은 쉬고 있을 때도 `cancel()` 직후 `speak()`하는 데다 탭 밖이라 첫 발화 잠금도 풀리지 않았다. 그래서 `speak()`의 클라우드 경로는 **첫 await 전에 동기로** `speakQueue`와 같은 잠금 해제(재사용 요소 `queueAudio`에 무음 WAV `play()` + 볼륨 0 빈 발화)를 하고 합성 뒤 재생도 **그 재사용 요소로** 한다(§18-2의 "`speak()` 경로는 재생마다 `new Audio`" 서술은 이 날짜부터 이 규칙으로 대체된다 — 세대 토큰·`activeQueueEnd` 동기 종료·objectURL 회수·공개 시그니처는 그대로). 합성 대기에는 큐와 같은 상한(`fetchMs` 8초)을 둬 매달리면 기기 음성으로 가고, 요청은 끊지 않아 늦게 와도 캐시에 남는다. 기기 음성 폴백(`fallbackDevice`)의 cancel 규칙은 `speakDeviceAwait`와 같다 — 말하는 중·대기 중일 때만 `cancel()`하고, 잠금 해제용 빈 발화만 남았으면 끊지 않고 뒤에 잇는다. `prefetchSpeech`는 device 언어 요청도 "마지막 프리페치"로 기억해, 그 언어 엔진을 cloud로 바꾸거나(`setTtsEngine`) 속도를 바꾸면(`setTtsRate` — 캐시 키에 speed가 들어간다) **화면 코드 수정 없이** 새 설정으로 다시 돈다(같은 설정 재탭은 진행 중 요청을 끊지 않고, device로 바꾸면 기존대로 중단하며, 화면이 중단 함수를 부르면 잊는다). 서버 로그를 볼 수 없는 폰을 위해 마지막 클라우드 재생 결과(시각·언어·성공, 또는 실패 단계 캐시·합성·재생과 이유 `tts 501`·`tts 500`·`timeout`·`network`·`NotAllowedError` 등, 그리고 기기 음성 대체 여부)를 언어별 1건 메모리에 두고(`getTtsPlaybackDiag`·`TTS_DIAG_EVENT`, 단발과 큐 조각 공통), `TtsEngineControl`이 마운트 후 캡션 한 줄로 보인다(예: "마지막 재생: 클라우드 ✓ · 14:40", "마지막 재생: 클라우드 실패(재생 NotAllowedError) → 기기 음성 · 14:40"). 오프라인 잠금은 `eval:speech`의 "단발" 영역(F1~F6)과 뒤집은 ⑰이다.
- **기기 음성 멈춤 복구 · 속도 연타 비용 · 합성 요청 공유 (2026-09-25 후속).** "기기랑 클라우드가 꼬인 것 같다, 속도를 바꾸다 보면 다시 나온다"는 관찰에 따라, iOS WebKit이 `cancel()` 뒤 speechSynthesis를 paused로 굳혀 이후 발화를 조용히 무시하는 버그를 막으려고 기기 음성으로 말하기 직전(`fallbackDevice`·`speakDeviceAwait`·잠금 해제 빈 발화) paused면 `resume()`한다. 속도 변경의 프리페치 재실행은 옛 속도 배치를 누르는 순간 멈추고 마지막 조작 600ms 뒤 한 번만 돌며(엔진 cloud 전환은 즉시), 같은 문장을 🔊·프리페치·큐가 동시에 원하면 합성 요청 하나를 함께 기다린다 — 한 소비자의 중단은 자기만 물러나고 마지막 소비자가 떠날 때만 요청을 끊으며, `/api/tts`가 `req.signal`을 합성에 넘겨 끊긴 요청은 상류 OpenAI 합성도 멈춘다(499 `client_closed`). 오프라인 잠금은 `eval:speech` "단발" F7~F16이다.
- **영속 캐시는 오디오를 바이트로 저장하고, 조회 때 오디오 레코드를 다시 쓰지 않는다 · 캐시 오디오 자가 치유 (2026-09-27).** iPhone Safari에서 클라우드로 둔 🔊가 "마지막 재생: 클라우드 실패(재생 NotSupportedError) → 기기 음성"으로 떨어지던 신고의 원인은 영속 캐시의 LRU 갱신 한 줄이었다. `ttsCacheGet`이 IndexedDB에서 꺼낸 Blob을 atime을 고치려고 같은 키에 다시 넣었는데, WebKit은 **이전 프로세스(앱 재실행 전)가 쓴 Blob 레코드**를 이렇게 다시 쓰면 꺼낸 Blob을 읽을 수 없게 만들고(`WebKitBlobResource error 1`) 그 레코드도 그 프로세스 동안 죽인다. 그 Blob을 `<audio>`에 넣으면 error 4와 `play()` NotSupportedError가 났고, 죽은 Blob도 null이 아니어서 재합성이 영영 일어나지 않았다 — 그래서 한 번 캐시된 모든 클라우드 음성(영어·일본어·한국어, 단발·큐)이 앱을 다시 연 뒤부터 기기 음성으로만 났다. Chromium에서는 같은 절차가 정상이라 로컬 검증에 드러나지 않았다. 규칙은 이렇다. IndexedDB(`eunwoo-tts` v2)에는 Blob이 아니라 **바이트(ArrayBuffer)와 형식**을 저장하고, 꺼낼 때마다 `new Blob([bytes], { type })`로 새 메모리 Blob을 만들어 1차 캐시에 올린다. 목록(`audio` store: 키·크기·시각·형식)과 바이트(`bytes` store)를 나눠 LRU 시각은 목록만 고치므로 **조회 때 오디오가 든 레코드를 다시 쓰는 일이 없다**. v1의 Blob 레코드는 꺼내는 즉시 바이트로 읽어(상한 3초) 새 형식으로 옮겨 적고(디스크의 옛 오디오는 멀쩡하므로 재합성 비용이 없다 — 지시 버전을 올려 캐시를 비우지 않았다), 읽기가 실패하거나 매달리거나 오디오 형식이 아니면 미스로 보고 지운 뒤 그 한 건만 다시 합성한다. 합성 응답은 `res.ok`에 더해 content-type이 `audio/*`여야 받아들이고(200으로 온 HTML·캡티브 포털을 오디오로 재생하거나 캐시에 굳히지 않는다 — 진단 이유 `tts type`), 받은 바이트로 형식이 붙은 Blob을 직접 만든다. 그래도 캐시(메모리·IndexedDB)에서 온 오디오가 재생 단계에서 미디어 소스 오류(NotSupportedError, 또는 사용자 중단이 아닌 `error` 이벤트)로 실패하면 그 키를 두 캐시에서 빼고 **네트워크로 한 번만** 새로 받아 같은 재사용 요소로 다시 재생하며, 그 재시도도 실패하면 기기 음성으로 간다(두 번 치유하지 않는다 — 방금 네트워크로 받은 오디오가 실패하면 곧바로 기기 음성이고 캐시에 남기지 않는다). iOS 재생 차단(NotAllowedError)·대기 상한은 오디오 문제가 아니라 치유하지 않는다. `speak`·`speakQueue`·`prefetchSpeech`가 모두 같은 `getAudioBlob`를 지나므로 화면 코드는 바뀌지 않았고, 진단에는 `healed`가 더해져 캡션이 "마지막 재생: 클라우드 ✓(캐시 오디오 손상 → 새로 받음)" 또는 "클라우드 실패(캐시 오디오 손상 → 새로 받음 → 재생 NotSupportedError) → 기기 음성"으로 그 단계를 보인다. 오프라인 잠금은 `eval:speech` "영속캐시" G1~G17이다 — 가짜 IndexedDB의 WebKit 모사 모드가 "꺼낸 옛 Blob이 있는 키를 다시 쓰면 그 Blob과 레코드가 죽는" 동작을 흉내 내고, G4가 옛 알고리즘이 이 모사에서 실제로 죽는지 먼저 확인한다.

## 17. 학습 스트릭 — 연속 학습일 (2026-09)

### 17-0. 무엇을 위한 것인가

은우에게 **매일 하는 습관**을 만들어 주려는 장치다(듀오링고 스트릭과 같은 계열). **은우와 아빠를 나란히 놓고** 서로 자극이 되게 한다 — 아빠가 이어 가면 은우도 이어 가고 싶어진다.

### 17-1. 무엇을 "학습 완료"로 세는가 — **시험만 센다**

사용자 확정: **시험을 본 날만 인정한다.**

| 사람 | 인정되는 활동 | 레코드 |
|---|---|---|
| **은우** | 영어 단어장 시험 · 자유대화(은우 발화 1줄 이상 — 2026-09-26 추가, 은우 트랙 한정 예외 §17-9) | `VocabQuizRecord` · `TalkSessionRecord` |
| **아빠 · 일본어** | 일본어 단어 시험 · 한자 시험 | `JaQuizRecord` · `JaKanjiQuizRecord` |
| **아빠 · 운동** (2026-09-24 추가 — §17-7) | 러시안 파이터 루틴을 **지킨 날** | `WorkoutCycleRecord`(§19-4) |
| **아빠 · 영어** (2026-09-26 추가 — §17-8) | 토익스피킹 표현 시험(답한 문항 1개 이상) · 모의고사 응시(녹음된 문항 1개 이상) | `ToeicQuizRecord` · `ToeicAttemptRecord` |

**세지 않는 것**(의도적으로 제외):

- **수학** — 시험 기능이 없다. 문제 설명 생성은 "공부"보다 "준비"에 가깝다고 보고 뺀다. **수학만 한 날은 스트릭이 끊긴다**(사용자 확정).
- **"오늘 읽었어요" 체크**(`ReadingRecord`) — 누르기만 하면 되니 기준이 느슨해진다.
- **대화 복습**(`JaDialogRecord`) — 읽기에 가깝다.
- **생성 행위 전부** — 카드·단어장·한자 정보 만들기는 학습이 아니라 준비다.

**한 문항이라도 답해야 센다.** 시험을 열자마자 "그만하기"를 누른 세션(답한 문항 0)은 **세지 않는다** — 안 그러면 스트릭이 "시험 화면을 열었다"로 전락한다.

### 17-2. 날짜는 **KST 고정**이다

스트릭의 "하루"는 **한국 시간 자정~자정**이다. 기기 시간대에 기대지 않는다(해외·시간대 오설정에서 갈린다).

- 저장된 시각은 전부 ISO UTC다. 거기서 **KST 일자(`YYYY-MM-DD`)를 파생**한다.
- 계산은 이 저장소가 이미 검증한 방식 — **`+9시간 후 `getUTC*``**. `toLocaleString`·`Intl`·시간대 DB를 쓰지 않는다. 그래야 **서버(Cloud Run UTC)·SSR·클라이언트가 항상 같은 값**을 낸다(hydration 안전).
- **단일 정의처 `lib/kst.ts`** 를 신설한다. 지금 같은 로직이 세 곳에 복붙돼 있다(`card-view`의 `localDateString`, 시험 기록 화면 둘의 `formatKst`) — 그것들을 이 모듈로 모은다. 날짜 규칙이 갈리면 스트릭이 조용히 틀어진다.
  - 목록·상세·카드 이력의 "만든 날짜"(`createdAt`) 표시도 이 모듈의 `formatKstDate(iso)`(`YYYY.MM.DD`)로만 만든다 — 예전의 `iso.slice(0, 10)`은 UTC 일자라 KST 00:00~08:59에 만든 기록이 전날로 보였다. 읽음 기록의 `readAt`은 기기 로컬 날짜(`deviceDateString`)라 예외다.
- **"오늘"이 필요한 순간만** 현재 시각을 읽는다. 과거 기록을 접는 계산은 결정적이라 어디서 돌려도 같다.

### 17-3. 스트릭 계산 (순수 함수)

`lib/streak.ts` — AI·저장 없음. 세션 목록을 받아 사람별로 접는다.

```ts
interface StreakInfo {
  current: number;        // 연속 일수
  doneToday: boolean;     // 오늘(KST) 이미 했는가
  lastDate: string | null;// 마지막으로 한 KST 일자
  best: number;           // 최고 기록
}
```

**연속 판정 규칙**(듀오링고 방식):

- 오늘 했으면 → 오늘부터 거슬러 올라가며 **하루도 안 빠진 날 수**.
- 오늘 아직 안 했는데 **어제** 했으면 → **어제까지의 연속일수를 그대로 보여 준다**(아직 살아 있다. 오늘 하면 +1, 자정을 넘기면 끊긴다).
- 어제도 안 했으면 → **0**.

같은 날 여러 번 시험을 봐도 **하루는 하루다**(일자 집합으로 접는다).

### 17-4. 헤드라인 — 모든 화면 상단 고정

- 루트 `app/layout.tsx`의 body 최상단에 `sticky top-0`로 둔다. **카드 모드 전면 오버레이(z:20)가 이것을 덮는다** — 몰입 화면에서 자동으로 가려지는 게 의도다. 헤드라인은 그보다 낮은 층(z 10~19)에 둔다.
- **`/unlock`에서는 숨긴다**(잠금 화면에 학습 현황이 보일 이유가 없다).
- **영어 모바일 상단바가 `sticky top-0`이라 겹친다** — 오프셋을 조정해 둘이 포개지지 않게 한다.
- 표시 내용:
  - **은우 🔥N일** · **아빠 🔥N일** 을 **나란히**(대조가 이 기능의 목적이다).
  - 오늘 한 사람은 채워진 상태, 아직 안 한 사람은 흐리게 + "오늘 아직" — 무엇을 해야 하는지 한눈에.
  - 오늘 한 **과목·주제**를 작게(예: `영어 단어장 · DAY 08`).
- **데이터는 클라이언트가 `/api/streak`로 가져온다**(서버 컴포넌트가 매 페이지 렌더마다 전체 세션을 스캔하지 않게). 초기 렌더는 **중립 상태**로 그리고 마운트 후 채운다(hydration 안전 — §17-2와 같은 이유).
- 시험을 끝낸 직후 헤드라인이 **바로 갱신**돼야 한다(성취감이 여기서 나온다). 시험 저장 성공 시 갱신 신호를 보낸다.
- 인쇄에서는 제외한다(`print-hide`).

### 17-5. 저장·조회

**새 레코드를 만들지 않는다.** 이미 저장된 시험 세션에서 파생한다 — 그래야 **과거 기록도 즉시 스트릭에 반영**된다(오늘부터 새로 쌓지 않아도 된다).

- 날짜 필터 메서드는 두지 않는다(Firestore 복합 인덱스 회피 규약). 전체를 읽어 메모리에서 접는다 — 가족용 규모(세션 수백 건)라 충분하다.
- **일본어 시험은 전역 목록이 없다**(`listJaQuizzes(bookId)`뿐) → `listAllJaQuizzes`를 추가한다. 한자 시험도 마찬가지로 확인한다.
- 스트릭 값을 **저장하지 않는다**(읽을 때 계산). 저장하면 두 진실이 갈린다 — 영어 오답노트 집계와 같은 규약.

### 17-6. eval

순수 함수라 전부 오프라인으로 잠근다: KST 일자 환산(자정 경계·UTC 날짜와 다른 날), 연속 판정(오늘 함/어제까지 함/끊김), 같은 날 중복 세션 접기, **답한 문항 0인 세션 제외**, 최고 기록, 사람별 분리(은우 세션이 아빠 스트릭에 안 섞이는지 — 모드 무오염과 같은 함정).


### 17-7. 아빠의 운동 트랙 (2026-09-24)

사용자 요청: **"운동도 상단 스트릭에 구분해서 — 일본어, 운동."** 아빠 칸을 **🗾 일본어**와 **💪 운동** 두 트랙으로 나눠 **각자의 연속 일수**를 보인다. 두 트랙을 한 스트릭으로 합치지 않는다(합치면 운동만 한 날에 일본어 스트릭이 이어져 보인다 — 사람별 분리와 같은 함정).

**무엇을 "지킨 날"로 세는가** — 운동 루틴에는 **계획된 휴식**이 있어 "운동한 날"만 세면 6일마다 끊긴다. 그래서 **루틴을 지킨 날**을 센다:

| 센다 | 이유 |
|---|---|
| 운동 사건이 있는 날(`complete`·`fail` 모두) | 실패도 루틴의 일부다 — 정자세 한계까지 한 날 |
| 엔진이 정한 **휴식·회복 휴식·마무리 휴식** 슬롯 날(오늘까지만) | 쉬라고 한 날에 쉰 것이 루틴을 지킨 것이다 |
| **재측정을 끝낸 날** — 사건이 있는 사이클이 닫힌 `endedAt` KST 일자(Day 27 completed든, 재측정 안내를 따른 도중 재측정 abandoned든) | 재측정도 루틴의 한 날이다. 앱의 재측정 안내를 따른 날이 "건너뛴 날"로 스트릭을 끊으면 안 된다 |

| 세지 않는다 | |
|---|---|
| 운동일에 기록 없이 지난 날 | 건너뛰었다 — **끊긴다** |
| 재측정일에 RM을 안 넣고 지난 날 | 할 일을 안 했다 |
| 시작 전(`not_started`) 날, 사이클이 없던 날, 사건 0개로 닫힌 사이클(레거시 정리)의 닫힌 날 | 루틴 밖 |
| 오늘보다 뒤의 휴식 슬롯 | 아직 오지 않았다 |

- 휴식 슬롯은 **사건 재생 규칙(§19-2)이 정한 것 그대로** 쓴다 — 화면·스트릭이 휴식 규칙을 따로 구현하지 않는다(엔진 `workoutKeptDays(cycles, todayKst)`, `lib/workout.ts`). 슬롯은 다음 사건 날짜 전날, 그 사이클이 닫힌 날, 오늘 중 가장 이른 날에서 자른다(**그날 포함**). 오늘 뒤 날짜의 사건(시계 어긋남)은 세지 않는다. 모든 사이클(중단 포함)의 날을 합집합으로 접는다. 한 날에 이유가 겹치면 라벨은 사건 > 재측정 끝냄 > 휴식 슬롯 순(가장 구체적인 것).
- **오늘이 휴식 슬롯이면 `doneToday = true`** — "오늘 아직"으로 흐리게 두지 않는다(쉬는 것이 오늘 할 일이다).
- 연속 판정·최고 기록·"어제까지 살아 있음" 규칙은 §17-3과 **같은 함수**를 쓴다 — 날짜 집합을 받는 코어(`computeStreakFromDays(days, todayKst)`)를 `lib/streak.ts`에서 떼어 내고, 기존 `computeStreak`(세션 → 날짜 집합)은 그 위에 얹는다(동작 불변 — 기존 eval 그대로 통과).
- `/api/streak` 응답에 `appaWorkout: PersonStreak`을 더한다. 기존 `appa`는 **일본어 트랙 그대로**(호환). 운동 `todayLabel`(짧게): 기록함 → `Day 7 ✓` / 재부여 성공 `Day 5 목표 ✓` / 실패 `Day 7 ✗`, 휴식 → `휴식`, 회복 → `회복 휴식`, 마무리 → `마무리 휴식 2/3`, 재측정 끝낸 날 → `재측정 ✓`. 오늘 안 했으면 null. 일본어 `todayLabel`은 "일본어" 라벨이 앞에 붙으므로 `단어장 · {제목}` / `한자 시험`으로 줄인다.
- **헤드라인**: `🧒 은우 🔥N일 …` | `🧑 아빠` 아래 두 트랙 `🗾 일본어 🔥N일 …` · `💪 운동 🔥N일 …` — 트랙마다 따로 흐리게/"오늘 아직"/짧은 라벨. 한 줄·고정 높이(`--streak-h`). 긴 라벨은 말줄임.
- **폰(<640px) 표시 규칙**(e2e 실측: 전부 펼치면 530~700px라 390px 폰에서 💪 운동 트랙이 첫 화면 밖으로 밀렸다): 폰에서는 **`이모지 (사람 이름) 🔥N일`만** 보인다 — `🧒 은우 🔥N일 | 🧑 아빠 🗾 🔥N일 💪 🔥N일`. 트랙 이름·"오늘 아직"·오늘 라벨은 sm 이상에서만 보이고 폰에서는 스크린리더 문구로 남긴다(`max-sm:sr-only`). 아직인 쪽은 **흐림**이 신호다. 은우 칸도 같은 규칙. 사람 이름은 폰에서도 남긴다(🧒·🧑 이모지는 폰에서 거의 같아 보인다). 트랙은 🗾·💪 이모지로 가른다. 가로 스크롤은 남기되 스크롤바는 숨긴다(40px 안에 스크롤바가 생겨 글자가 잘리지 않게).
- 운동 기록·취소·사이클 시작이 성공하거나 **409**(서버 상태가 이미 바뀜 — 다른 탭에서 이미 기록한 경우 등)면 `STREAK_REFRESH_EVENT`를 쏜다(시험 저장과 같은 즉시 갱신 — 성취감). 헤드라인은 겹친 재조회 중 **마지막 요청의 응답만** 반영한다.
- eval: `eval:streak`에 코어 분리 회귀(기존 15항목 그대로) + `computeStreakFromDays` 직접 케이스, `eval:workout`에 `workoutKeptDays` — 운동·실패일 포함, 휴식·회복·마무리 휴식 포함, 운동일 건너뜀 → 끊김, 재측정 대기일 제외·재측정 끝낸 날 포함(도중 재측정 abandoned 포함, 사건 0개 사이클 제외), 미래 휴식 제외, 시작 전 제외, 중단 사이클 사건 포함, 두 사이클 합집합, 오늘 휴식이면 doneToday.

### 17-8. 아빠의 영어 트랙 (2026-09-26)

아빠 칸에 세 번째 트랙 **🎙️ 영어**(토익스피킹 — §20)를 더한다. 순서는 `🗾 일본어 · 🎙️ 영어 · 💪 운동`. 일본어·운동과 한 스트릭으로 합치지 않는 이유는 §17-7과 같다(한쪽만 한 날에 다른 트랙이 이어져 보인다). 은우의 영어 단어장 시험(`vocabQuizzes`)과는 **컬렉션부터 다르다** — 이름은 둘 다 "영어"지만 은우 트랙에 한 날도 섞이지 않는다.

**무엇을 세는가** — §17-1의 "시험만 센다"를 그대로 옮긴다. 이 과목의 시험은 둘이다.

| 센다 | 레코드 | 조건 |
|---|---|---|
| 표현 시험(5지선다 3모드·말하기 자기 채점, §20-2) | `ToeicQuizRecord`(`toeicQuizzes`) | 답한 문항(`answered === true`)이 1개 이상 — 열자마자 그만둔 세션을 빼는 §17-1 규칙 그대로 |
| 모의고사 응시(실전·유형 연습, §20-4) | `ToeicAttemptRecord`(`toeicAttempts`) | **끝까지 녹음된 문항(`recorded`)이 1개 이상** — "녹음 없이 연습"이나 녹음이 하나도 끝나지 않은 응시는 세지 않는다 |

- 응시는 순수 함수 `toeicStreakSessions`(`lib/toeic-streak.ts`)가 "녹음된 문항 = 답한 문항"으로 옮겨 **같은 연속 판정 코어**(`computeStreak`, §17-3)에 넣는다 — 영어 트랙만의 규칙을 새로 쓰지 않는다. 날짜는 세션·응시의 `startedAt` KST 일자다.
- **세지 않는 것**: 사진 판독·파일 가져오기·발화 포인트·모의고사·사진 만들기(준비다), 전체 듣기·학습 보기(읽기·듣기에 가깝다), AI 채점(응시한 날을 이미 셌다 — 다음 날 채점을 눌러도 그날은 늘지 않는다).
- `/api/streak` 응답에 `appaEnglish: PersonStreak`을 더한다(`appa`는 여전히 일본어, `appaWorkout`은 운동 — 호환). `todayLabel`은 오늘 한 것 중 **가장 늦게 시작한 것**: 표현 시험이면 `표현집 · {세트 제목}`, 응시면 `모의고사 · {모의고사 제목}`(같은 시각이면 표현집). 헤드라인이 "영어"를 앞에 붙인다. 토익 두 컬렉션을 못 읽거나 계산이 실패하면 **이 트랙만** 중립값(current 0)으로 보낸다 — 새 컬렉션의 권한·색인 문제가 은우·일본어·운동 트랙을 죽이지 않게(운동 트랙과 같은 규약).
- 즉시 갱신: 표현 시험은 새로 저장된 모드가 하나라도 있으면, 응시는 끝/그만두기 저장에서 녹음된 문항이 1개 이상이면 `STREAK_REFRESH_EVENT`를 쏜다.

**폰(<640px) 표시 — §17-7 규칙의 갱신.** 트랙이 셋이 되자 §17-7의 폰 표기로도 360px에서 넘쳤다(두 자리 연속일 실측 419/360px — 59px 넘쳐 💪의 🔥가 첫 화면 밖). 그래서 두 가지를 더 덜어 낸다. 정의처는 `components/streak-headline.tsx` 머리 주석이다.

- 폰에서는 🔥 뒤 **"일" 글자를 뺀다** — `🧒 은우 🔥12 | 🧑 아빠 🗾 🔥34 🎙️ 🔥5 💪 🔥27`. §17-7의 폰 표기 `🔥N일`은 이 날짜부터 `🔥N`으로 대체된다. 스크린리더에는 `role="img"`의 `aria-label`("영어 12일 연속")이 그대로 가고, sm 이상에서는 "일"까지 전부 보인다. 칸 간격도 폰에서 한 단계 좁힌다(헤드라인 `gap-2`·`px-2`, 아빠 묶음 `gap-2` — sm 이상은 예전 `gap-3`·`px-3`·`gap-2.5`).
- **세 자리 이상이면 한 단계 더 압축한다.** 네 칸(은우·일본어·영어·운동) 중 하나라도 연속일이 **100일 이상**이면(`COMPACT_FROM_DAYS`) 폰에서 사람 이모지 🧒·🧑(장식, `aria-hidden`)를 숨기고 칸 간격을 `gap-1.5`로 줄인다. **사람 이름(은우·아빠)과 트랙 이모지(🗾·🎙️·💪)는 남긴다** — 누구의 🔥인지는 이름이, 어느 트랙인지는 이모지가 말한다(QA가 낸 "아빠 이름 sr-only" 안은 쓰지 않았다). 두 자리까지는 압축하지 않는다(필요할 때만).
- 실측(2026-09-26, `/api/streak` 응답 주입, 헤드라인 안 넘침): 두 자리는 360·390px 모두 0, 세 자리(123·234·345·456 / 999×4) 360px에서 22·24px → 0, 네 자리 53px → 0(390px 23 → 0). 문서 가로 넘침은 전 경우 0이고, 그래도 넘치면 헤드라인 안 가로 스크롤(스크롤바 숨김)은 §17-7 그대로다.
- eval: `eval:streak` "영어 트랙" 6항목 — ① 오늘 표현 시험 + 어제 응시(녹음 1) → 2일·오늘 함 ② 녹음 0 응시 제외(`isCountedToeicAttempt` 판정 일치) ③ 답한 문항 0 표현 시험 제외 ④ 트랙 분리 반례(은우·일본어·운동 날짜를 섞으면 3연속으로 오염돼 보인다) ⑤ 영어만 한 날 일본어는 여전히 "오늘 아직" ⑥ `/api/streak` 배선 정적 점검(영어 = 토익 두 컬렉션만, 은우·일본어 계산식 불변). `eval:toeic`의 "스트릭 트랙" 절도 같은 분리 반례를 건다.

### 17-9. 은우 트랙에 자유대화 포함 (2026-09-26)

사용자 확정(2026-09-26): 자유대화(§21)도 은우가 **학습한 날**로 센다. §17-1 "시험만 센다"의 **은우 트랙 한정 예외**다 — 1학년에게는 영어로 직접 말해 본 날이 시험 본 날만큼 의미가 있다는 판단이다. 일본어 대화 복습을 뺀 §17-1 근거("읽기에 가깝다")와는 경우가 다르다: 자유대화에서는 아이가 **직접 말한다**.

| 센다 | 레코드 | 조건 |
|---|---|---|
| 영어 단어장 시험(§17-1 그대로) | `VocabQuizRecord`(`vocabQuizzes`) | 답한 문항 1개 이상 |
| 자유대화 | `TalkSessionRecord`(`talkSessions`) | **은우 발화 줄이 1개 이상**(`childTurnCount ≥ 1` — 빈 전사 제외). 연결만 하고 한마디도 안 한 대화는 세지 않는다(저장도 하지 않는다, §21-2) |

- 대화는 순수 함수(`lib/talk-streak.ts` `talkStreakSessions`)가 "은우 발화 = 답한 문항"으로 옮겨 **같은 연속 판정 코어**(`computeStreak`, §17-3)에 넣는다 — 코어는 "답한 문항 ≥ 1"만 보므로 발화 수만큼 복제하지 않고, 발화가 1줄 이상이면 답한 문항 하나로 옮긴다(`isCountedTalkSession` — `childTurnCount`가 숫자가 아니거나 1 미만이면 세지 않는다). 날짜는 대화 `startedAt`의 KST 일자다. `/api/streak`은 `listAllTalkSessions()`로 전체를 읽어 메모리에서 센다(날짜 필터 쿼리를 두지 않는 규약).
- `todayLabel`은 오늘 한 것 중 **가장 늦게 시작한 것**(같은 시각이면 단어장 시험): 시험이면 `영어 단어장 · {DAY}`(기존), 대화면 `자유대화 · {주제}`(`talkStreakLabel`). 발화 0 대화는 더 늦어도 라벨이 되지 않는다.
- 대화 컬렉션을 못 읽으면 은우 트랙은 **단어장 시험만으로** 계산한다 — 새 컬렉션의 읽기 실패가 은우 트랙 전체를 죽이지 않게(운동·영어 트랙의 중립값 규약과 같은 방향). 응답은 그대로 200이다.
- 대화 저장에 성공하면(은우 발화 ≥ 1) 대화 화면이 `STREAK_REFRESH_EVENT`를 쏜다 — 같은 대화를 여러 번 저장해도(멱등 재전송, §21-2 5) 첫 성공에만.
- eval: `eval:streak` "자유대화" 6항목 — ① 발화 0 대화 제외(`isCountedTalkSession` 판정 일치 — 0·NaN·음수) ② 대화만 한 날 은우 스트릭 증가·오늘 함 ③ `startedAt`의 KST 일자로 센다(UTC 전날 15:30 → 오늘) ④ 아빠 트랙 무오염(대화 날짜를 섞으면 오염돼 보이는 반례) ⑤ 라벨 `자유대화 · {주제}` ⑥ `/api/streak` 배선 정적 점검(은우 = 단어장 시험 + `talkStreakSessions`, 읽기 실패 → 단어장만, 아빠 트랙 무혼합, 라벨 = 가장 늦은 것). 영어 트랙 ⑥(§17-8)도 은우 계산식이 바뀐 것에 맞춰 갱신했다. 합계 53항목.

## 18. 대화 해설 낭독 — 한국어 해설까지 이어 읽기 (2026-09)

### 18-0. 무엇을 위한 것인가

아빠의 일본어 **대화 복습 해설**(호출 C 결과 — 총평·잘한 점·고칠 점·어휘·다음 연습, `components/ja-dialog-coaching-view.tsx`)은 지금 **어휘 단어에만 🔊가 있다.** 해설의 본체인 한국어 설명과 일본어 인용·고친 문장·연습 문장은 소리로 들을 수 없다.

요청(2026-09-24): **"가이드 해설에도 음성 낭독 기능"**. 그래서 두 가지를 붙인다.

1. **일본어 문장마다 🔊** — 잘한 점 인용(`quoteJa`)·고칠 점의 원문(`originalJa`)과 고친 문장(`betterJa`)·다음 연습(`practice[].ja`). 단어 🔊와 같은 단발 재생(`speak(ja, "ja-JP")`).
2. **"🎧 해설 듣기" — 해설 전체를 순서대로 이어 읽기.** 한국어 설명은 한국어로, 일본어 문장은 일본어로.

적용 화면은 해설 뷰를 쓰는 **두 곳 모두**다 — 대화 상세(`/japanese/dialog/[id]`)와 새 대화 검토 화면(`/japanese/dialog/new`). 뷰 컴포넌트 하나에 넣으면 둘 다 따라온다.

**기대치(명시)**: 이어 읽기는 **화면을 켠 상태**를 기준으로 한다. iOS Safari는 화면이 잠기거나 앱이 백그라운드로 가면 `speechSynthesis`와 JS 타이머를 멈춘다 — 잠금 화면 연속 재생은 보장하지 않는다(기본 조합에서 일본어가 기기 음성이기 때문). 오디오 요소만 쓰는 "일본어도 클라우드" 설정에서만 이어질 가능성이 있고, 소리 설정에 그 안내를 한 줄 둔다. 오프라인으로 세션을 시작하면 영속 캐시 지문을 못 받아 IDB 캐시를 쓰지 못한다(§16 기존 규약) — 오프라인 재청취는 보장하지 않는다.

### 18-1. 낭독 대본 — 순수 함수로 만든다 (`lib/ja-coaching-script.ts`)

해설 → **대본**(재생할 조각 배열)을 만드는 일은 화면이 아니라 **순수 함수**가 한다. 런타임 import는 `./tts-shared`의 상수뿐, 타입은 `import type`(클라이언트 번들 안전 — `lib/tts.ts`(openai)를 절대 import하지 않는다). 오프라인 eval로 잠근다.

```ts
interface ScriptPiece {
  text: string;               // 읽을 텍스트(trim됨, 비어 있지 않음, length ≤ TTS_TEXT_MAX_CHARS)
  lang: "ko-KR" | "ja-JP";
  section: "summary" | "goods" | "fixes" | "items" | "practice";
  item: number | null;        // 하이라이트 대상 카드 번호. 섹션 제목 조각은 null, 총평 본문은 0
}
export function buildCoachingScript(c: JaDialogCoaching): ScriptPiece[];
export function splitForTts(text: string, max: number): string[];
export function normalizeKoForTts(text: string): string;
export function coachingJaTexts(c: JaDialogCoaching): string[]; // 프리페치용 일본어 문장 목록
```

순서(빈 섹션 — 배열이 비었거나 본문 조각이 하나도 안 남는 섹션 — 은 제목까지 통째로 건너뛴다. 각 필드는 `(s ?? "").trim()`, 비면 조각을 만들지 않는다):

| 섹션 | 조각 |
|---|---|
| 총평 | ko `총평.` → ko `summaryKo`(item 0) |
| 잘한 점 | ko `잘한 점.` → 항목 i마다: ja `quoteJa` → ko `whyKo` |
| 고칠 점 | ko `고칠 점.` → 항목 i마다: ja `originalJa` → (betterJa가 있으면) ko `고치면,` → ja `betterJa` → ko `whyKo` → (있으면) ko `문법: {grammarKo}` |
| 어휘 | ko `어휘.` → 항목 i마다: ja `word` → ko `meaningKo` → (있으면) ko `usageKo` |
| 다음 연습 | ko `다음 연습.` → 항목 i마다: ja `ja` → (있으면) ko `ko` |

**한국어 정리(`normalizeKoForTts`)** — 한국어 조각에만, **쪼개기 전에** 적용한다: `→`·`⇒`는 `, `로, `〜`·`～`는 제거, 이모지(Extended_Pictographic)는 제거하고 떨어져 남은 결합 문자(U+FE0F 변형 선택자·U+200D ZWJ·U+20E3 키캡 — `1️⃣`는 숫자만 남는다)도 지운다, 지운 자리에 남은 문장부호 앞 공백은 붙인다(`요 😊.` → `요.`), 연속 공백은 하나로. 일본어 조각은 **정리하지 않는다**(🔊·프리페치의 캐시 키와 글자까지 같아야 캐시가 맞는다).

**쪼개기(`splitForTts`) — 규칙 확정**:

- 길이는 `String.length`(UTF-16)로 잰다 — 서버 zod(`app/api/tts/route.ts`)와 같은 단위.
- `text.trim().length ≤ max`면 `[text.trim()]` 한 조각(일본어 조각은 거의 전부 여기).
- 문장 끝: `[.?!]` 뒤에 공백이나 문자열 끝이 올 때(`3.5배`·`N5.x`는 안 자른다), `[。？！]`는 공백이 없어도 끝. 문장 끝 부호 **바로 뒤의 닫는 기호** `」』）)"'’”】`는 앞 조각에 붙인다(`「そうです。」라고` → `」`가 뒤 조각 머리로 가지 않게).
- **번호 목록 머리**(줄 머리나 공백 뒤 `\d{1,2}.` + 공백 — `1. 첫째`)는 문장 끝이 아니다(번호가 앞 조각 꼬리에 붙지 않게). 강제 자르기도 그 바로 뒤에서 자르지 않는다.
- 문장 단위로 자른 뒤 **max 이하가 되도록 앞에서부터 탐욕적으로 묶는다.**
- 한 문장이 max를 넘으면 max 이내 마지막 `, 、 ，` 또는 공백에서, 그것도 없으면 max에서 자르되 **서로게이트 쌍을 쪼개지 않는다**(max < 2에서 둘이 부딪치면 쌍 보존이 길이 상한보다 우선 — 이론상 경계).
- 불변식(eval로 잠금): 모든 조각이 trim됨·비어 있지 않음·`length ≤ max`, 그리고 `pieces.join("").replace(/\s+/g,"") === text.replace(/\s+/g,"")`(글자 유실·추가 없음). 조각 내부 공백은 건드리지 않는다. 빈·공백 입력 → `[]`. `max < 1`은 방어(1로 취급).
- 쪼갠 조각은 같은 `section`·`item`을 갖는다.

### 18-2. 연속 재생 엔진 — `lib/speech.ts`에 `speakQueue` 추가

`speak(text, lang)`·`speakSequence`·`stopSpeaking`·`prefetchSpeech`의 **시그니처와 동작은 그대로**(§16-1). 기존 `speak()` 경로는 지금처럼 재생마다 `new Audio`를 쓴다. 새 공개 API:

```ts
export function speakQueue(
  items: { text: string; lang: string }[],
  handlers?: { onItem?: (index: number) => void; onEnd?: (reason: "done" | "stopped", info: { sounded: number }) => void },
): () => void;                       // 반환 = 멈추기 함수
export function unlockSpeechPlayback(): void; // 탭 핸들러 안에서 동기로 — iOS 재생 잠금 해제(§19 운동 안내도 쓴다)
```

**정지·종료 계약(가장 중요)**

- 시작 시 `cancelPlayback()`으로 이전 재생(단발·큐)을 끊고 새 세대 토큰을 받는다.
- 모듈 변수 `activeQueueEnd`를 두고, **`cancelPlayback()`이 토큰을 올린 직후 동기적으로** 활성 큐를 끝낸다(`onEnd("stopped")`). 그래서 다른 🔊(`speak`)·`stopSpeaking()`·새 `speakQueue()`가 오면 옛 큐의 `onEnd("stopped")`는 **그 호출이 반환되기 전에**, 새 큐의 `onItem(0)`보다 **먼저** 온다. 재생 중이던 조각도 즉시 끊긴다.
- `onEnd`는 **정확히 한 번**(ended 플래그). 끝까지 읽으면 `"done"`. 핸들러 호출은 try/catch로 감싼다. **핸들러 안에서 `speak`/`speakQueue`를 부르지 않는다**(재진입 금지 — 계약).
- (2026-09-26 추가 — 토익 응시 §20-9) `onEnd`의 둘째 인자 `info.sounded`(`SpeakQueueEndInfo`)는 끝까지 소리를 냈다고 본 조각 수다. 하위 호환이라 인자 하나짜리 기존 핸들러(해설 낭독·운동 안내)는 그대로 돈다. 아래 "연속 3조각" 규칙은 그대로라 **1~2조각 큐는 전부 무음이어도 `"done"`·`sounded 0`**으로 끝난다 — 소리가 꼭 나야 하는 화면(토익 질문 음성)이 이 값으로 다시 판정한다.
- 반환된 멈추기 함수: 이미 끝났으면 no-op. 아직 이 큐의 세대면 `cancelPlayback()`, 이미 다른 재생에 밀렸으면 자기만 정리(`onEnd("stopped")`는 이미 불렸으므로 no-op) — **끝났거나 밀려난 큐의 stop이 그 뒤 시작된 다른 재생을 죽이면 안 된다.**
- 빈 items(모두 공백): cancel 없이 `onEnd("done")`을 microtask로 한 번 부르고 no-op 함수를 돌려준다.
- 큐는 조각을 쪼개지 않는다(인덱스 보존). 300자를 넘는 조각은 그 조각만 기기 음성.

**조각 재생**

- 조각마다 그 시점의 엔진(`getTtsEngine(lang)`)을 따른다 — 속도·엔진 변경은 **다음 조각부터** 반영.
- cloud: 캐시/합성 → 재생. 실패(합성 에러·재생 에러·타임아웃)하면 **그 조각만** 기기 음성. 조각당 cloud 시도 1회, 한 방향 폴백(cloud → device → 건너뜀).
- **501(키 없음)을 한 번 받으면 이후 조각은 기기 직행**(`cloudOff`) — 로컬·키 미설정에서 조각마다 요청을 되풀이하지 않는다.
- **합성 대기 타임아웃 8초** — **큐가 그 조각을 기다리기 시작한 시점부터** 잰다(look-ahead가 요청을 먼저 보냈어도, 앞 조각을 재생하는 동안의 시간은 세지 않는다 — 느린 망에서 멀쩡한 합성이 기기 음성으로 떨어지지 않게). 타임아웃은 **대기 쪽 setTimeout**으로만 걸고, 요청은 큐의 AbortController로만(큐가 끝날 때) 끊는다 — 늦게 끝난 합성도 캐시에 남아 재청취에 쓰인다(`AbortSignal.any`·`AbortSignal.timeout`은 iOS 17.4+라 쓰지 않는다). 넘으면 그 조각은 기기 음성.
- **클라우드 조각 재생 안전 타임아웃**: `ended`가 끝내 안 오면 큐가 멈춘다. 오디오 `duration`이 유한하면 `duration × 1000 + 3초`, 아니면 기기 추정식과 같은 값으로 상한을 두고, 넘으면 그 조각을 끝난 것으로 보고 다음으로 간다(재생 중 소리는 끊는다).
- 지문 공급자(`GET /api/tts`) fetch에 3초 타임아웃. **타임아웃·네트워크 실패는 그 세션을 영구히 "메모리만"으로 고정하지 않는다** — 이번 조회만 메모리로 처리하고, 다음 캐시 접근에서 다시 시도한다(세션당 조회 시도 총 3회 — 첫 시도 포함, 동시에 몰린 조회는 한 번의 시도를 함께 기다리고, 저장(put)은 조회를 새로 일으키지 않는다. 200인데 본문이 깨진 응답도 일시 실패로 센다. 서버가 명시적으로 지문 없음을 주면 기존대로 메모리만). 그러지 않으면 한 번의 느린 응답이 영어 단어장까지 모든 화면의 영속 캐시를 그 세션 내내 꺼 재합성 요금을 낸다.
- device: **기다릴 수 있는 기기 재생**(`speakDeviceAwait`) — `onend`/`onerror`로 풀리고, `currentPlayStop`에 등록돼 `cancelPlayback()`이 이벤트를 기다리지 않고 즉시 푼다. utterance는 모듈 변수로 붙잡는다(GC로 `onend`가 사라지는 Chrome 버그). 말하는 중일 때만 `cancel()`한다(조각마다 무조건 cancel 금지 — iOS·Chrome에서 새 발화가 씹힌다). **안전 타임아웃**: 추정 `max(3초, 글자수 × 250ms ÷ rate + 2초)`; 만료 시 `speechSynthesis.speaking || pending`이면 1초씩 연장(상한 = 추정 × 3), 아니면(또는 상한) `cancel()` 후 다음 조각. 기존 `fallbackDevice`(무조건 cancel·onend 없음)는 큐에서 재사용하지 않는다.
- 소리를 낼 수 없는 상태(기기 음성 미지원 + cloud 불가)로 **연속 3조각**이 즉시 끝나면 큐를 `"stopped"`로 끝낸다(하이라이트만 번쩍이며 "done"이 되지 않게).
- 테스트 훅 `__setQueueTiming({...})`(기존 `__clearTtsMemoryCache` 관용구)로 타임아웃 상수를 eval에서 줄일 수 있게 한다.

**미리 받기(look-ahead)** — 큐 전용이다.

- 큐마다 자기 `AbortController`와 로컬 `pending: Map<cacheKey, Promise<Blob>>`를 둔다(키 = `${lang}:${speed}:${text}`, 기존 캐시 키와 동일 → 속도를 바꾸면 자연히 무효). 재생 단계는 `pending.get(key) ?? getAudioBlob(...)`을 기다린다 — **같은 문장을 두 번 합성하지 않는다**(짧은 제목 조각 뒤 긴 조각에서 흔히 겹친다).
- 조각 i 재생 중 **다음 cloud 조각 2개**(device 조각은 세지 않음)를 순차로 받는다. 발사 직전에 엔진·`canUseCloud`를 다시 확인한다.
- 전역 `prefetchSpeech`/`prefetchAbort`/`prefetchLang`을 **건드리지 않는다**(페이지 프리페치와 서로 끊지 않게). 큐가 끝나면 abort·맵 비우기.
- 해설 전체를 미리 합성하지 않는다(안 들을 수도 있다 — 비용 가드).

**iOS 자동재생 제약** — 사용자 탭 밖에서 새 `Audio`를 `play()`하면 iOS Safari가 막을 수 있다.

- 큐는 **오디오 요소 하나(`queueAudio`)를 재사용**한다. `playBlob(blob, token, el?)`에 요소 주입만 추가한다(기본값은 지금처럼 `new Audio` — `speak()` 경로 불변). 주입 시 이전 핸들러를 먼저 비우고 `el.src = url`. `finish`의 동일성 검사는 `currentAudioUrl === url`(호출마다 유일)로 바꾼다.
- `unlockSpeechPlayback()`: `queueAudio`를 만들고(없으면) 0.1초 무음 WAV(한 번 만든 objectURL, 상수라 revoke 안 함)로 `play()` — 그 Promise의 reject(AbortError 등)는 따로 삼킨다. 기기 음성도 `cancelPlayback()` **다음에** 볼륨 0 빈 발화(`" "`)를 한 번 말해 잠금을 푼다. `speakQueue`는 시작할 때(취소 **다음에**, **첫 `await` 전에**) 이 잠금 해제를 스스로 한다 — 그래서 **탭 핸들러 안에서 동기적으로** 호출돼야 한다. 공개 `unlockSpeechPlayback()`은 **지금 나는 소리를 끊지 않는다**(재생 중이면 요소·발화를 건드리지 않고, 조용할 때만 잠금 해제) — §19 세션의 ✓ 탭이 앞 세트 안내 음성을 자르지 않게.
- 큐 요소에서 **우리가 일으키지 않은 `pause`**(잠금 화면 ⏸·전화)가 오면 큐를 `"stopped"`로 끝낸다(`ended`가 안 와 막히거나 타임아웃 뒤 다시 재생하지 않게).
- 재생한 조각의 `objectURL`은 기존 규약대로 회수한다(누수 금지 — eval에서 생성 수 = 회수 수).
- 최종 확인은 실기기(아빠 iPhone Safari)다.

### 18-3. 한국어를 클라우드 TTS 언어에 추가

- `lib/tts-shared.ts`: `TTS_LANGS = ["en-US", "ja-JP", "ko-KR"]`(라우트 zod enum이 이 배열을 쓰므로 자동 허용).
- `lib/tts.ts`: `TTS_INSTRUCTIONS["ko-KR"]`를 기존처럼 **영어로** 쓴다 — 요지: 한국어 표준어(서울)로 또박또박, **글 속 일본어(가나·한자, 특히 「」 안)는 일본어 읽기로 — 중국어 금지**, 성인 학습자에게 강의를 설명하는 차분한 교사 톤. `export function ttsInstructionsFor(lang: TtsLang): string`를 추가해 eval이 모든 `TTS_LANGS`의 지시가 비어 있지 않은지 확인한다(tsx eval은 타입 검사를 안 하므로).
- **`TTS_INSTRUCTIONS_VERSION`은 올리지 않는다(2 유지).** 이 값은 영속 캐시 지문 전체에 걸린다 — 올리면 이미 캐시된 영어·일본어 오디오가 통째로 비워져 재합성 비용이 난다. 새 언어 추가는 기존 키와 겹치지 않는다. ⚠️ 나중에 **ko 지시를 튜닝하면 버전을 올려야 하고, 그러면 전 언어 캐시가 비워진다** — 그 비용을 감수할 때만 고친다.
- **한국어 기본 엔진은 cloud**(`DEFAULT_ENGINE.ko = "cloud"`). 이유: 기기 한국어 음성은 해설 속 일본어 인용을 한국어식으로 읽거나 건너뛴다. 일본어 기본(device, Kyoko)은 그대로 — 해설 듣기의 기본 조합은 **"한국어 해설자(클라우드) + 일본어 원어민(기기)"**.
- `components/tts-engine-control.tsx`: 언어 라벨을 삼항이 아니라 맵(`{"en-US":"영어","ja-JP":"일본어","ko-KR":"한국어"}`)으로, `SAMPLE["ko-KR"]`은 일본어 인용이 섞인 문장(예: `안녕하세요. 오늘은 「は」와 「が」의 차이를 알아볼게요.`)으로 — 혼합 낭독 지시가 먹는지 들어 볼 수 있게.
- **영속 캐시 상한**: 해설 한 번이면 한국어 조각 30~60개가 IDB에 들어간다. 항목 상한 300이면 대화 몇 개만 들어도 은우의 영어 단어 오디오가 밀려난다 → `lib/tts-cache.ts`의 `MAX_ITEMS`를 **1000**으로(바이트 상한 50MB는 그대로 — 실제 제약은 바이트가 한다).
- 비용: 대화 하나의 해설이 대략 1~2천 자 — §16-0과 같은 "무시할 만한" 규모이고, 한 번 합성하면 영속 캐시에 남는다.

### 18-4. 화면 (`components/ja-dialog-coaching-view.tsx`)

- 해설 맨 위 **해설 듣기 바**(`position: sticky; top: var(--streak-h, 0)`; 배경 `var(--bg)` — 자동 스크롤이 카드를 따라가도 ■ 멈추기가 화면에 남게): 정지 상태면 `🎧 해설 전체 듣기`, 재생 중이면 `■ 멈추기` + 진행 **`{조각 index+1} / {대본 길이}`**(조각 기준, `aria-live="polite"`). `<details>` "⚙️ 소리 설정" 안에 `TtsSpeedControl`, `TtsEngineControl lang="ko-KR"`, `TtsEngineControl lang="ja-JP"` + "화면을 끄고 들으려면 일본어도 클라우드로" 안내 한 줄.
- 각 섹션 제목 옆 **`▶`** = 그 섹션 첫 조각부터 이어 듣기(UI가 오프셋을 더해 절대 인덱스로 관리).
- 재생 중 카드(섹션·item) **하이라이트**: 레이아웃이 밀리지 않게 `border-color` + `box-shadow: 0 0 0 1px var(--accent)`. item이 null(제목 조각)이면 섹션 제목을 강조. (section,item)이 바뀔 때만 `scrollIntoView({ block: "nearest", behavior })`(`prefers-reduced-motion`이면 `"auto"`), 카드에 `scroll-margin-top: calc(var(--streak-h, 0px) + var(--coach-bar-h, 56px) + 8px)` — 듣기 바 실제 높이를 ResizeObserver로 재 `--coach-bar-h`에 넣는다. 재생을 시작하면 소리 설정 `<details>`를 접는다(펼친 설정이 바를 키워 따라가는 카드를 가리지 않게).
- 일본어 문장 옆 **🔊**(기존 `.speak` 클래스·`speakJa`): `quoteJa`, `originalJa`(취소선 그대로 — 내가 한 말과 고친 말을 귀로 대조), `betterJa`, `practice.ja`. 누르면 토큰 규약으로 이어 읽기가 멈춘다.

- 정지 조건: ① 언마운트(`useEffect(() => () => …, [])`), ② **대본 내용 키**(`script.map(p => p.lang + "|" + p.text).join("\n")`)가 바뀔 때(해설 "다시 만들기"). 참조만 바뀌는 `router.refresh()`("단어장에 담기")에는 멈추지 않는다. 정지에는 `stopSpeaking()`이 아니라 **큐가 돌려준 stop**을 쓴다(말풍선 🔊를 죽이지 않게).

### 18-5. 프리페치 정리

대화 상세는 부모(전사 `turns`)와 자식(해설 어휘·연습)이 각자 `prefetchSpeech`를 부른다. `prefetchSpeech`는 새 배치가 오면 직전 배치를 끊고, React 패시브 효과는 **자식 → 부모** 순으로 돌기 때문에 **해설 쪽 프리페치는 부모에게 항상 끊긴다**(일본어 엔진이 cloud일 때 해설 🔊 첫 재생이 느린 원인. 기본 device면 둘 다 no-op이라 드러나지 않았다).

→ 해설 뷰에 `prefetch?: boolean`(기본 true) prop. 상세는 `prefetch={false}`로 끄고, **전사 문장 + `coachingJaTexts(coaching)`을 한 배열로** 한 번만 부른다. 의존성은 배열 참조가 아니라 **문자열 키**(`join("\u0001")`) — `router.refresh()`로 참조만 바뀌면 다시 시작하지 않는다(중단된 요청의 합성 요금 낭비 방지). 검토 화면은 부모가 프리페치하지 않으므로 기본값(true) 그대로. 한국어 해설은 미리 받지 않는다(이어 듣기 look-ahead가 맡는다).

## 19. 아빠의 운동 — 러시안 파이터 풀업·푸시업 루틴 (2026-09)

### 19-0. 무엇을 위한 것인가

아빠(성인 학습자 — 일본어와 같은 사람)가 **파벨 차졸린의 러시안 파이터 루틴**(Greasing the Groove 계열 풀업·푸시업 사다리)을 매일 따라가도록, **오늘 할 세트를 계산해 보여 주고, 기록을 받아 다음 날을 자동으로 정하는** 기능이다. 사이클이 끝나면 RM을 재측정해 **다음 사이클을 자동으로 다시 계산**한다.

- 사용자 원안(2026-09-24): RM 입력 / 일일 세트 성공 여부 기록 → 사다리 수열 생성·예외 처리 엔진 → 상태 저장(현재 Day·실패 플래그·누적 볼륨) → 당일 목표 세트와 진행률 표시. 원안 Python 생성기(`step_indices = [None, 4, 3, 2, 1]`, 블록마다 직전 블록 베이스 +1)가 계획의 오라클이다.
- **AI 호출이 없다.** 원안의 LLM 코치 프롬프트가 하던 일(Day 계산·실패 롤백·브리핑)은 전부 결정적 규칙이라 **순수 함수 엔진**이 한다. 같은 입력이면 언제나 같은 답이 나와야 하는 상태 기계를 LLM에 맡길 이유가 없다(비용·오답 위험만 는다). 브리핑 문구와 주의사항은 코드가 만든다.
- 상단 스트릭(§17)에는 **일본어와 구분된 별도 트랙 `💪 운동`** 으로 들어간다(2026-09-24 사용자 요청, §17-7). 일본어 스트릭에는 섞지 않는다. 세는 기준은 "루틴을 지킨 날"(운동·실패 기록일 + 계획된 휴식일 + 재측정 끝낸 날).

### 19-1. 사다리 규칙 (엔진 — `lib/workout.ts`, 순수 함수)

**Day 1 사다리(베이스)** — RM으로부터:

- 맨 위 세트 = `max(1, floor(RM × 비율))`. 비율: **풀업 0.6(=3/5), 푸시업 0.5(=1/2)**. 부동소수 오차를 피하려고 **정수 분수**로 계산한다(`Math.floor(rm * 3 / 5)`, `Math.floor(rm / 2)`).
- 5세트, 1회씩 내려간다: `[top, top-1, top-2, top-3, top-4]`, 각 세트 **최소 1**.
- 예: 풀업 10RM → `[6,5,4,3,2]`(20회), 푸시업 18RM → `[9,8,7,6,5]`(35회), 풀업 11RM → top 6, 푸시업 17RM → top 8, 풀업 1~3RM → `[1,1,1,1,1]`.
- RM 입력 범위: 정수 **1~150**. `top − 4 < 1`(풀업 RM < 9, 푸시업 RM < 10)이면 설정 화면에 경고: "RM이 낮으면 이 루틴의 부담이 커요 — 사다리가 평평해져요." (막지는 않는다.)
- **목표는 항상 사이클에 저장된 `base`로 계산한다.** RM에서 다시 계산하지 않는다(규칙이 바뀌어도 진행 중 사이클이 흔들리지 않게).

> **Day 23 뒤 3일 연속 휴식은 의도다** — 원안 Python의 Day 24 REST(블록 4의 휴식일) + 원안 문구 "Day 24 완료 시 25~26 휴식". 휴식 카드에 "사이클 마무리 휴식 1/3"처럼 순번을 보인다.

**운동일 목표** — Day `n`에서 블록 `b = floor((n−1)/6)`, 블록 안 `d = (n−1) % 6`(0~4):
`target[i] = base[i] + b + (d > 0 && i ≥ 5 − d ? 1 : 0)` (i = 0~4). 즉 블록 베이스 = Day 1 +b, 블록 안에서 **뒤쪽 세트부터** 하루에 하나씩 +1(d=1 → 5세트, d=2 → 4세트, d=3 → 3세트, d=4 → 2세트). 다음 블록 첫날은 1세트까지 +1된 셈이라 "Day 1 전 세트 +1"과 같다.

### 19-2. 기록과 상태 기계

**저장하는 것은 사건(event)뿐이다.** "현재 Day"·"실패 플래그"·"누적 볼륨"은 **저장하지 않고 사건을 재생해 계산한다**(스트릭 §17-5와 같은 규약 — 저장하면 두 진실이 갈린다).

```ts
type WorkoutExercise = "pullup" | "pushup";
interface SetPair { pullup: number[]; pushup: number[] }       // 5개씩
interface FailedAt { exercise: WorkoutExercise; setIndex: number /*0..4*/; reps: number | null }
interface WorkoutEvent {
  date: string;        // KST 일자 YYYY-MM-DD — 서버가 기록 시점에 찍는다(lib/kst)
  at: string;          // ISO UTC
  kind: "complete" | "fail";
  day: number;         // 이 운동이 차지한 계획 Day(슬롯)
  targetDay: number;   // 실제로 쓴 목표의 Day — 보통 day, 실패 후 복귀(재부여)면 직전 성공 Day
  failed: FailedAt | null;  // fail일 때만
  reps: SetPair;       // 실제 수행 횟수 — 서버가 계산해 넣는다
  durationSec: number | null; // 실측 소요시간(초) — 세션이 잰 클라이언트 보고값, 없거나 범위 밖이면 null (§19-8, 2026-09-26)
}
```

`durationSec`은 이 절의 "사건 값은 서버 계산값" 원칙의 **유일한 예외**다 — 서버가 알 수 없는 벽시계 값이라 형식·범위만 검증해 싣고(§19-8), 재생·오늘 상태·진행률·볼륨 계산에는 쓰지 않는다(소요시간 표시에만 쓴다).

**재생(`replay`)** — 사건을 **배열 순서 그대로** 접는다(정렬하지 않는다 — 배열 끝이 undo 대상이고, 저장 불변식이 날짜 순서를 보장한다):

- 초기: `nextDay = 1`, `repeatOf = null`, `lastSuccessDay = null`, `failsAtNextDay = 0`.
- `complete`:
  - 재부여 운동(`targetDay ≠ day`): `repeatOf = null`, `lastSuccessDay = targetDay`. **`nextDay`·`failsAtNextDay`는 그대로**(실패했던 그 Day에 다시 도전한다).
  - 보통 운동: 완료 집합에 `day`를 넣고 `lastSuccessDay = day`, `nextDay` = 다음 운동일(23 → 27), **`failsAtNextDay = 0`**.
- `fail`: `repeatOf = lastSuccessDay`(없으면 null → 같은 Day를 그대로 재도전), `failsAtNextDay += 1`, 실패 수 +1(`failsByDay[day] += 1`).
- 모든 사건: 볼륨 += `reps` 합.

**휴식은 달력이 채우고, 운동은 기록이 채운다.**

- 마지막 사건 L(날짜 dL) 다음부터 **휴식 슬롯**이 달력 하루씩 차지한다:
  - L이 `fail` → 슬롯 1개: **회복 휴식**(recovery).
  - L이 재부여 `complete` → 슬롯 0개(회복 휴식을 이미 했다 — 계획 휴식을 또 넣지 않는다).
  - L이 보통 `complete` → L.day와 `nextDay` 사이의 계획 휴식일 전부(Day 5 뒤 → [6], Day 23 뒤 → [24, 25, 26], 그 밖 → []).
- `gap = diffDateStrings(dL, today)`(KST 일자 차, `lib/kst.ts`에 추가하는 단일 정의):
  - `gap ≤ 0` → **오늘 기록함**(`recorded_today`). 오늘은 더 할 게 없다.
  - `1 ≤ gap ≤ 슬롯 수` → 그 슬롯의 **휴식/회복 휴식**.
  - `gap > 슬롯 수` → `nextDay`가 27이면 **재측정**, 아니면 **운동**: 슬롯 Day = `nextDay`, 목표 Day = `repeatOf ?? nextDay`.
- 사건이 없으면: 오늘 < 시작일 → **시작 전**, 아니면 Day 1 운동.
- **운동일은 기다린다.** 운동일에 기록하지 않고 며칠이 지나도 같은 Day가 그대로다(벌칙 없음). **휴식일은 기다리지 않는다** — 달력이 지나면 쉰 것으로 친다. 휴식일엔 기록 버튼이 없다(파벨 규칙: 휴식일에 하지 않는다).
- **깨진 사건**(운동일이 아닌 day·targetDay, 달력에 없는 date)은 상태 계산에서 **없는 것으로 본다** — 정규화 규칙과 같은 기준. 깨진 마지막 사건이 "오늘 기록함"으로 기록을 영영 막거나 "아주 옛날"로 상태를 튀게 하지 않는다. `diffDateStrings`는 형식 밖 입력에 NaN을 낸다. 읽기 함수(`todayStatus`·`upcoming`·`snapshot`)는 절대 던지지 않고(페이지 500 방지), 판정 함수(`decide*`)만 형식 오류에 RangeError를 던진다(라우트 zod가 먼저 막으므로 프로그래밍 오류 — 500).
- **하루에 사건은 최대 1개**, 사건 날짜는 엄격히 증가한다(서버는 오늘 상태가 `workout`일 때만 기록을 받고, `workout`은 gap ≥ 1에서만 나온다).
- **날짜는 전송 시각 기준이다.** 23:50에 끝낸 세션이 다음 날 아침에 전송되면 그날 기록이 되고 일정이 하루 밀린다 — 운동일은 기다리므로 계획이 틀리지는 않는다(알려진 한계, 되돌리기로 정정 가능).

**오늘 상태(`TodayStatus`) — 화면이 보는 유일한 계약.** 화면은 규칙을 다시 구현하지 않는다.

```ts
type Upcoming =
  | { kind: "workout"; day: number; targetDay: number }
  | { kind: "rest"; day: number; cycleEnd: boolean; index: number; of: number }
  | { kind: "recovery"; pendingDay: number }
  | { kind: "retest" };
type TodayStatus =
  | { kind: "not_started"; startDate: string; daysUntil: number; displayDay: 1 }
  | { kind: "workout"; day: number; targetDay: number; isRepeat: boolean; target: SetPair;
      totals: { pullup: number; pushup: number }; retestHint: boolean; displayDay: number }
  | { kind: "rest"; day: number; cycleEnd: boolean; index: number; of: number; next: Upcoming; displayDay: number }
  | { kind: "recovery"; pendingDay: number; resumeTargetDay: number; next: Upcoming; displayDay: number }
  | { kind: "recorded_today"; outcome: "complete" | "repeat_complete" | "fail"; day: number; targetDay: number;
      tomorrow: Upcoming; displayDay: number }
  | { kind: "retest"; displayDay: 27 };
```

- `displayDay`: 운동 → `day`, 휴식 → 그 휴식 Day, 회복 → `pendingDay`, 기록함 → `day`, 시작 전 → 1, 재측정 → 27.
- `retestHint = failsAtNextDay ≥ 2` — 같은 슬롯 Day에서 두 번 이상 실패했으면(연속 실패든, "실패 → 재부여 성공 → 또 실패" 루프든) "RM 재측정을 고려해 보세요" 안내. **재부여 성공은 이 수를 되돌리지 않는다**(되돌리면 루프에서 안내가 영영 안 뜬다).
- 앞으로의 일정(`tomorrow`, `next`, 미리보기)은 엔진의 `upcoming(cycle, today, n)`이 만든다 — 오늘부터 하루씩, 운동일이면 **가상의 성공 사건을 덧붙여** `todayStatus`를 되풀이하는 시뮬레이션. 예: 실패 당일 → [회복, 재부여 운동(X, X−1), 운동(X, X)].
- 문구 예: 재부여 성공 당일 "✅ Day 5 목표 완료 — 내일 Day 7 재도전"(휴식 없음), 보통 성공 "🎉 Day 5 완료 — 내일은 휴식(Day 6)".

**실패 처리**(원안 Failure Handler):

1. 세트를 못 채우거나 자세가 무너지면 **그 자리에서 중단**하고 실패로 기록한다 — 어느 운동의 몇 세트에서, 그 세트 몇 회까지 했는지(횟수는 선택, `0 ≤ reps ≤ 목표` — 횟수는 채웠지만 자세가 무너진 경우도 담는다).
2. 다음 날은 **회복 휴식** 1일.
3. 복귀하면 **직전에 완전히 성공한 Day의 목표**로 한 번 한다(재부여). Day 1에서 실패해 직전 성공이 없으면 Day 1을 그대로 다시 한다(재부여 아님).
4. 재부여 운동을 성공하면 **실패했던 Day에 다시 도전**한다(그 사이 휴식 없음).
5. 같은 Day에서 실패가 2회 이상이면 재측정 안내(강제 아님).

**수행 횟수(볼륨)** — 서버가 계산한다(클라이언트 숫자를 믿지 않는다). 기준 목표 = `target(cycle.base, targetDay)`:

- `complete` → 목표 그대로.
- `fail` → 실패한 스텝 **이전** 스텝은 목표 그대로, 실패한 세트는 입력 횟수(없으면 0, `0..목표`로 클램프), 이후는 0. 예: Day 1 푸시업 3세트(setIndex 2 = 스텝 5)에서 4회 → 풀업 [6,5,4,0,0], 푸시업 [9,8,4,0,0].
- 누적 볼륨 = 사이클 안 모든 사건의 `reps` 합(성공·실패·재부여 모두). **원시 횟수만** 보인다(590 대비 % 같은 표시는 하지 않는다 — 실패·재부여로 100%를 넘을 수 있다).
- **진행률** = 보통 `complete`로 끝낸 **서로 다른 운동 Day 수 / 20**, 표시 `Math.round(done / 20 × 100)`%. 재부여 성공은 진행률에 넣지 않는다(볼륨엔 넣는다). 계획표의 ✗ 표시는 사건의 `day`(슬롯) 기준 실패 수.

### 19-3. 사이클 전환과 재측정

- **처음 시작**: 활성 사이클이 없으면 설정 화면 — RM 기본값 **풀업 10, 푸시업 18**(원안의 현재 상태), Day 1 사다리 미리보기(클라이언트가 `lib/workout`의 순수 함수로 계산), 시작일 **오늘/내일**.
- **재측정(Day 27)**: RM 입력(현재 RM으로 미리 채움) + 측정 안내("엄격한 정자세로, 반동 없이 — 오늘 하루만 최대치"). 새 사이클 시작일 기본값은 **내일**(최대치 측정 당일 또 운동하지 않게).
- **도중 재측정**: 언제든 "RM 다시 재기(새 사이클)"로 새 사이클을 시작할 수 있다. 시작일은 오늘/내일 중 고른다.
- **닫는 사이클의 상태는 사건 재생으로 판정한다**: `closingStatus(cycle) = replay(events).nextDay === 27 ? "completed" : "abandoned"`. 20개 운동일을 다 마쳤으면 재측정 화면이 아닌 곳(Day 23 완료 당일, 마무리 휴식 중)에서 재측정해도 **completed**다. 사이클은 지우지 않는다(기록 보존).
- **사건이 0개인 활성 사이클을 다시 설정하면 닫지 않고 그 자리에서** `rm`·`base`·`startDate`를 갈아끼운다(RM 오타·시작일 변경이 "중단 사이클" 찌꺼기로 쌓이지 않게, cycleNo도 그대로).
- **RM 변화**("10 → 13")는 연속한 두 사이클의 `rm`(cycleNo 순)에서 파생한다 — 별도 필드로 저장하지 않는다.
- 활성(`active`) 사이클은 **최대 1개**다. 읽을 때 여러 개가 보이면(레거시·사고) `pickActiveWorkoutCycle`이 결정적으로 하나를 고른다(createdAt이 가장 늦은 것) — 한 곳에만 정의(`lib/workout.ts`), 페이지·스토어가 같이 쓴다. 새 사이클을 만들 때 나머지 활성은 전부 닫는다.
- **마지막 기록 취소**: 잘못 누른 기록을 되돌린다 — 활성 사이클의 마지막 사건 1개를 뺀다. 두 단계 확인(브라우저 `confirm()` 대신 화면 안 확인 패널). 가족 실데이터를 되돌릴 수 없게 바꾸는 작업이라 **prod-guard 대상이다**(§19-4).

### 19-4. 저장 모델 — `WorkoutCycleRecord` (Firestore 컬렉션 `workoutCycles`)

```ts
interface WorkoutCycleRecord {
  id: string;
  createdAt: string;                 // ISO
  cycleNo: number;                   // 1, 2, 3 … (전체 max + 1)
  startDate: string;                 // KST YYYY-MM-DD — Day 1을 할 수 있는 첫날
  rm: { pullup: number; pushup: number };
  base: SetPair;                     // Day 1 사다리(5개씩) — RM에서 계산해 고정 저장
  status: "active" | "completed" | "abandoned";
  endedAt: string | null;            // ISO
  rev: number;                       // 변경마다 +1 (낙관적 동시성 토큰, 생성 시 0)
  events: WorkoutEvent[];            // 시간순 append
}
```

- **타입의 단일 정의처는 `lib/workout.ts`**(런타임 의존성은 `./kst`뿐 — 클라이언트·eval 안전). `lib/store.ts`는 `import type`으로 가져와 재수출한다(store는 서버 전용 — 엔진이 store를 import하면 안 된다). `lib/workout-contract.ts`는 타입 재수출 + 요청·응답 shape만. 모든 값은 직렬화 가능(Date 객체 금지 — RSC props로 넘어간다).
- 사건은 사이클 문서 안의 배열이다(사이클당 수십 건). 날짜 필터 쿼리를 두지 않는다(복합 인덱스 회피 규약) — 전체를 읽어 메모리에서 고른다. Firestore는 `undefined`를 거부하므로 `failed`·`endedAt`·`durationSec`은 반드시 `null`로 쓴다(`normalizeWorkoutCycle`/`normalizeWorkoutEvent` — `normalizeJaDialogRecord` 관용구, 두 백엔드 공유, 정의는 `lib/workout.ts`. `durationSec`이 없는 옛 사건·범위 밖 값은 null로 채운다 — §19-8). 정규화는 깨진 사건을 버리고 경고하며, ISO가 아닌 `createdAt`은 epoch ISO로 둔다.
- **검증과 쓰기는 한 원자 단위다.** 판정은 순수 함수(`decideLog`·`decideUndo`·`decideStart` — `lib/workout.ts`)가 하고, 스토어는 그것을 **파일 백엔드는 `mutate` 콜백 안에서, Firestore는 `getDb().runTransaction()` 안에서** 호출한다(`applyVocabLink` 관용구와 같은 구조 — 저장소 첫 트랜잭션 도입이니 이유를 주석으로 남긴다). 기존 `get → 판정 → update` 관용구를 복사하지 않는다(Cloud Run 인스턴스가 여럿이면 뒤 쓰기가 앞 쓰기를 덮는다). `todayKst`·`nowIso`는 라우트가 트랜잭션 밖에서 한 번 계산해 넘긴다(트랜잭션 재시도에도 결정적).
- **동시성 토큰은 `rev`**: 기록·취소 요청은 클라이언트가 본 `expectedRev`를 보낸다. 사건 **개수**가 아니라 rev로 대조한다(개수는 "다른 탭에서 취소 후 다시 기록"하면 같아져 낡은 탭의 취소가 엉뚱한 사건을 지운다 — ABA). 사이클 시작 요청은 클라이언트가 본 활성 사이클 id `expectedActiveCycleId`(없으면 null)를 보낸다 — 연타·두 탭에서 두 번 만들어지지 않는다.
- **서버는 자기가 계산한 값으로 사건을 만든다**: 오늘 상태를 다시 계산해 `workout`이 아니면 거절, 요청의 `day`·`targetDay`는 "화면이 낡지 않았다"를 확인하는 데만 쓰고, 사건의 day·targetDay·date·at·reps는 서버 계산값. 예외는 `durationSec` 하나 — 클라이언트 보고값을 형식·범위만 보고 싣는다(§19-8).
- **prod-guard**: `DestructiveOp`에 `"undoWorkoutEvent"`·`"closeWorkoutCycle"`을 추가한다. **Firestore 백엔드에서만**(파일 백엔드는 가드하지 않는 기존 관용구) 취소 첫 줄, 그리고 시작 요청이 사건 있는 활성 사이클을 닫는 분기에서 `assertDestructiveAllowed`를 부른다. 최초 생성·사건 0개 제자리 교체·기록(append)은 가드 대상이 아니다. 라우트는 `isProdGuardError` → 403 `prod_guard`.
- **파일 백엔드**: `DbShape.workoutCycles: WorkoutCycleRecord[]`(**필수 필드**). `emptyDb`·`readDb`(`(parsed.workoutCycles ?? []).map(normalizeWorkoutCycle)` — 옛 db.json 호환)·`mergeDbForSeed`(**`mergeById(cur.workoutCycles, seed.workoutCycles)`** — 빠뜨리면 `npm run seed`가 운동 기록을 지운다)·`scripts/seed.ts`(`workoutCycles: []`) 네 곳을 함께 바꾼다.
- `scripts/migrate-to-firestore.ts`에는 **넣지 않는다** — 운동 기록은 프로덕션에서만 생긴다(로컬 테스트 사이클이 프로덕션에 활성으로 올라가면 활성이 2개가 된다).

### 19-5. API

| 경로 | 요청 | 동작 |
|---|---|---|
| `POST /api/workout/cycle` | `{ pullupRm, pushupRm, start: "today" \| "tomorrow", expectedActiveCycleId }` | 활성과 expected 대조 → 활성 사건 0개면 제자리 교체, 아니면 `closingStatus`로 닫고 새 사이클(cycleNo = max+1) |
| `POST /api/workout/log` | `{ cycleId, expectedRev, kind, day, targetDay, failed, durationSec }` | 오늘 상태 재계산·대조 후 사건 append(date·at·reps는 서버, `durationSec`은 형식·범위만 보고 싣는다 — §19-8), rev+1 |
| `POST /api/workout/undo` | `{ cycleId, expectedRev }` | 활성 사이클의 마지막 사건 제거, rev+1 |

- 공통 관용구: `export const runtime = "nodejs"`, zod `safeParse`(issues 매핑), 계약 타입으로 받는 `json(body, status)` 헬퍼, `req.json()` 실패 → 400. AI 없음 → `OPENAI_API_KEY` 무관.
- 요청 계약 타입(`lib/workout-contract.ts`)과 라우트 zod 스키마는 **컴파일 때 양방향으로 묶는다**(`[Request, z.infer<typeof bodySchema>] extends [z.infer<…>, Request]`) — 화면은 계약 타입으로 보내고 라우트는 zod로 받으므로, 한쪽만 필드명을 바꾸면 런타임 400이 된다. 스토어 입력 타입도 엔진 판정 입력(`Decide*Input`)의 별칭이다(두 정의 금지).
- zod: RM은 `z.number().int().min(1).max(150)`. log의 `day`·`targetDay`는 1~23 정수이며 운동일. `kind`로 판별 유니온 — `complete`는 `failed: null`, `fail`은 `failed: { exercise, setIndex 0..4, reps: 정수 0..500 | null }`(`.nullish()` 금지 — undefined가 Firestore로 샌다). 두 갈래 공통 `durationSec`(§19-8, 계약은 필수 nullable)은 `z.number().int().min(0).nullable().default(null)` — 형식(정수·0 이상) 위반은 400 `invalid_input`(`issues[].path = "durationSec"`)이지만 **3시간 상한은 zod가 보지 않는다**(zod에 max를 두면 상한을 넘긴 기록 전체가 400으로 날아간다 — 엔진 `decideLog`가 기록은 받고 소요시간만 null로 싣는다). `.default(null)`은 필드가 **빠진** 요청을 400 대신 null로 채우는 선택이다: version-watch는 자동 새로고침을 하지 않아, 배포 전 번들을 든 채 며칠째 열린 폰 화면이 세션 끝에 보낸 기록을 잃지 않게(그 화면은 어차피 잴 수 없었으니 null — 근사 — 이 맞는 값이다). `.nullish()`와 달리 출력 타입이 `number | null`(필수)이라 위의 양방향 검사가 그대로 묶이고 undefined가 새지 않는다.
- 응답: `{ ok: true, ... }` / `{ ok: false, error, messageKo, issues? }`. 에러 enum과 상태 코드:
  `invalid_input`(400) · `not_found`(404, 사이클 없음) · `conflict`(409, rev·활성 id 불일치 — 다른 탭·연타로 이미 바뀜) · `stale_state`(409, 오늘 상태가 운동이 아니거나 day·targetDay가 다름) · `not_active`(409, 닫힌 사이클) · `empty`(409, 취소할 사건 없음) · `prod_guard`(403) · `save_failed`(500).
  409 계열이면 화면은 메시지를 보이고 `router.refresh()`한다.
- **화면 데이터는 서버 컴포넌트가 직접 읽는다**: `app/workout/page.tsx`는 **`export const dynamic = "force-dynamic"`**(필수 — 빠지면 빌드 때 빈 DB로 정적 고정돼 "처음 시작" 화면이 영구히 박힌다. store를 읽는 모든 페이지의 관용구). 서버에서 `kstTodayString()` → `listWorkoutCycles()` → `pickActiveWorkoutCycle` → 엔진 `snapshot(active, today)` → 클라이언트 뷰에 직렬화 가능한 props. 렌더 중 `new Date()`·localStorage 금지(오늘은 props). 날짜 표시는 KST 문자열(`createdAt.slice(0,10)`은 UTC라 쓰지 않는다).
- PIN 게이트는 `proxy.ts`가 `/workout`·`/api/workout`을 자동으로 덮는다.

  - `workout`: 세트표(1~5세트 × 풀업/푸시업) + **`▶ 운동 시작`**(세션) + **`✓ 전부 해냈어요`**(폰 없이 이미 했을 때) + **`✗ 실패 기록`**(운동·세트·횟수 고르기). `isRepeat`면 배너 "실패 후 복귀 — Day {targetDay} 목표로 한 번, 성공하면 Day {day} 재도전". `retestHint`면 "같은 Day에서 두 번 이상 막혔어요 — RM 재측정을 고려해 보세요".

  - `rest` / `recovery`: "😴 Day 6 휴식 — 상체 완전 휴식"(마무리 휴식이면 "사이클 마무리 휴식 {index}/{of}") / "🩹 회복 휴식 — 내일 Day {resumeTargetDay} 목표로 복귀" + `next` 미리보기.

- **세션 모드**(`▶ 운동 시작`) — 전면 오버레이(z-index 20 + `lockBodyScroll`, 스트릭 헤드라인이 가려지는 게 의도 — §17-4):
  - 현재 스텝을 크게("풀업 1세트 · 6회"), `✓ 완료`(u-btn-primary) / `✗ 실패`(u-btn-secondary). 그 아래 **세트(라운드) 5행 목록**(한 행 = 풀업 + 푸시업).
  - 머리에 실시간 **경과 시계** "⏱ 경과 12:34"(1시간을 넘으면 `1:02:03`, 1초 틱, `role="timer"`·`aria-live="off"` — 매초 낭독하지 않게). 세션을 처음 연 순간부터 재고, 기록 요청을 보낸 뒤엔 그 시각에서 멈춘다. 시작 시각을 모르는 옛 진행 보존값을 이어 받았으면 숨긴다(§19-8).

  - 타이머 종료 알림: **비프**는 `✓` 탭 핸들러 안에서 `AudioContext`를 만들거나 `resume()`하고 그 컨텍스트로 낸다(가능하면 종료 시각에 미리 예약 — 탭 밖 재생 제약 회피). 진동(`navigator.vibrate`, 가능하면). **음성 안내**(토글, localStorage 영속, 기본 켬): `✓` 탭에서 `unlockSpeechPlayback()`을 부르고, 종료 시 `speakQueue([{ text: "다음, 풀업 2세트 5회", lang: "ko-KR" }])`(재사용 오디오 요소라 탭 밖에서도 나올 가능성이 높다). 세션 시작 탭에서 그날의 **휴식 뒤 안내 문구 4개**(휴식은 라운드 사이에만 있으므로 2~5세트의 첫 스텝인 풀업 안내만 — 첫 스텝과 푸시업 스텝 안내는 휴식 뒤에 나오지 않는다)를 `prefetchSpeech(phrases, "ko-KR")`로 미리 받는다. **음성·비프는 best-effort**, 시각 타이머가 기준이다. 화면이 꺼진 상태의 알림은 보장하지 않는다(Wake Lock은 best-effort — 요청하고, visible 복귀 때 재요청).
  - **목록 순서는 실시간으로 바뀐다**(2026-09-25 사용자 요청): **지금 할 세트가 맨 위**, 그 아래 남은 세트(번호순), **완료한 세트는 맨 아래**(번호순, 흐리게 ✓). 해야 할 일이 늘 눈앞에 오게 한다.
  - **세트 완료 축하 → 아래로 이동**: 푸시업 `✓`로 세트를 끝낸 순간 약 1초 축하(체크가 튀어 오르고 이모지가 터지며 "🎉 {n}세트 완료!", 되는 기기면 짧은 진동) 뒤, 그 세트 행이 **부드럽게 완료 구역(맨 아래)으로 미끄러져 내려가고** 다음 세트가 위로 올라온다(FLIP — 위치를 재고 transform으로 옮기는 방식, Web Animations/CSS transition. 새 라이브러리 금지). 풀업 `✓`는 그 줄에 작은 체크 애니메이션만(재배치 없음 — 세트가 아직 안 끝났다).
  - 애니메이션은 **보여 주기일 뿐 상태를 붙잡지 않는다**: 휴식 타이머·비프 예약·음성·저장은 탭 즉시 기존대로 진행하고, 애니메이션 중에도 조작은 상태 기준으로 동작한다(연타 가드는 그대로). `prefers-reduced-motion`이면 축하·이동 없이 즉시 재배치. 새로고침 복원·세션 재진입 때는 애니메이션 없이 최종 순서로 그린다. 마지막 세트 완료는 기존 완료 기록·"🎉 Day N 완료" 흐름을 그대로 탄다.
  - 순서 규칙의 정의처는 엔진 순수 함수 `roundDisplayOrder(step, held)`(`lib/workout.ts`, eval:workout "세트 목록 순서")다 — 화면은 현재 스텝에서 파생만 한다. 축하 문구는 목록 행과 함께 **휴식 영역 캡션 자리에도** 같은 1초 동안 보인다(보이는 높이가 약 620px 미만인 폰에서는 목록이 첫 화면 아래라 안 보이므로 — 자동 스크롤은 하지 않는다, 스크린리더 낭독은 한 곳만).

  - 실패: 그 세트에서 한 횟수를 고르게(선택, 0..목표) 한 뒤 기록 → 세션 종료.

### 19-8. 총 운동 소요시간 (2026-09-26)

사용자 요청: "총 운동소요시간 체크해줘. 지난건 대략 근사치로 하고 내일부턴 실제 소요시간으로." 지금 저장된 사건에는 **끝낸 시각(`at`) 하나뿐**이라(하루 사건 최대 1개, 세트별 시각 없음) 지난 기록의 실제 소요시간은 되살릴 수 없다. 그래서 실측과 근사를 나눈다.

**실측 — 세션(▶ 운동 시작)이 잰다.**
- 정의: 그날 세션을 **처음 연 순간**부터 **기록 요청을 처음 보낸 순간**(마지막 ✓ 또는 실패 기록)까지의 벽시계 시간(초). 휴식이 포함된다. 같은 기기 시계의 두 시각 차라 폰·서버 시계 차이에 영향받지 않는다.
- 시작 시각은 세션 진행 보존값(localStorage `workout-session:v1`)에 `startedAt`(epoch ms)으로 함께 둔다 — 새로고침하거나 닫았다가 "이어서 하기"를 해도 첫 시작이 유지된다. 그래서 진행 보존은 **0스텝·휴식 없음이어도 저장한다**(§19-6). 진행 복원 조건(`SessionMatch` — 사이클·rev·Day·날짜)이 깨지면 시작 시각도 함께 버려지고 새 세션은 지금부터 잰다. 이 기능 전의 옛 저장값(필드 없음)을 이어 받으면 시작을 모르므로 `durationSec: null`로 보낸다(근사치로 보인다).
- 끝 시각은 기록 요청을 **처음 보낸 순간**을 ref에 고정한다(네트워크 오류 뒤 다시 눌러도 값이 늘지 않는다). 실패 입력 패널에서 "돌아가기"로 운동을 이어 가면 고정한 끝 시각을 버린다 — 실패 기록 전송이 실패한 뒤 이어 한 운동은 아직 끝나지 않았다. `durationSec = round((끝 − 시작) / 1000)`이고, 기기 시계가 거꾸로 가 음수면 null이다. 렌더 중에는 `Date.now()`를 읽지 않는다(시각은 effect·핸들러·타이머 콜백에서만 — hydration 안전).
- 기록 요청(`POST /api/workout/log`)의 두 갈래(완료·실패) 모두에 `durationSec: number | null`을 싣는다. 서버는 형식(정수, 0 이상)과 상한(`WORKOUT_DURATION_MAX_SEC` = 3시간 = 10800초)만 검사하고, **범위 밖이면 기록은 받되 소요시간만 null**로 둔다 — 닫아 둔 채 몇 시간 뒤 끝낸 벽시계 값이 총합을 망치지 않게. §19-2 "사건은 서버 계산값" 원칙의 예외다: 소요시간은 서버가 알 수 없는 **클라이언트 보고값**이라 서버는 형식·범위만 검증한다.
- 검사는 둘로 나뉜다. 형식(정수가 아님·음수·문자열)은 라우트 zod가 400으로 막고, 상한은 엔진 `decideLog`가 null로 바꾼다(zod가 상한까지 보면 기록 전체를 잃는다). 필드가 **빠진** 요청은 zod `.default(null)`이 null로 채운다(옛 번들을 든 폰 화면 — §19-5). "쓸 수 있는 실측값인가"의 판정은 `isValidDurationSec`(정수 0..10800) **한 함수**이고 판정(`decideLog`)·정규화·표시(`eventDuration`)가 같은 함수를 쓴다 — 정규화는 소수를 자르지 않고 null로 둔다(추측하지 않는다). 0초도 유효한 실측이다.
- `WorkoutEvent`에 `durationSec: number | null`(필수 nullable)을 더한다. 옛 사건은 정규화(`normalizeWorkoutEvent`)가 null로 채운다 — **정규화 함수에 새 필드를 넣지 않으면 쓰기 직전 정규화가 값을 조용히 지운다**(두 백엔드 공통 함정). 새 사건 종류·새 쓰기 경로를 만들지 않으므로 원자성(`mutate`/`runTransaction`)과 `rev` 규약은 그대로이고(스토어 입력 타입이 `DecideLogInput`의 별칭이라 필드가 저절로 따라온다), 취소(undo)하면 소요시간도 사건과 함께 사라진다. 활성 사이클에 기록을 한 번 쓰면 그 사이클의 옛 사건 전부에 `durationSec: null` 키가 생긴다 — 쓰기 경계 정규화의 결과이고 의미는 같다.
- 세션 없이 오늘 카드의 "✓ 전부 해냈어요"·실패 기록으로 남긴 날은 잴 방법이 없다 → `durationSec: null` → 아래 근사치로 보인다.

**근사 — 실측이 없는 사건**(지난 기록·세션 없이 한 기록·상한 초과). 저장하지 않고 **읽을 때 엔진이 계산**한다(§19-2 "저장은 사건뿐, 파생값은 재생" — 백필로 프로덕션 DB를 고치지 않는다).
- `추정초 = Σ풀업 reps × 3 + Σ푸시업 reps × 2 + 수행 스텝 수 × 10 + 쉰 휴식 수 × 120`. 수행 스텝 수는 완료 10, 실패는 실패 스텝 번호 + 1. 쉰 휴식 수는 완료 4, 실패는 실패 스텝 앞에서 `restFollowsStep`인 스텝 수. 계수는 엔진 한 곳(`lib/workout.ts`)에 상수로 두고, 기본 휴식 2분(`DEFAULT_REST_SEC`)은 세션 컴포넌트도 같은 상수를 import한다(정의처 하나).
- 예(10/18RM): Day 1 완주 710초 ≈ 12분, Day 23 완주 805초 ≈ 13분, Day 1 푸시업 3세트(스텝 5)에서 4회로 실패 387초 ≈ 6분. 2026-09-25 이전(모든 스텝 뒤에 쉬던 시기)의 사건도 같은 식으로 근사한다 — 해당 사건이 1건 이하라 규칙을 나누지 않았다.
- 근사식은 `at`·`durationSec`을 보지 않는 순수·결정적 함수(`estimateEventSec`)다. 실패 지점이 없는 손상된 fail 사건은 "reps가 있는 앞쪽 스텝 수"를 대체값으로 쓰고(던지지 않는다), 음수·비숫자 reps는 0으로 친다.
- 계수 3·2·10초는 추정값이다(`DURATION_ESTIMATE_SEC` 한 곳). 실측이 쌓이면 중앙값으로 보정할 수 있다.

**표시 — 화면은 규칙을 다시 구현하지 않는다**(엔진이 스냅샷·기록에 실어 내린다).
- 사건마다 `EventDuration { sec, source: "measured" | "estimated" }`(`eventDuration`), 사이클 합계 `DurationTotal { totalSec, measuredCount, estimatedCount }`(`cycleDuration` — 깨진 사건은 재생과 같은 기준으로 뺀다). 스냅샷은 `lastEventDuration`·`duration`을, 지난 사이클 행(`workoutHistory`)은 `duration`을, 📒 운동 기록은 `workoutLog(cycles)`의 `WorkoutLogRow { key, cycleId, cycleNo, event, duration }[]`을 싣는다(계약 `lib/workout-contract.ts`가 타입 재수출).
- 문자열(`components/workout-shared.tsx` 순수 포맷 함수): 실측은 0인 칸을 빼고 초까지(`14분 12초`·`45초`·`0초`·`1시간 5분 12초`), 근사는 분 반올림·최소 1분(`약 13분`·`약 1시간 5분`), 합계는 근사가 하나라도 섞이면 `약 …`이고 전부 실측이면 초까지, 옆에 "실측 n회 · 근사 m회". 사건이 0이면 합계 줄을 숨긴다. 세션 머리 시계는 `12:34`·`1:02:03`.
- 위치: ① 오늘 기록 카드 — "오늘 기록 · Day 5 완료 · 14분 12초"(근사면 안내 한 줄) ② 이번 사이클 누적 — "총 운동 시간" ③ 지난 사이클 목록 — 사이클별 총 시간 ④ 새 접이식 **"📒 운동 기록"** — 날짜·결과·소요시간(실측 / 근사)·끝낸 시각(KST) ⑤ 세션 오버레이 머리 — 실시간 "⏱ 경과 12:34"(1초 틱). 상세는 §19-6.
- 📒 운동 기록의 순서는 엔진이 정한다 — 모든 사이클(닫힌 것 포함)의 쓸 수 있는 사건을 날짜 → 기록 시각(`at`) → cycleNo → cycleId → 배열 위치 **내림차순**(도중 재측정한 날은 닫힌 사이클과 새 사이클에 같은 날 사건이 있을 수 있다). 입력 순서와 무관하게 결정적이다. "끝낸 시각"은 사건의 `at`(서버가 기록 요청을 받은 순간)의 KST `HH:MM`이라, 세션 없이 기록한 날은 그 버튼을 누른 때다.
- 알려진 한계: ① 실측 시작점은 "세션을 **처음 연** 순간"이고 0스텝도 저장하므로, 세션을 잠깐 열어 보기만 해도 시계가 시작된다(예: 18:00에 열어 보고 19:30~19:45에 운동하면 1시간 45분 — 3시간 상한 안이라 걸러지지 않는다). 시작점은 "처음 연 순간"으로 확정됐다(2026-09-26 사용자 결정 — 첫 ✓를 시작점으로 바꾸지 않는다). ② 끝 시각 고정은 오버레이 안에만 있다 — 마지막 ✓ 전송이 실패한 뒤 세션을 닫았다 다시 열면 새 끝 시각이 쓰인다(드문 경로이고 3시간 상한이 최악을 막는다).
- eval(`eval:workout` "10) 총 운동 소요시간" 24항목, 합계 158): 상수·`isValidDurationSec` 경계, 옛 사건 정규화 → `durationSec` null·유효값 보존·범위 밖·소수·문자열 → null, `decideLog`가 값을 싣고 **쓰기 경계 `normalizeWorkoutCycle` 뒤에도 보존**(함정 잠금), 0·10800 보존·10801·음수·12.5·NaN → null(기록은 ok), 소요시간이 거절 규칙을 바꾸지 않음, 근사식(Day 1 710·Day 23 805·스텝 0~9 실패의 휴식 수·결정성·손상 fail), 합계·undo 뒤 합계·`workoutLog` 정렬, 표시 문자열 17건("약" 규칙).

## 20. 아빠의 영어 — 토익스피킹 표현집 + 모의고사 (2026-09)

> AI 호출(A 표현집 판독 · B 발화 포인트 · C 모의고사 문항 C1~C5 · D 답변 피드백)과 하네스 밖 관문 두 개(P 사진 생성 · T 음성 전사)의 프롬프트·JSON Schema·zod·후처리, 저장 모델(컬렉션 5개), 시험 모드·형식표·채점 규칙, 화면·라우트 목록의 상세는 전부 `docs/harness/toeic.md`에 있다. 여기서는 §14처럼 **제품 수준의 흐름과 경계, 비용, 실기기 확인**만 적는다.

### 20-0. 무엇을 위한 것인가

아빠(성인 — 일본어·운동과 같은 사람)가 **토익스피킹**을 준비하는 과목이다. 사용자 요구는 셋이었다(2026-09-25) — ① 문제 유형을 분석한 **모의시험** ② 표현모음집 **사진을 올리면 은우 단어장과 같은 낭독·시험** ③ 가진 교재 10쪽을 **미리 넣기**.

- 목표는 단어 뜻을 아는 것이 아니라 **시험 답변으로 말로 꺼내 쓰는 것**이다("단순 영영의미보다는 발화로 이어질 수 있는 포인트들을 카드에 많이 실어주면 좋겠어"). 그래서 은우 단어장의 "영영 정의 + 이모지" 대신 표현마다 **발화 포인트**(문항별 활용 문장·답변 틀·바꿔 쓰기·발음·함정·이어 말하기)를 붙이고, 시험에 **소리 내어 말하기** 모드를 둔다.
- 이름은 앱에서 **"아빠의 영어"**(부제 "토익스피킹"), 코드·경로는 `toeic`이다 — `english`는 은우 북카드가 이미 쓰고 있고, 언어가 같아도 학습자·눈높이·기록이 전부 다르다(§20-6).
- **표현집**과 **모의고사**는 한 과목 아래 나란히 선 독립 기능이다. 한쪽이 비어도 다른 쪽은 온전히 동작하고, 만나는 곳은 두 군데뿐이다 — 모의고사를 만들 때 표현집의 표현을 "활용할 표현"으로 넘겨 모범답변에 녹이고(§20-3), AI 피드백이 그 목록에서 "넣었으면 좋았을 표현"을 고른다(§20-5).

### 20-1. 진입과 셸

- **홈 `/`**은 5칸이다 — 은우 줄(영어·수학) / 아빠 줄(일본어 · **🎙️ 아빠의 영어 · 토익스피킹**) / 아빠 운동 한 줄(`sm:col-span-2`). 폰(<640px)은 1열 그대로 이 순서다. §19-6의 2×2 설명은 이 배치로 바뀌었다.
- **허브 `/toeic`**은 표현집(`/toeic/sets`)·모의고사(`/toeic/mocks`) 두 장을 고르기만 한다(일본어 허브와 같은 모양). 셸도 일본어 방식이다 — 공통 레이아웃 없이 페이지마다 `u-navbtn` "← 상위" 헤더, 허브는 "← 과목 선택". 은우 영어 셸(`EnglishNav`)을 쓰지 않는다.
- 새 토큰·새 전역 클래스는 없다(`app/globals.css` 무변경). 허브는 `.u-*`·`.t-*`만 쓰고, 목록·카드·시험·학습 보기·응시·결과 화면은 화면별 CSS 모듈(`components/toeic-*.module.css`)을 두되 색·간격은 기존 CSS 변수(토큰)만 쓴다(일본어 화면과 같은 관용구 — 새 색조 없음). PIN 게이트는 `proxy.ts`가 허용목록 밖을 모두 막으므로 `/toeic`·`/api/toeic`에도 자동으로 걸린다.
- 두 목록(표현집·모의고사)은 관리 모드에서 삭제와 순서변경을 한다(§15-1의 공유 프리미티브 `use-reorder` 그대로). 삭제는 딸린 기록까지 함께 지우며 prod-guard 대상이다(§20-6).

### 20-2. 표현집 — 넣기 · 카드 · 전체 듣기 · 시험

**넣는 길은 둘이다.**

- **사진으로 추가**(`/toeic/sets/new`): 교재 페이지 사진 최대 8장 → 자르기·리사이즈(은우 단어장과 같은 사진 파이프) → 사진마다 판독(호출 A, 병렬) → 같은 DAY끼리 묶은 **초안** → 검토·수정 → 묶음마다 저장 → 저장 직후 발화 포인트를 **한 번 자동으로**(best-effort) 만든다. 검토 화면은 판독 오류를 사람이 잡는 자리다 — 표현·뜻·예문·해석·QUIZ를 고칠 수 있고, 잘림·흐림 칩, 빠진 번호, 읽지 못한 사진 수를 사실대로 알리며, 저장이 거부할 것(세트 안 같은 표현, 잘린 항목의 빈 뜻)을 저장 전에 짚는다. 표현을 하나도 읽지 못하면(표현 페이지가 아닌 사진 등) 오류가 아니라 "다시 찍어 주세요" 안내다. 사진 원본은 저장하지 않는다(판독에 쓴 장수만 남는다).
- **파일로 가져오기**(목록의 📂): 사용자가 고른 JSON 파일(`toeic-sets/v1`)을 그대로 서버에 보낸다. AI를 부르지 않고, 같은 `presetKey`가 이미 있으면 건너뛰어 **두 번 눌러도 한 번만** 들어간다. 교재 10쪽 미리 넣기는 이 경로로 한다 — 교재 내용을 저장소에 넣지 않기 위해서다(§20-6).

**카드**(`/toeic/sets/[id]`): 표현 🔊 · 뜻 · 예문 🔊(표현이 쓰인 구간 강조) · 해석, 그 아래 발화 포인트(핵심 한 줄 · 문항 배지 달린 활용 문장 🔊 · 답변 틀 · 바꿔 쓰기 🔊 · 발음 · 함정 · 문법 · 이어 말하기 🔊), 그리고 교재 하단 QUIZ. 발화 포인트는 부수 효과다 — 비어 있어도 카드와 시험(뜻·표현 모드)은 동작하고, "발화 포인트 만들기/다시 만들기" 버튼이 있다. 자동 생성은 **빈 자리만** 채우고 "다시 만들기"를 눌렀을 때만 덮어쓴다(보던 문장이 말없이 바뀌지 않게).

**전체 듣기**: 세트 전체를 순서대로 이어 읽는다(§18의 `speakQueue` — 탭 안에서 시작, 지금 읽는 카드를 강조·스크롤, ■로 멈춤). 모드는 셋 — ① 표현·뜻·예문(기본) ② 활용 문장까지 ③ 영어만(따라 말하기용). 한국어 뜻은 ko-KR(기본 클라우드), 영어는 en-US로 읽는다. 속도·엔진은 은우와 **전역 설정을 공유**한다(§15-2·§16-5).

**시험 네 모드**(`/toeic/sets/[id]/quiz`, AI 없음):

| 모드 | 문제 → 답 |
|---|---|
| 뜻 → 표현 | 한국어 뜻 → 5지선다 표현 |
| 표현 → 뜻 | 표현 → 5지선다 뜻 |
| 빈칸 | 교재 예문에서 표현 구간을 가린 문장 + 예문 해석 → 5지선다(발화 포인트가 있어야 나온다) |
| 말하기 | 우리말 문장 → **소리 내어 영어로 말하고** → "정답 보기"(모범 문장 표시·자동 재생) → "말했어요 ⭕ / 못 했어요 ❌" 자기 채점. 한 번에 최대 10문항, 교재 QUIZ 먼저 |

- 기본은 5지선다 세 모드 혼합이고 말하기는 따로 고른다. 모드 고르기 화면은 모드마다 낼 수 있는 문항 수를 미리 세어 보여 준다(0이면 비활성). 문제를 소리로 읽지 않는다(표현을 읽으면 정답이 샌다) — 답을 고른 뒤 표현을 en-US로 읽는다.
- **숙련도는 모드별로 따로 센다**(연속 2회 정답 졸업, 은우 단어장과 같은 함수) — 뜻은 아는데 말로 못 꺼내는 상태가 흔해서, 말하기 결과가 "안다" 판정을 오염시키면 안 된다. 혼합 세션은 모드마다 따로 저장하고, 일부 저장이 실패하면 "다시 저장"은 **아직 저장되지 않은 모드만** 보낸다(같은 세션이 두 벌 쌓여 거짓 졸업이 나지 않게).
- **오답노트**(`wrong`, 모드 탭 — `?wrong=<mode>`로 그 모드 오답만 다시 풀기)와 **시험 기록**(`history`)은 일본어 골격을 따르되 토익 전용 화면이다(은우 시험 화면은 URL·문구·발음 언어가 박혀 있어 재사용하면 섞인다).

### 20-3. 모의고사 — 만들기 · 학습 보기

- **만들기**(`/toeic/mocks`): 목표 등급 IM3 / **IH(기본)** / AL(모범답변의 길이·수준이 달라진다), 파트(기본 다섯 전부 — 일부만 골라 유형 연습용으로도 만든다), 주제 힌트(표현집 세트 주제 칩 + 직접 입력, 최대 8개 — 안 고르면 AI가 다양하게). 서버가 표현집에서 **활용할 표현을 최대 24개**(숙련도 낮은 것 먼저) 골라 함께 넘기고, 표현집이 비었으면 넘기지 않는다.
- 현행 TOEIC Speaking 11문항 형식(Q1–2 지문 읽기 · Q3–4 사진 묘사 · Q5–7 듣고 답하기 · Q8–10 정보 활용 · Q11 의견)을 **파트 다섯 개 호출로 나눠 병렬**로 만든다. 프로덕션은 Firebase Hosting → Cloud Run 리라이트라 요청 하나가 60초를 넘으면 끊기기 때문이다. 실패한 파트는 비워 두고 학습 보기의 "이 파트 다시 만들기"로 채운다(부분 성공). 고른 파트가 전부 실패할 때만 저장하지 않는다. 다시 만들기는 **빈 파트만** 채운다 — 이미 있는 파트를 덮으면 보던 모범답변·응시 기록이 가리키는 문항이 말없이 바뀐다. 만들기 요청이 도중에 끊기면 목록을 다시 읽고 "서버에서 만들어졌을 수 있어요"라고 알린다(곧장 다시 누르면 한 벌이 더 생길 수 있어서 버튼 이름이 "그래도 다시 만들기"다).
- **문항은 AI가 새로 쓴다** — 실제 기출·ETS 공식 샘플을 옮기지 않는다(저작권은 ETS에 있다). 파트 지시문도 이 앱의 문장이다.
- **Q3–4 사진**: 학습 보기가 처음 열리면 아직 없는(pending) 두 칸을 **자동으로** 한 장씩 병렬 요청한다(사진 한 장 = 요청 하나). 실패한 칸은 버튼("사진 다시 만들기")으로만 다시 만들고, 사진 대신 장면 설명을 보인다. 응답이 60초에 끊겨도 서버는 끝까지 만들어 저장하고, 화면은 실패를 받으면 한 번 다시 읽어 이미 저장됐는지 확인한 뒤에만 실패로 적는다. 먼저 준비된 사진이 이긴다(다시 부르면 새로 만들지 않고 돌려준다).
- **학습 보기**(`/toeic/mocks/[id]`): 파트별 자료·모범답변(활용한 표현 강조)·요령, Q1–2 끊어 읽기·강세·발음 팁, Q8–10 표, Q11 답변 뼈대. 영어는 전부 🔊(en-US), 한국어는 소리로 읽지 않는다. 여기서 **실전 응시**(다섯 파트가 다 있을 때만)와 **유형 연습**(있는 파트 하나)을 시작하고, 응시 기록(끝까지/중단·녹음 수·채점 수·추정 등급)을 본다.

### 20-4. 응시 (`/toeic/mocks/[id]/take`)

- 전면 오버레이(스트릭 헤드라인이 가려지는 게 의도 — §17-4). 형식표(`docs/harness/toeic.md` §6-4)가 단계·시간을 정한다 — 지시문(파트 첫 문항만, 영어로 읽고 한국어 캡션) → Q8 앞 표 읽기 45초 → 질문 음성(Q10은 두 번, Q8–10은 질문 글을 숨기고 표만) → 준비 → "삐—" → 답변 녹음. 시계는 종료 시각 기반이라 백그라운드·스로틀에도 남은 시간이 맞다. 준비부터 답변이 끝날 때까지 메모장(저장 안 함)을, 녹음 중에는 레벨 미터를 보인다.
- **시작 전 마이크 점검(2초)**을 한다 — 권한 창을 사용자 탭 안에서 띄우려는 것이다. 마이크를 못 쓰거나 거부하면 **"녹음 없이 연습"**(타이머만, 채점할 녹음이 남지 않는다)으로 계속한다. 시작 탭 안에서 동기로 오디오 잠금 해제·질문 음성 미리 받기·사진 미리 받기를 한다(iOS의 탭 밖 재생 제약, §18-2).
- **녹음 규칙**: 재생과 마이크 캡처를 시간상 겹치지 않는다(질문 음성·비프가 끝난 뒤에 마이크를 연다). 답변 타이머는 녹음이 실제로 시작된 순간부터 잰다. 마이크가 8초 안에 답하지 않으면 그 문항은 시간만 잰다 — 마이크를 기다리는 곳에는 전부 상한이 있고(답변 8초, 점검 탭은 권한 창에 답할 시간을 주려고 15초), 넘으면 오디오 세션을 재생 쪽으로 되돌리고 늦게 도착한 마이크는 바로 닫는다(세션이 녹음 모드에 갇혀 질문 음성이 수화기로 작게 나지 않게). 녹음 중 화면이 숨겨지면 그 문항은 "중단됨" → "이 문항 다시"/"다음 문항으로". 질문 음성이 끝내 나지 않으면 — 큐가 멈췄거나, 짧은 질문 큐가 끝났는데 **소리를 낸 조각이 모자라면**(클라우드와 기기 음성이 함께 실패한 경우) — 멈추고 "다시 듣기"/"질문 보기"를 띄운다(Q8–10은 평소 질문 글을 숨기므로, 못 들은 질문에 답하게 두지 않는다). Wake Lock은 best-effort다.
- **녹음은 이 기기에만** 남는다(IndexedDB, 최근 응시 5회분). 다른 기기·브라우저에서 결과를 열면 "녹음은 응시한 기기에만 있어요"다.
- 끝·그만두기는 **한 번만** 저장한다 — 이미 닫힌 응시에 다시 오면 409로 거절하고 화면은 성공으로 본다(늦은 요청이 "끝까지"를 "중단"으로 뒤집지 못하게). 응시 중 화면을 떠나면 그만둠으로 닫히고, 녹음된 문항은 그대로 채점할 수 있다. 녹음된 문항이 1개 이상이면 스트릭 영어 트랙에 센다(§17-8).

### 20-5. AI 채점 · 결과 (`/toeic/attempts/[id]`)

- 응시가 끝나도 AI는 돌지 않는다. 결과 화면의 **"AI 채점 받기(n문항)"**를 눌러야 한다 — 대상은 녹음됐고, 이 기기에 녹음이 있고, 아직 점수가 없는 문항이다(동시 2개, 진행 "채점 중… a / b"). 녹음이 이 기기에 없으면 버튼을 막고 이유를 말한다.
- 문항마다: 기기에서 녹음을 16kHz mono WAV로 바꿔(iOS의 `audio/mp4`가 전사에서 형식 오류·잘림을 내는 보고가 있어서 — 실패하면 원본 그대로) 올린다(최대 4MB, 서버는 전사만 하고 저장하지 않는다) → 음성 전사(관문 T — 지문·모범답변을 힌트로 넣지 않는다, 넣으면 전사가 기대 문장 쪽으로 끌려가 점수가 부풀려진다) → 단어가 2개 미만이면 AI 피드백 없이 0점 "답변이 인식되지 않았어요" → **Q1–2**는 지문과 전사문을 대조하는 순수 함수(빠진·바뀐 단어 표시, 참고 점수, "발음·억양은 채점하지 않았어요 — 녹음을 다시 들어 보세요") / **Q3–11**은 AI 피드백(호출 D — 점수, 총평, 잘한 점, 고칠 문장, 빠진 내용, 개선 답변 🔊, 넣었으면 좋았을 표현).
- 피드백이 실패하면 **전사문을 먼저 저장**하고 "다시 채점"을 띄운다 — 다시 누르면 저장된 전사문으로 피드백만 다시 한다(녹음은 응시 뒤 바뀌지 않으니 전사 비용을 두 번 내지 않는다). 이미 점수가 있는 문항은 AI를 부르지 않는다.
- **추정 등급**은 11문항이 모두 채점됐을 때만 "추정(참고용) N / 200 · 등급"으로 보인다(ETS 환산표는 비공개라 참고값이다). 유형 연습은 안내만 한다.
- 문항마다 내 녹음 ▶, 전사문, 모범답변(접힘) 🔊, 그리고 폰에서 판정하기 위한 **진단 줄**(녹음 형식·길이·크기 → WAV 변환 여부 · 전사 상태 — §16-5의 진단 캡션 관용구)이 있다.

### 20-6. 경계

- **은우 기록과 섞지 않는다.** 경로(`/toeic`·`/api/toeic`), 컬렉션 5개(`toeicSets`·`toeicQuizzes`·`toeicMocks`·`toeicImages`·`toeicAttempts`), 스트릭 트랙(§17-8)이 전부 갈린다. 은우 영어 단어장(`vocabBooks`·`vocabQuizzes`)을 같이 쓰면 은우 스트릭·오답노트·기록이 오염된다. 재사용은 순수 함수(보기 만들기·숙련도 집계·연속 판정)와 공용 모듈(사진 파이프·발음·순서변경)까지이고, 은우 화면 컴포넌트는 쓰지 않는다.
- **교재 내용은 공개 저장소 밖에 둔다.** 이 저장소는 PUBLIC이다 — 교재 사진·전사본을 커밋하면 출판물이 공개된다. 교재 10쪽 전사본과 발화 포인트를 합친 가져오기 파일은 `data/private/`(`.gitignore`의 `data/`, `.gcloudignore`가 그것을 물려받아 배포 업로드에서도 빠진다)에만 있고, 앱의 **"파일로 가져오기"가 유일한 반입 경로**다. 프로덕션에 넣는 것은 가족이 앱에서 파일을 고르는 행동이다 — 로컬 스크립트로 프로덕션 DB에 쓰지 않는다(CLAUDE.md 서문). `public/*.json`에 두는 것도 안 된다(정적 확장자는 PIN 게이트 예외라 더 나쁘다). 가져오기 오류 응답에는 경로와 규칙만 싣고 값은 싣지 않는다(교재 원문이 응답·로그에 새지 않게). eval 픽스처는 전부 지어낸 영어이고, 가져오기 파일 검증은 파일이 있을 때만 돈다(공개 저장소·CI 기준은 SKIP).
- 표현집 판독은 §1 "원문 전사 금지"의 예외다(§14-2 단어장과 같은 근거 — 가족이 가진 교재를 학습용으로 옮긴다). 판독에 쓴 사진 원본은 저장하지 않는다.
- **녹음은 서버에 두지 않는다.** 서버에는 전사문·점수·피드백만 남는다(원본 미저장 원칙 §1·§13, Firestore 문서 1MB, 버킷 없음). 채점 업로드는 전사에만 쓰고 버린다.
- **AI가 만든 Q3–4 사진은 "업로드 원본 사진 미저장"(§1·§13)의 대상이 아니다** — 그 규칙은 사용자가 올린 사진에 대한 것이다. 사진 한 장 = `toeicImages` 문서 하나(JPEG data URL 900,000자 이하 — 넘으면 한 번 더 압축, 그래도 넘으면 실패), 모의고사를 지우면 함께 지운다. 화면에는 PIN 게이트 안의 `GET /api/toeic/images/[id]`(확장자 없는 경로, `cache-control: private`)로 내려준다.
- 삭제는 연쇄다 — 표현집 세트를 지우면 그 세트의 시험 세션이, 모의고사를 지우면 생성 사진·응시 기록이 함께 지워진다. 가족 실데이터를 되돌릴 수 없게 지우는 작업이라 prod-guard 대상이다(`deleteToeicSet`·`deleteToeicMock` — Firestore 백엔드에서 개발 환경이면 던진다).

### 20-7. 비용 경로

**AI 채점은 버튼을 눌러야 돈다**는 것이 이 과목의 비용 원칙이다(비용이 드는 경로를 자동으로 태우지 않는다). 다만 아래 "자동" 칸은 화면을 열거나 저장하는 순간 돈다.

| 행동 | 드는 것 | 언제 |
|---|---|---|
| 사진 판독 | 호출 A 사진 1장당 1회(검증 실패 시 재요청 1회) | 버튼 |
| 발화 포인트 | 호출 B 표현 7개당 1회 | 저장 직후 **자동 1회**(best-effort) + "다시 만들기" 버튼 |
| 파일 가져오기 · 표현 시험 · 오답노트 · 기록 | AI 0(발음 요금만) | 🔊 탭. 표현 시험은 시작하면 답 뒤에 읽을 표현(말하기는 모범 문장)을 en-US로 **자동 프리페치** |
| 카드 🔊 · 전체 듣기 | 클라우드 TTS(en-US, 한국어 뜻은 ko-KR) — 영속 캐시(§16-5) | 상세를 열면 en-US **자동 프리페치**(최대 90조각) |
| 모의고사 만들기 | 호출 C 파트당 1회(최대 5, 재요청 포함 최대 10) | 버튼 |
| 학습 보기 첫 열람 | 관문 P 사진 2장 + en-US TTS 프리페치 | **자동**(pending 칸만 — 실패 칸은 버튼) |
| 파트 다시 만들기 · 사진 다시 만들기 | 호출 C 1~2회 · 관문 P 1장(크기 초과면 한 번 더 압축해 1장 더) | 버튼 |
| 응시 | AI 0(지시문·질문 TTS 프리페치 — 실전 약 20~25조각) | 시작 탭 |
| AI 채점 | 문항당 전사 1회 + 호출 D 1회(재요청 시 2). Q1–2·무응답은 전사만. 실전 11문항 = 전사 11 + 호출 D 최대 9. 결과 화면을 열면 모범답변·개선 답변 en-US 프리페치 | **버튼**(이미 채점된 문항은 0) |

- 키(`OPENAI_API_KEY`)가 없으면 판독·발화 포인트·만들기·사진·채점 라우트가 **AI보다 먼저** 501로 안내하고(이미 준비된 사진·이미 채점된 문항은 키 없이도 돌려준다), 발음은 기기 음성으로 폴백한다 — 키를 비운 로컬에서 실호출이 구조적으로 불가능하다.
- 모델: 호출 A~D는 `OPENAI_MODEL`, 사진은 `OPENAI_IMAGE_MODEL`·`OPENAI_IMAGE_QUALITY`, 전사는 `OPENAI_TRANSCRIBE_MODEL`(§11, 빈 값이면 기본값).

### 20-8. 실기기 확인 항목 (아빠 iPhone Safari)

헤드리스 e2e(가짜 마이크 스트림·루프백 스텁)와 오프라인 eval로 흐름은 잠갔지만, 아래는 **실기기에서만** 판정된다. 마이크는 https에서만 열리므로 배포본(또는 `next dev --experimental-https`)에서 본다 — LAN http에서는 열리지 않는다.

1. 녹음 직후 다음 질문 음성이 **스피커에서 정상 볼륨**으로 나는가(오디오 세션 play-and-record → playback 전환 뒤 수화기로 가거나 작아지지 않는가).
2. **무음 스위치 ON**에서 비프가 나는가(운동 세션 비프와 비교).
3. 답변마다 마이크를 다시 잡을 때 **권한 창이 다시 뜨는가**, 탭 밖(타이머 콜백) 호출이 허용되는가 — 안 되면 8초 감시가 "시간만 재기"로 넘긴다(진단 줄·끝 화면 "녹음 실패"로 판정).
4. 실제 녹음 형식(`audio/mp4` 기대)과 WAV 변환 성공 여부, 변환 길이 ≈ 녹음 길이.
5. 전사가 **끝까지** 나오는가(앞뒤 1~3단어 잘림) — 필요하면 원본 mp4 업로드와 비교.
6. Wake Lock이 응시 20분 동안 유지되는가(Safari 탭 / 홈 화면 앱).
7. 녹음 중 화면 잠금·앱 전환 → "중단됨" → "이 문항 다시"와 시계 보정.
8. 녹음을 거친 뒤에도 질문 음성이 탭 밖에서 계속 재생되는가, AirPods 연결 시 입출력 경로.
9. 결과 화면에서 내 녹음 다시 듣기와 IndexedDB 보관(프라이빗 모드면 메모리뿐이라 새로고침하면 사라진다).
10. 표현집: 전체 듣기의 실제 소리(한국어 클라우드 ↔ 영어 조각 이음), 말하기 "정답 보기" 자동 재생, 오답노트 🔊, 관리 모드 터치 드래그. 모의고사 학습 보기: 긴 모범답변 이어 읽기, 사진 로딩, 폼 한글 입력.

실호출 첫 확인(사용자 동의 후 1회로 묶는다 — docs/HARNESS.md §4): 사진 한 장의 소요 시간·크기(900,000자 안)·거부 빈도, 전사 지연(채점 요청 60초 상한), 호출 C·D 출력이 zod 폭 안에 드는지. Firestore 경로(트랜잭션 안 판정·사진 문서 커밋 크기)는 에뮬레이터가 없어 타입 검사와 가짜 DB까지만 확인했다.

### 20-9. 알려진 한계 · eval

## 21. 은우 자유대화 — AI 전화영어 선생님 (2026-09)

> AI 호출·프롬프트 원문·스키마·세션 설정은 `docs/harness/english.md` §12. 여기에는 제품 수준의 흐름·경계·비용·실기기 확인만 적는다.

### 21-0. 무엇을 위한 것인가

사용자 요청(요지): 은우 영어에 "자유대화"를 더한다. AI가 **전화영어 선생님**처럼 대화를 이끌고, 대화 중 AI가 말한 영어와 은우가 말한 내용을 **화자별로 실시간 스크립트**로 보여 준다. 시작 전에 **주제**를 고르거나 **단어장 하나**를 고르고, 그것을 기초로 선생님이 대화를 이끈다. 대화가 끝나면 **문장 하나씩 골라** 선생님이 대화하듯 설명해 준다. 모든 기능은 **초등학교 1학년** 눈높이에서 유연하고 쉽게, 가정교사처럼 친근하게.

### 21-2. 흐름

1. **시작 화면 `/english/talk`**(영어 셸 메뉴 `💬 자유대화`, 영어 허브 `/english`의 셋째 카드 — 한 줄 전체) — 주제 칩(프리셋 10개, `lib/talk-topics.ts` 단일 정의) 또는 직접 입력(30자), **또는** 단어장 하나 선택("모은 단어" 포함 — 화면에는 id·이름·DAY·단어 수만 내리고 단어 목록은 서버가 id로 읽는다). 선생님 말 빠르기(천천히(기본) · 보통). 안내: "어른과 함께 해요 · 이름·학교·주소는 말하지 않아요 · 이어폰이 있으면 더 잘 들려요". 아래에 지난 대화 목록(관리 모드: ✏️ 이름 바꾸기·🗑 삭제(인라인 확인, 그림 연쇄)·드래그·↑↓ 순서변경 — §15-1 `use-reorder`).
2. **📞 대화 시작** 탭 → **탭 핸들러 안에서 동기로**(첫 await 전에) 발음 큐 정지 → `unlockSpeechPlayback()`(대화 뒤 설명 낭독이 탭 밖에서도 나게) → 선생님 소리 재생 준비 → 마이크 획득(`lib/mic-session.ts` `acquireMicStream` — 첫 권한 창을 생각해 대기 상한 15초) → **마이크를 얻은 뒤** 연결(`/connect`)과 주제 일러스트(`/scene`, §21-7)를 병렬로 부른다. 서버가 고른 주제/단어로 선생님 지시문을 만들어 OpenAI에 연결하고, 데이터 채널이 열리면 선생님(Sunny)이 먼저 인사한다(앱이 넣는 숨은 안내 + 응답 요청 — `docs/harness/english.md` §12-1). 마이크를 거부하면 안내를 보이고 연결·그림 생성 요청이 아예 나가지 않는다. 연결이 실패하면 안내를 보이고 저장하지 않으며, 진행 중인 그림 요청도 끊는다.
3. **대화 화면**(전면 오버레이 — z 20·스크롤 잠금·Wake Lock) — 위쪽에 주제 일러스트·그림 카드(§21-7)와 단어장 모드의 "📓 오늘의 단어" 접이식 목록, 가운데 실시간 스크립트: 선생님 말풍선 왼쪽("Sunny 선생님"), 은우 말풍선 오른쪽("은우"). 선생님 글자는 말하는 대로 이어 붙고, 은우 줄은 말을 시작하면 "듣는 중…"으로 먼저 자리를 잡은 뒤 글자가 채워진다(늦게 온 전사도 그 자리에). 끼어들어 끊긴 선생님 말은 "끊김", 전사 실패는 "잘 안 들렸어요", 안전 필터로 잘린 말은 흐리게. 아래에 도움 카드·🙋 도와줘요·남은 시간·"끝내기". 상태: 연결 중 · 선생님이 생각하는 중… · 선생님이 말하는 중 · 은우가 말하는 중 · 은우 차례예요 · 마무리하는 중 · 은우 말을 받아 적는 중…(끝내기 직후 — 4). 작은 폰(375×548급)에서도 스크립트와 끝내기가 보이게, 도움 카드가 뜨면 "오늘의 단어" 목록을 자동으로 접는다(다시 펼치는 것은 사용자).
4. **5분**이 되면 선생님이 칭찬 한마디와 작별 인사를 하고 끝낸다 — 선생님이 말하는 중이면 최대 8초 기다렸다가 마무리 안내를 넣고, 그 응답의 소리가 멈추면(또는 오디오 없이 끝나면, 늦어도 25초 안에) 끝낸다. 언제든 "끝내기"로 먼저 끝낼 수 있다. **끝내기 버튼과 5분 마무리 뒤 종료는 아직 전사 중인 은우 말을 최대 2.5초 기다린다** — 은우 줄이 "듣는 중…"이거나 글자가 오는 중이면 바로 닫지 않고 "은우 말을 받아 적는 중…"(끝내기 버튼 잠김)으로 그 전사를 기다렸다가 닫고 저장한다(말을 마치자마자 끝내기를 눌러도 마지막 말이 남게). 그동안 마이크 입력을 끄고, 서버의 말 차례 감지를 꺼 새 응답이 생기지 않게 하며(은우가 말하는 중이었으면 그때까지의 소리를 넘겨 받아 적게 한다), 선생님 소리는 멈추고 진행 중 응답은 취소한다 — 상세는 `lib/talk-realtime.ts` `finish`. 기다릴 은우 줄이 없으면 바로 끝낸다. **화면이 숨겨지면**(잠금·앱 전환) 즉시 끝낸다(과금 중지, 스크립트 보존). **대화 중 뒤로가기**(iPhone 가장자리 스와이프·안드로이드 뒤로)로 대화 화면이 사라져도 끝낸다 — 연결 닫기 → 마이크 놓기(트랙 stop → 오디오 세션 playback) → 서버 hangup, 그리고 저장을 한 번 보낸다(개발 모드 StrictMode의 "정리 → 재실행" 흉내에는 끝내지 않게 한 틱 미룬다).
5. 끝나면 스크립트를 저장한다. **은우가 한마디도 안 했으면 저장하지 않는다**("다음엔 한마디 해 볼까요?" — 선생님이 한마디도 하기 전에 끝났으면(연결 중 끝내기·첫 인사 전 끊김) "연결되기 전에 끝났어요 — 다시 시작해 볼까요?", 연결 자체가 실패했으면 "대화를 시작하지 못했어요" + 그 이유). 저장은 **멱등**이다 — 대화 한 번에 화면이 저장 키(`clientSessionId`, UUID) 하나를 만들고 서버가 그 값을 대화 문서 id로 쓰므로, 응답이 유실돼 "다시 저장"·화면 복귀 자동 재시도·뒤로가기 정리가 겹쳐도 대화는 하나다. 본문이 keepalive 한도(브라우저 64KiB 아래로 잡은 계약 상수 `TALK_SAVE_KEEPALIVE_MAX_BYTES` — **UTF-8 바이트로 잰다**, 한글 한 글자는 3바이트라 글자 수로 재면 한도를 넘긴 본문이 keepalive로 나가 곧바로 거부된다) 안이면 `keepalive`로 보내 숨김 중에도 끝까지 가게 하고, 문서가 내려가는 중(`pagehide`)인데 본문이 그보다 크면 **그림을 뺀 본문**으로 보낸다(그림보다 대화가 남아야 한다 — 이 경로로 저장된 대화에는 그림이 없다). 모든 저장 경로가 판정 함수 하나(`planTalkSaveBody`, `lib/talk-contract.ts`)를 지난다. keepalive 요청이 거부되면(TypeError) 문서가 내려가는 중이 아닐 때만 keepalive 없이 한 번 더 보낸다(멱등이라 중복 없음). 저장 실패면 "다시 저장" 버튼 + 화면 복귀 때 1회 자동 재시도. 성공하면 은우 스트릭을 즉시 갱신한다(§17-9). 결과 패널에는 끝난 사유(화면이 꺼져서·연결이 끊겨서 등)와 "대화 보기 →", 접이식 "진단"(응답 수·토큰 — §21-4)이 있다.
6. **대화 보기 `/english/talk/[id]`** — 주제 일러스트(있으면)·"오늘 본 그림 카드"·스크립트 말풍선을 보여 주고, **문장 하나를 탭하면** 선생님 설명 시트가 열린다: 선생님 말투의 설명(한국어 + 영어가 섞인 말풍선)을 **자동으로 읽어 주고**(🔊 다시 듣기, 읽는 조각 강조), 은우 문장이면 "더 멋진 문장"을, 짚은 단어가 있으면 그 뜻을 함께 보인다. 문장은 서버가 저장된 대화에서 번호로 꺼낸다(화면은 번호만 보낸다). 설명은 한 번 만들면 대화 기록에 저장돼(설명이 있는 문장엔 💬 표시) 다시 탭해도, 새로고침 뒤에도 AI를 부르지 않는다. 제목 편집·삭제(그림 연쇄)도 여기서 한다.

### 21-3. 경계

- 저장: 새 컬렉션 `talkSessions`(스크립트·주제·단어 스냅샷·설명·보인 그림 카드)와 `talkImages`(주제 일러스트 한 장 = 문서 하나 — Firestore 문서 1MB 때문에 대화 문서와 분리). 둘은 한 원자 단위로 함께 만들고 함께 지운다(파일 백엔드 `mutate` 하나, Firestore `batch`). 은우 단어장 컬렉션(`vocabBooks`·`vocabQuizzes`)과 섞지 않는다. 음성·녹음은 저장하지 않는다. 저장하지 않는 대화(은우 발화 0)의 그림은 서버에 남지 않는다.
- 삭제는 prod-guard 대상이다(`DestructiveOp` `deleteTalkSession` 하나가 그림 연쇄까지 — 개발 환경에서 Firestore를 지우려 하면 라우트가 403 `prod_guard`). 이름 바꾸기·순서변경·설명 추가는 수정이라 가드 밖이다. `scripts/migrate-to-firestore.ts`에는 넣지 않는다(프로덕션에서만 생기는 기록).
- 선생님 지시문(§12-1): 개인정보(이름·학교·주소·전화번호·사진·위치)를 묻지 않고 되풀이하지 않는다, 무섭거나 슬픈 이야기는 "엄마·아빠께 말해 보자", 물으면 AI 선생님이라고 솔직히 말한다. 지시문은 "보장되지 않는다"(모델 문서) — **어른 동반이 전제**다. 아이 이름은 AI에 보내지 않는다(화면의 "은우" 라벨은 로컬 표시다).
- 키 노출 없음: 브라우저의 SDP offer → 앱 서버(PIN 게이트 안, `/api/english/talk/connect`) → 서버가 표준 키로 OpenAI `/v1/realtime/calls`에 연결(통합 인터페이스, `lib/talk-gateway.ts`). 브라우저에는 SDP answer·callId·서버가 해석한 주제 스냅샷·모델·음성만 간다. 지시문도 서버가 조립한다(클라이언트는 주제 키·직접 입력 글자·단어장 id만 보낸다). 앱이 대화 중 넣는 짧은 안내(인사·마무리·도움 요청)는 서버 컴포넌트가 props로, 일러스트 안내는 장면 라우트가 조립해 내린다 — 선생님 지시문·호출 I 프롬프트는 폰 번들에 싣지 않는다.
- 끝낼 때 서버 hangup을 한 번 더 부른다(`/api/english/talk/hangup` — 탭이 닫혀도 가게 `sendBeacon`, 안 되면 `fetch` keepalive) — 과금 이중 안전장치. 연결 응답에서 callId(`Location` 헤더)를 못 읽으면 대화는 살리고 이 이중 장치만 빠진다.
- 키가 없으면 연결·일러스트·hangup 라우트가 OpenAI를 부르지 않고 501이다. 저장은 AI를 부르지 않아 키 검사가 없고, 이미 저장된 설명은 키 없이도 다시 볼 수 있다(새 문장 설명만 501).
- 개발 빌드 전용 **가짜 전송**(localStorage `talk-debug-fake`)과 **시간 배율**(`talk-debug-timescale`, 0.01~1 — 5분·8초·25초·5초·12초를 곱한다)이 있다. production에서는 localStorage를 읽기 전에 꺼지고 가짜 전송 모듈은 번들에 실리지 않는다. ⚠️ 가짜 전송도 `/connect`·`/scene`은 실제로 부르므로, **실제 키가 있는 dev 서버에서 켜면** 통화 생성 요청 1회(미디어·응답 없음, 끝낼 때 hangup)와 일러스트 1장(약 1센트)이 생긴다 — 로컬 e2e는 루프백 스텁으로 돌린다.
- 이 과목의 AI 음성(Realtime)은 발음 단일 관문(`lib/speech.ts`)을 거치지 않는 **별도 재생 경로**다. 대화 후 설명 낭독은 기존 클라우드 TTS(`speakQueue`)를 쓴다 — 목소리가 다르다(선생님 marin, 설명 낭독은 앱 공통 alloy). 알려진 한계.

### 21-4. 비용 경로

- 대화 1회(최대 5분, `gpt-realtime-2.1`): 대략 $0.3~2 — 매 응답이 대화 전체를 다시 입력으로 과금하므로 뒤 턴일수록 비싸고, 캐시 적중에 따라 폭이 크다. 은우 발화 전사는 분당 약 $0.003. 실측은 응답마다 오는 사용량(`response.done.usage`)을 서버 로그 없이 화면 진단에서 볼 수 있게 한다(§12).
- 대화 1회에 주제 일러스트 1장(품질 low, 약 1센트 — §21-7)이 더해진다. 마이크를 얻은 뒤에만 요청하므로 마이크 거부·대화 전 끝내기에는 생성 요청이 나가지 않고, 대화가 그림보다 먼저 끝나면 요청을 끊는다(그림 없이 저장).
- 대화 안에서 앱이 선생님 응답을 더 부르는 경로 두 가지에는 상한이 있다 — 도구를 부르고 질문 없이 끝난 응답 뒤의 이어 말하기는 **연속 2회**까지(은우 발화로만 0으로 — 소리 있는 응답으로는 되돌리지 않는다, §21-7), 12초 도움 요청은 **선생님 차례 하나에 한 번**이고, 은우가 말하기 전까지 **연속 2번**(🙋 요청 합산 — 은우가 말을 시작하면 다시 센다, `docs/harness/english.md` §12-6). 상한 전에는 은우가 계속 조용하면 선생님 차례마다 요청이 되풀이됐다(가짜 전송 e2e — 시간 배율 0.2로 5분 상한을 60초로 줄인 대화 — 에서 선생님 차례 18회에 도움 요청 12회). 상한에 닿으면 도움 카드는 그대로 뜨고 요청만 멈춘다.
- 문장 설명 1회(호출 I): 1센트 미만 + 설명 낭독(클라우드 TTS). 같은 문장은 저장된 설명을 쓰므로 한 번만 과금된다(동시에 두 번 탭하면 AI는 두 번 불릴 수 있지만 저장은 한 건).
- **자동으로 도는 비용은 없다** — 대화는 📞 탭, 설명은 문장 탭으로만 시작한다. 대화 보기는 설명·낭독을 미리 받아 두지 않는다(프리페치 없음).

### 21-5. 실기기 확인 (배포본 · iPhone Safari)

1. 선생님 목소리가 **스피커로 정상 음량**인가(수화기로 가지 않는가). 대화 내내 마이크가 열려 있어 TOEIC 녹음(재생과 녹음을 겹치지 않음)보다 위험이 크다 — 안 되면 이어폰.
2. 선생님 목소리가 은우 발화로 잡혀 스스로 끼어들지 않는가(스피커 최대 음량).
3. 은우의 긴 쉼·"음…"에서 선생님이 성급히 끼어들지 않는가(semantic VAD, eagerness low).
4. 한국어가 섞인 발화의 전사.
5. 은우 글자가 늦게 도착해도 스크립트 **순서**가 맞는가.
6. 화면 잠금·앱 전환 → 종료·저장. 그림이 실린 본문은 대개 keepalive 한도를 넘어 일반 요청으로 나가므로 숨김 중에 끝까지 못 갈 수 있다 — 화면 복귀 때 자동 재시도(멱등)로 저장되는지. 실제 일러스트의 base64 크기도 여기서 본다.
7. 끝난 뒤 설명 낭독이 스피커로 나오는가(오디오 세션 playback 복귀).
8. 5분 상한에서 칭찬·작별 인사 후 종료.
9. 대화 중 가장자리 스와이프 뒤로가기가 어느 경로로 처리되는가 — Next 클라이언트 내비게이션(언마운트 정리)인지, bfcache 동결(`pagehide`)인지. 헤드리스로는 두 경로 모두 "끝내기 + 저장"을 확인했다.
10. 도움 카드·그림 카드가 390px 폰에서 스크립트를 너무 가리지 않는지, 📞 탭 안의 재생 준비로 선생님 첫 소리가 나는지, 대화 중 화면이 꺼지지 않는지(Wake Lock).
11. 은우가 말을 마치자마자(또는 말하는 도중에) "끝내기"를 눌러도 그 마지막 말이 저장되는지, 기다리는 2.5초 동안 선생님이 새로 말하지 않는지(말 차례 감지 끄기·말하던 소리 넘기기의 실제 동작 — §21-2 4).

### 21-6. eval

- `eval:english`(오프라인 — 2026-09-26 기준 484항목 중 자유대화 308항목): 선생님 지시문·수업 블록·인사·마무리·화면 카드 덧붙임·도움 요청·일러스트 안내·사진 프롬프트와 호출 I 프롬프트·사용자 템플릿 11개의 spec-sync(조립 없이 블록 하나와 정확히 일치하는 `block-exact`), 호출 I JSON Schema·도구 정의의 의미 동치, 스펙 문장 속 숫자(zod 폭·5초·12초·30장·6장 등)와 코드 상수 대조, 지시문 조립(프리셋·직접 입력 정리·단어장 단어 상한), 세션 설정(env 빈 값 폴백·속도·도구), **스크립트 리듀서**(합성 이벤트 — 늦게 온 은우 전사의 자리, 끊긴 응답, 빈 전사·실패 전사, 앱이 넣은 숨은 항목·도구 호출 항목 제외), 문장 나누기, 호출 I zod 반례(한국어 조각의 영어 글자·keyWords가 문장 밖이거나 한글·선생님 문장에 betterEn), 도구 호출 검사·도움 상태 기계(은우 발화 전 연속 2번 상한 포함)·주제 장면·단어장 ✓ 매칭, 저장 본문 계획(`planTalkSaveBody` — keepalive 바이트 판정·떠날 때 그림 빼기), 설명 낭독 대본, 스트릭 변환. 호출 I 실호출은 게이트 `EVAL_TALK=1`(2회)일 때만 — 사용자 동의 후.
- `eval:streak`: §17-9(자유대화 6항목, 합계 53).
- 실제 연결(WebRTC·음성)은 오프라인으로 검증할 수 없다. 화면 흐름은 **개발 빌드 전용 가짜 전송**(`lib/talk-fake-transport.ts` — 합성 이벤트를 흘려보내는 대역, 이벤트마다 고유 `event_id`. 프로덕션 번들에서는 동작하지 않는다, §21-3)과 가짜 마이크로 e2e를 돌리고(루프백 OpenAI 스텁 — 실호출 0), 실제 연결은 사용자 동의 후 실호출·실기기로 확인한다. 2026-09-26 QA 2회차가 뒤로가기 네 시점·저장 재시도 여섯 경로·작은 폰(375×548)·마이크 거부·키 없는 production을 실행으로 확인했다(배포 가능 판정). 같은 날 3회차가 그 회차의 수정 셋을, 4회차가 도움 요청 연속 상한·끝내기 전 전사 기다림(숨김·뒤로가기는 즉시)·연결 전 끝내기 문구를 다시 실행으로 확인했다(둘 다 배포 가능). 끝내기 전 기다림은 컨트롤러 동작이라 오프라인 eval이 아니라 가짜 전송 e2e로만 본다.

### 21-7. 화면 카드 — 말문 막힘 도움 · 그림 카드 · 주제 일러스트 (2026-09-26 추가)

사용자 요청: "은우가 말문이 막히면 화면에 표현이나 단어를 표시해서 자연스러운 발화를 유도하자. 대화하는 동안 관련 내용을 설명하는 그림이나 사진, 문서 등을 화면에 띄우자." 사용자 확정: **그림 카드(이모지) + 주제 일러스트 1장**, 도움 카드는 **5초 조용하면 자동 + 🙋 버튼**. 상세는 `docs/harness/english.md` §12-6.

- **말문 막힘 도움 카드**: 선생님이 질문할 때마다 "이렇게 말해 볼 수 있어요" 답 예시 2~3개와 핵심 단어(이모지·영어·뜻)를 화면용으로 함께 준비한다(도구 호출). 선생님 말이 끝나고 은우가 **5초** 조용하면 살짝 띄우고("이렇게 말해 볼까요?"), 말을 시작하면 접는다. 은우가 말하다 멈춰도("음…") 조용함을 다시 재므로 말하다 막힌 경우에도 뜬다. 받은 도움이 없으면 기본 문구(Yes! · No. · I don't know. · Can you say it again?)를 보인다. **🙋 도와줘요**를 누르면 바로 띄운다. **12초** 넘게 조용하면(또는 🙋) 앱이 선생님에게 "짧은 답 예시를 말해 주고 같이 말해 보자고 해 주세요"라고 한 번 청한다 — 아이가 아무 말도 안 하면 선생님이 끝없이 기다리는 문제를 막는다. 선생님이 말하는 중에 🙋를 누르면 카드는 바로 띄우고 요청은 선생님 소리가 멈춘 뒤에 보내며, 선생님이 아직 한 번도 말하지 않았으면(연결 중) 카드만 띄운다. 선생님 응답이 만들어지는 중에는 요청을 보내지 않고 기다린다(한 번에 한 응답만 대화에 쓸 수 있다). 마무리(5분)가 시작되면 카드도 요청도 없다.
- **그림 카드**: 선생님이 사물·동물·음식·색·동작을 말하면 이모지 그림 카드(영어 + 뜻)를 띄운다(무료·즉시) — 큰 카드 1장 + 지난 카드는 작은 칩으로 최근 6장, 대화 기록에는 보인 카드 최대 30장. 단어장 모드에서는 **"오늘의 단어" 목록**(문서)을 곁에 두고 연습한 단어에 ✓를 단다(대소문자·관사·복수형 s/es/ies를 같은 단어로 본다).
- **주제 일러스트 1장**: 대화를 시작하면 주제 장면 그림을 AI로 한 장 만든다(마이크를 얻은 뒤 연결과 병렬, 품질 low·1024×1024 — 약 1센트, 보통 수십 초 안에 도착. 토익 모의고사 사진과 같은 사진 생성 공용 코어 `lib/image-gen.ts`). 기다리는 동안 "그림을 그리는 중…". 대화 중(마무리 전)에 도착하면 화면에 띄우고 선생님에게 알려 "What do you see?" 같은 질문에 쓰게 한다. **마무리 중에 도착하면 띄우지도 알리지도 않고 저장에만 싣는다**(곧 끝날 대화에 새 그림을 올리지 않는다). 실패하면 칸을 숨기고 대화는 그대로 간다. 대화 기록에 저장돼 대화 보기에서 다시 본다(`/api/english/talk/images/[id]`, PIN 게이트 안).
- **질문 없이 끝난 차례는 이어 말하게 한다**(2026-09-26 실연결 정정): 선생님이 한두 마디 하다("Let me think of a small next question…") 도구를 부르고 질문 없이 응답을 끝내면 은우는 질문을 못 듣고 기다리게 된다. 지시문에 "말(질문 포함)을 다 한 뒤에 도구를 부르고, 생각한다는 말은 하지 않는다"를 넣고, 앱은 도구를 부른 응답에서 선생님이 말한 글자에 `?`가 없으면(소리 없이 도구만 부른 응답 포함) 선생님에게 이어 말하게 한다 — 질문이 있었으면 은우 차례라 기다린다. 이어 말하기는 은우가 말하기 전까지 **연속 2회**까지다(§21-4, `docs/harness/english.md` §12-6).
- **모델 출력은 믿지 않는다**: 도구 인자는 화면에 띄우기 전에 순수 함수(`lib/talk-cards.ts`)로 검사해 잘못된 항목만 버린다(한글 섞인 답 예시, 그림 문자가 없는 이모지 칸 등). 저장 때 서버가 카드를 한 번 더 검사하고, 장면 문장은 클라이언트 값을 쓰지 않고 저장된 주제에서 다시 만든다.
- **소리를 내지 않는다**: 카드에는 🔊가 없다. 대화 중에는 마이크가 계속 열려 있어 앱이 소리를 내면 선생님이 그 소리를 은우 말로 들을 수 있다.
- 비용: 대화 1회에 주제 일러스트 1장이 더해진다. 도구 호출은 텍스트 토큰이라 비용 변화가 작다.

### 21-8. 알려진 한계 (2026-09-26 QA 기준)

QA 2회차(2026-09-26)는 배포 가능으로 판정했다(P0·P1 0). 그 회차가 남긴 P2 셋은 같은 날 고쳤다 — ① 저장 keepalive를 글자 수가 아니라 **바이트**로 판정(§21-2 5, 한글이 섞인 6만 글자 미만 본문이 64KiB를 넘어 모든 재시도가 거부되던 것) ② 이모지 칸이 ▲ ● ■ ◆ 같은 **도형 기호**만 준 카드를 버리던 것("색깔과 모양" 프리셋 — 도형·기호 블록을 그림으로 인정, `docs/harness/english.md` §12-6) ③ "카드가 떠 있는 중 선생님 재개 → 접힘"의 eval 잠금. 같은 날 사용자 결정 셋도 반영했다 — ④ 이모지 칸 규칙 확정(그림 문자 필수 — 이모지·국기·키캡·도형 기호 블록, 라틴·한글 금지, Ⓐ·㉠ 같은 글자형 기호 거부 — `docs/harness/english.md` §12-6) ⑤ 호출 I [말투] 예시를 라틴 글자 없는 문장으로 교체(ko 조각 규칙과 부딪혀 재요청이 나던 것) ⑥ 12초 도움 요청에 은우 발화 전 **연속 2번** 상한(§21-4). ①~③은 QA 3회차가, ④~⑥은 4회차가 다시 실행으로 확인했다(`_workspace/qa_report_english_talk_3.md`·`_4.md`, 둘 다 배포 가능). 아래는 그 뒤에도 남은 한계다 — 처음 두 항목(끝낼 때 전사 기다림 2.5초·연결 전 끝내기 문구)은 2026-09-26 확정된 동작이고(QA 4회차 재검증), 나머지는 코드가 이미 이렇게 동작한다는 기록이지 의도한 규칙이 아니다.

- 끝낼 때 아직 전사 중인 은우 발화: 끝내기 버튼·5분 마무리 뒤 종료는 그 전사를 **최대 2.5초** 기다렸다가 닫고 저장한다(§21-2 4). 2.5초 안에 오지 않은 전사와, 화면 숨김·뒤로가기·`pagehide`로 즉시 끝난 대화의 전사 중 발화는 여전히 저장에서 빠진다(끝난 뒤 화면에는 "듣는 중…" 줄을 그리지 않는다). 기다리는 동안의 말 차례 감지 끄기·말하던 소리 넘기기는 가짜 전송으로만 확인했다 — 실제 연결에서 마지막 말이 남는지는 실기기로 본다(§21-5 11).
- 연결되기 전에 끝나면(연결 중 끝내기·선생님 첫 인사 전 끊김) 결과 패널은 "연결되기 전에 끝났어요 — 다시 시작해 볼까요?"를 보인다(선생님이 한마디라도 했고 은우가 말하지 않았을 때만 "다음엔 한마디 해 볼까요?"). 연결 실패는 이전처럼 "대화를 시작하지 못했어요" + 그 이유다.
- 연결 중에 뒤로가기를 했는데 연결 응답이 끊기 직전에 도착한 좁은 창에서는, 받은 callId로 서버 hangup을 보내지 않는다(연결만 닫는다). 미디어가 붙지 않은 통화라 과금 영향은 작다고 본다.
- 삭제한 대화에 같은 저장 키의 늦은 재저장이 도착하면 대화가 다시 생긴다 — 재시도는 대화 화면에서만 나가므로 현실 경로는 거의 없다.
- 설명 낭독 목소리(alloy)가 선생님 목소리(marin)와 다른 것은 그대로다(§21-3).
- Firestore 백엔드의 저장 멱등(`batch.create` → ALREADY_EXISTS → 같은 시작 시각이면 기존 대화 반환, 아니면 새 id)과 설명 추가 트랜잭션은 코드·타입으로만 대조했다 — 프로덕션 DB에서는 실행해 보지 않았다.
