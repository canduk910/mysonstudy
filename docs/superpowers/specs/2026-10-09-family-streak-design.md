# 가족 스트릭 강화 — 설계 (2026-10-09)

> 상태: 설계 승인(대화) → 이 문서 검토 대기. 구현 계획은 이 문서 승인 뒤 따로 쓴다.
> 상위 작업: ① 가족 스트릭 강화 → ② 엄마의 생활영어(별도 스펙). 엄마 트랙은 ①의 규칙 위에서 시작한다.
> 관련 스펙: `docs/SPEC.md` §17(학습 스트릭 — §17-10 어학 트랙까지), §23-9(오늘의 복습 스트릭).

## 0. 목적과 성공 기준

사용자 요청(2026-10-09): **"세 가족 모두 미루지 못하게 스트릭을 강화해 줘."** 학습자는 은우(1학년)·아빠·엄마 셋이다.

성공 기준:
- 🔥가 "한 문제 찍고 나가기"로는 켜지지 않는다 — 그날 **한 판을 끝까지** 해야 켜진다.
- 세 사람이 서로의 오늘 상태를 보고 챙긴다 — **가족 연속일**과 **가족 보드**.
- 엄격하지만 지킬 수 있다 — 아픈 날을 위한 **🧊 쉬는 날 카드**와 하루 늦은 **🔁 만회**.
- 잊지 않는다 — 각자 폰으로 **알림**(오늘 아직·마지막·만회 기회·가족·콕 찌르기).
- 지금 이어지고 있는 🔥가 규칙 변경 때문에 **소급으로 끊기지 않는다.**

하지 않는 것(YAGNI): 사람별 하루 목표 숫자 설정, 리더보드·포인트, 알림 문구 AI 생성, 이메일·SMS.

## 1. 공통 원칙

- **적용일 `STREAK_V2_FROM`** — 배포일(KST `YYYY-MM-DD`)을 상수로 박는다. 그 **이전 날짜는 옛 규칙**(§17-1 "답한 문항 ≥ 1"·§17-9·§23-9 그대로), **그날부터 새 규칙**(아래 §2). 🧊 카드·🔁 만회도 적용일부터만 계산한다.
- **새 저장 없이 파생** — 판정·카드·만회·배지는 전부 기존 학습 기록에서 날짜 순으로 계산한다(§17-5 원칙 유지). 같은 기록 → 같은 결과. 새 컬렉션은 알림용 `pushSubscriptions`·`pushLog` 둘뿐이다(§6).
- **사람·트랙 분리 유지** — 은우 / 아빠 📚 어학 / 아빠 💪 운동 / 엄마. 가족 연속일만 사람 단위로 묶는다(§3).
- 계산은 순수 모듈(`lib/streak*.ts`)에 두고 라우트는 읽기·조립만 한다. 오늘(KST)은 인자로 받는다.

## 2. 하루 목표량 — "한 판 끝내기" (적용일부터)

그날 아래 중 **하나라도 끝까지** 마치면 그 트랙의 그날이 켜진다("한 날").

| 트랙 | 한 판 | 판정(기록 필드) |
|---|---|---|
| 🧒 은우 | 영어 단어장 시험(그림 보고 말하기 포함) 1판 | `VocabQuizRecord` — `finishedAt ≠ null` **그리고** 모든 문항 `answered === true`(문항 1개 이상) |
| | 자유대화 1회 | `TalkSessionRecord.childTurnCount ≥ 3` |
| | 📅 오늘의 복습(영어) | §2-1 |
| 🧑 아빠 📚 어학 | 일본어 단어 시험·한자 시험 1판 | `JaQuizRecord`·`JaKanjiQuizRecord` — `finishedAt ≠ null` 그리고 모든 문항 answered |
| | 토익 표현 시험·틀 시험·틀 테스트 1판 | `ToeicQuizRecord` — 같은 조건 |
| | 토익 모의고사·한 문제 연습 응시 | `ToeicAttemptRecord` — `finishedAt ≠ null` 그리고 **응시 범위 문항(`questions`) 전부 녹음됨** |
| | 소재별 틀 말하기 1판 | `ToeicFrameDrillSessionRecord` — 모든 문항에 결과가 있고 `outcome === "spoken"` 문항 ≥ 1 |
| | 📅 오늘의 복습(일본어·토익) | §2-1 |
| 🧑 아빠 💪 운동 | 루틴을 지킨 날(§17-7 그대로) | `workoutKeptDays` — 변경 없음 |
| 👩 엄마 | 오늘의 레슨 1개 완료 | ② 엄마의 생활영어 스펙에서 정의(레슨 기록 `finishedAt` + 발화 체크까지) |

### 2-1. 오늘의 복습 한 판
그날 D에 그 영역 복습을 **1개 이상** 하고, 다음 중 하나면 한 판이다(`lib/review-schedule.ts` `reviewFullDays` — 순수, 영역 분리는 호출측):
- 그날 복습한 항목 수 ≥ `REVIEW_DAILY_CAP`(20), 또는
- **차례 온 기존 항목**(D 이전 마지막 이력 e의 `e.on + 간격[e.step] ≤ D`인 항목)이 있으면 그것을 **전부** D에 복습했다, 또는
- 차례 온 기존 항목이 없는 날은 D에 `REVIEW_NEW_ONLY_MIN_RUN`(5)개 이상 복습했다.

큐 크기를 재구성하지 않고 이력만으로 판정한다 — 같은 기록 → 같은 결과.

### 2-2. 화면
- 시험·훈련을 중간에 나가면 한 줄 안내: **"한 판을 끝내야 🔥가 켜져요."**(그만둠 확인 창이 있는 곳은 그 창에, 없는 곳은 결과 화면에)
- 상단 스트릭은 오늘 아직인 칸을 지금(흐림)보다 분명히 — 흐림 + 칸 옆 작은 점.

## 3. 엄마 칸 · 가족 연속일 · 가족 보드

### 3-1. 상단 스트릭
`👪 🔥N | 🧒 🔥 | 🧑 📚🔥 💪🔥 | 👩 🔥` — 엄마 칸과 가족 칸을 더한다. 엄마 칸은 엄마 영역(②)이 생기기 전에는 숨긴다. 360px·390px에서 가로 넘침 0을 실측하고, 넘치면 기존 `compact` 단계(사람 이모지 숨김)를 두 자리부터 적용한다.

### 3-2. 가족 연속일 👪
- **한 날 = 그날 모든 "참여자"가 자기 날을 지킨 날**(켜짐 또는 🧊 카드).
- 사람별 그날: 은우 = 은우 트랙 / 아빠 = 📚 어학 **또는** 💪 운동 / 엄마 = 엄마 트랙.
- 참여자: 엄마는 **첫 레슨 완료일부터** 참여자다(그 전 날짜는 은우·아빠 둘로 판정).
- 적용일 이전 날짜는 옛 규칙의 사람별 날로 계산한다(가족 연속일이 0에서 시작하지 않게).
- 연속·최고 기록은 기존 코어 `computeStreakFromDays`.

### 3-3. 가족 보드 `/family`
홈에 카드로 연결. 세 블록:
1. **오늘** — 사람별 ✓/아직 + 오늘 라벨(기존 `todayLabel`) + 만회 가능하면 "오늘 두 판이면 어제가 돌아와요".
2. **이번 주** — 월~일 × (은우·아빠·엄마) 칸: 🔥 / 🧊 / 🔁(만회로 살린 날) / ✗ / 빈칸(미래).
3. **기록** — 가족 연속일·최고, 사람별 이번 달 남은 🧊, 받은 배지.
4. **콕 찌르기** 버튼(아직인 사람 옆) — §6 알림이 켜진 뒤에만 보인다.

## 4. 보상과 만회

### 4-1. 배지
트랙별(은우·아빠 📚·아빠 💪·엄마)과 가족 👪에 **7·30·100·200·365일**. 최고 기록(`best`)이 그 숫자 이상이면 받은 것. 달성한 날(현재 연속이 그 숫자에 처음 닿은 날)에 화면 축하를 한 번 보인다 — 본 축하는 기기 `localStorage`에만 기억한다(실패해도 다시 보일 뿐).

### 4-2. 🧊 쉬는 날 카드
- 사람마다 **KST 달력 달마다 2장**, 이월 없음. 아빠는 사람 단위 2장(어학·운동 공용, 가족 판정용) — 트랙 🔥에도 같은 카드를 적용한다(놓친 트랙마다 1장씩 쓰지 않고, **그 사람의 그날 1장**으로 그 사람의 모든 트랙을 잇는다).
- **자동 사용**: 날짜를 오름차순으로 걸으며, 이전 날이 이어지고 있던 상태에서 놓친 날 D가 나오면(D가 오늘이 아닐 때) 그 달 남은 카드가 있으면 1장을 쓴다. **카드가 먼저다** — 만회(§4-3)는 그 달 카드가 바닥났을 때만 열린다. 이어지던 연속이 없으면(이미 끊긴 상태) 쓰지 않는다.
- 카드 쓴 날은 **연속을 잇지만 숫자는 올리지 않는다**(듀오링고 방식). `current`는 켜진 날 수, 카드 날은 건너뛰며 잇는다.
- 오늘은 아직 끝나지 않았으므로 오늘에 카드를 쓰지 않는다(오늘 아직 = 기존처럼 "어제까지 살아 있음").

### 4-3. 🔁 만회
- 놓친 날 D에 카드가 없으면, **D+1에 두 판**(서로 다른 세션 2개, §2의 한 판 조건)을 하면 D가 살아난다. D+1 하루만.
- 만회는 카드보다 **늦게** 판정한다: D+1이 끝나기 전에는 D를 "만회 대기"로 두고(연속은 살아 있는 것으로 보이되 보드에 안내), D+1에 두 판이면 D = 만회 날(🔁, 숫자 +1), 한 판 이하로 끝나면 D = 끊김.
- 만회로 살린 날은 그 자체로 한 날로 센다(숫자 +1). 만회 판정에 쓴 D+1의 두 판 중 하나는 D+1 자신도 켠다.

### 4-4. 순수 함수 계약
`computeStreakV2({ legacyDays, v2Days(day → 한 판 개수), from: STREAK_V2_FROM, today }) → { current, best, doneToday, lastDate, freezeDays, repairedDays, pendingRepairDay, freezeLeftThisMonth }`. 트랙·사람·가족 모두 이 하나를 쓴다(가족은 "사람별 그날 지킴"을 날짜 집합으로 접은 뒤 넣는다). 사람 단위 카드 공유는 호출측이 사람별로 한 번 계산한 `freezeDays`를 그 사람 트랙들에 넘기는 방식으로 한다.

## 5. API

`GET /api/streak` 응답을 넓힌다(기존 필드 유지·호환):
- 각 `PersonStreak.info`에 `freezeDays`·`repairedDays`·`pendingRepairDay`·`freezeLeftThisMonth`(선택 필드 — 옛 클라이언트는 무시).
- 새 필드 `mom: PersonStreak | null`(엄마 영역 전 = null), `family: PersonStreak`, `week: { days: string[]; rows: Record<"eunwoo"|"appa"|"mom", ("lit"|"freeze"|"repaired"|"pending"|"missed"|"future"|"none")[]> }` — `pending` = 만회 대기(§4-3, 오늘 두 판이면 살아나는 어제), `badges`.
- 읽기 실패 규약(트랙만 중립값) 그대로.

## 6. 폰 알림

### 6-1. 기반
- **PWA**: `app/manifest.ts`(이름·아이콘·`display: standalone`) + 서비스 워커 `public/sw.js`(push 표시·클릭 시 해당 화면 열기, 데이터 없음). iPhone은 iOS 16.4+ 홈 화면 추가가 전제 — 미설치면 알림 설정 자리에 설치 방법 안내.
- **기기 등록**: 설정에서 "나는 누구"(은우·아빠·엄마) 선택 → `PushManager.subscribe` → `POST /api/push/subscribe {person, subscription, prefs}`. 새 컬렉션 `pushSubscriptions` `{id = endpoint 해시, person, endpoint, keys, prefs, createdAt, lastOkAt}`. 해제 `DELETE`.
- **발송**: 새 의존성 `web-push`, env `VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY`·`PUSH_CRON_SECRET`(GitHub Secrets → Cloud Run). Cloud Scheduler 작업 1개가 08:00~22:30 KST **30분마다** `POST /api/push/tick`(헤더 `x-push-secret`)을 부른다. `proxy.ts`는 이 경로만 PIN 대신 비밀 헤더로 검사(불일치 401). 발송 기록 `pushLog` `{id = 날짜·사람·종류, sentAt}`로 같은 알림 중복을 막는다(문서 id 멱등 생성).
- 410/404 응답 기기는 구독 삭제. 키가 없으면 501(로컬 안전).

### 6-2. 알림 종류
| 종류 | 시각(기본, 사람별 변경 가능) | 조건 |
|---|---|---|
| ⏰ 오늘 아직 | 은우 18:00 · 엄마 20:00 · 아빠 21:00 | 그 사람 오늘 아직 |
| 🚨 마지막 | 22:30 | 오늘 아직. 카드가 남았으면 "오늘 못 하면 🧊가 쓰여요" |
| 🔁 만회 기회 | 08:30 | `pendingRepairDay`가 어제 |
| 👪 가족 | 21:00 → 엄마 폰(설정하면 아빠 폰도) | 은우 오늘 아직 |
| 👉 콕 찌르기 | 즉시 | 보드 버튼 `POST /api/push/poke {to}`. 받는 사람당 하루 2회 상한 |

- 그날 켜지면 그 사람의 남은 알림은 보내지 않는다. 사람당 하루 최대 3개(콕 찌르기 포함). 22:30 뒤·08:00 전 발송 없음.
- 문구는 고정 문자열(사람·종류별 표), 은우 문구는 1학년 눈높이. 클릭 시 열 화면: 은우 `/english`, 아빠 어학 `/review`(없으면 홈), 엄마 엄마 영역 홈, 가족 `/family`.
- 아빠 "오늘 아직" = 📚·💪 **둘 다** 아직일 때(사람 단위). 문구에 아직인 트랙을 적는다.

### 6-3. 인프라 변경(실행 전 사용자 확인)
Cloud Scheduler 작업 생성(`gcloud scheduler jobs create http …`)과 Secrets 등록은 오케스트레이터가 사용자 확인 뒤 실행한다. 비용: 웹 푸시 무료, Scheduler 작업 1개 무료 한도 안, tick당 `/api/streak` 수준의 읽기.

## 7. 검증

- `eval:streak` 확장(오프라인, 실호출 0): §2 판정 표 행마다 반례(그만둠·일부 답·발화 2·녹음 일부), 적용일 경계(전날 옛 규칙·당일 새 규칙), 복습 큐 재구성, 카드(월 2장·이월 없음·끊긴 뒤 미사용·오늘 미사용·사람 단위 공유), 만회(D+1 두 판·한 판·D+2 무효·대기 상태), 가족(엄마 참여 시작일·아빠 둘 중 하나), 배지 경계, 알림 결정 함수(종류·조건·상한·조용한 시간).
- QA(subject=common): 스펙만 보고 쓴 **독립 참조 모델**과 무작위 시나리오 차분(운동 엔진 선례 — 참조 모델은 저장소에 두지 않는다).
- 알림은 헤드리스 판정 불가 — 배포 뒤 세 사람 폰에서 설치·구독·수신·클릭 이동 확인 목록.
- 로컬은 `STORE_BACKEND=file`, 키 비움. `data/db.json` sha 대조.

## 8. 만드는 순서

1. 판정 규칙(§2) + 적용일 + 복습 큐 재구성 — 순수 함수·eval
2. 카드·만회·배지(§4) — 순수 함수·eval
3. 가족 연속일·응답 확장·상단 칸·가족 보드(§3·§5)
4. 알림(§6) — 별도 배포, 인프라 확인 뒤
각 단계 끝에 QA, 단계마다 배포 가능(1~3은 비용 0).

## 9. 위험

- 규칙이 엄격해져 첫 주에 끊김이 잦을 수 있다 → 카드·만회가 완충. 적용일 이전 소급 없음.
