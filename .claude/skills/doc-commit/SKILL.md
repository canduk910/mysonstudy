# doc-commit — 프로젝트 문서 최신화 & 커밋

**한 일이 문서에 반영돼야 문서가 거짓말을 안 한다.** 이 스킬은 최근 작업(git 이력)·메모리·**코드 실체**를 근거로 `.md` 문서를 현재 사실에 맞추고 커밋한다. **`.md`만 손댄다 — 코드는 절대 바꾸지 않는다.**

## 이 저장소의 함정 — 어기면 CI가 깨지거나 코드 참조가 끊긴다

1. **spec-sync 프롬프트 블록은 손대지 마라.** `docs/harness/english.md`·`math.md`의 "시스템 프롬프트 (원문 그대로 사용)" 코드블록은 `lib/ai/*/prompts.ts`와 **바이트 단위로 일치**해야 한다(`SPEC_SYNC_TARGETS`가 eval에서 대조). 이건 코드에서 동기화되는 값이지 손으로 고치는 산문이 아니다. **문서의 프롬프트 코드블록을 절대 수정하지 마라.** 프롬프트가 바뀌었다면 그건 코드(prompts.ts) 변경 시 함께 갱신됐어야 하는 것이고, 이 스킬 범위 밖이다.
2. **harness §번호를 다시 매기지 마라.** 코드 주석 수십 곳이 `§7-5`, `§2A-1`처럼 절 번호를 참조한다. 새 절은 **append**만 하고, 기존 §번호·순서는 절대 바꾸지 마라(끊긴 참조가 조용히 생긴다).
3. **CLAUDE.md 변경 이력 표는 append.** `| 날짜 | 변경 내용 | 대상 | 사유 |` 표에 **한 줄 추가**한다. 날짜는 **절대 날짜**로(상대 날짜 금지). 과거 행을 다시 쓰지 마라.
4. **"This is NOT the Next.js you know" 블록은 손대지 마라.** CLAUDE.md의 그 블록은 `next dev`가 자동으로 쓰고 재삽입한다(`node_modules/next/dist/server/lib/generate-agent-files.js`). 손으로 고치면 되돌려진다.
5. **모든 주장을 코드로 검증하라.** 메모리·git 로그는 힌트다. 문서에 "X 라우트가 Y를 한다"를 쓰기 전에 **그 파일·함수·플래그가 실제로 있는지** 연다. 메모리는 쓰인 시점의 사실이라 낡았을 수 있다 — 옛 파일명·함수명을 그대로 베끼지 마라.

## 워크플로우 (순서대로 — 각 단계 끝나고 다음)

### 1. 근거 수집
- **메모리**: `~/.claude/projects/-Users-koscom-IdeaProjects-mysonstudy/memory/MEMORY.md`와 memory 파일들을 읽는다. **비어 있을 수 있다** — 그러면 git·코드가 1차 근거다.
- **최근 작업**: 문서를 마지막으로 만진 이후의 커밋을 본다.
  - `git log --oneline -40` 으로 최근 흐름 파악. 문서에 안 반영된 기능·라우트·통합·폐기(deprecation)를 추린다.
  - 범위가 모호하면 사용자에게 "어디부터의 작업을 반영할지" 묻는다(예: 특정 커밋·날짜 이후).
- **코드 실체 확인**: 추린 변경마다 실제 파일을 열어 확인(§함정 5). 새 라우트는 `app/api/`, 새 lib은 `lib/`, 스키마·프롬프트 존재 여부.

### 2. 변경 → 영향 문서 매핑
문서 표면(전부 후보):
- `CLAUDE.md` — 서문 경고·하네스 개요·**변경 이력 표**·에이전트/스킬 구성.
- `README.md` — 앱 소개·실행법.
- `docs/SPEC.md` — 앱 전체 명세. `docs/HARNESS.md` — 과목 공통 AI 규약. `docs/DESIGN.md` — 디자인 토큰.
- `docs/harness/english.md`·`math.md` — 과목별 AI 호출 명세(§ append만, 프롬프트 블록 불가침).
- `.claude/skills/*/SKILL.md` + `references/*.md` — 에이전트 스킬·다이얼·정합성 매트릭스.
- `.claude/agents/*.md` — 에이전트 역할 정의(6개).
각 변경이 **어느 문서의 어느 절**에 걸리는지 목록으로 적는다. 안 걸리면 안 건드린다(불필요한 diff 금지).

### 3. 문서 갱신 (함정 준수)
- 각 문서의 **기존 문체·밀도·형식을 맞춘다**(이 저장소 문서는 "왜"를 길게 적는 산문체다 — 새 문장도 그 톤).
- **CLAUDE.md 변경 이력**: 이번 작업 묶음마다 표에 한 줄(절대 날짜·무엇·대상·사유).
- **새 기능/라우트/통합**: 해당 스펙 문서(SPEC.md 또는 harness/*.md)에 **절 append** 또는 기존 산문 갱신. 프롬프트 블록은 절대 편집 금지.
- **폐기·삭제**: 없어진 것을 문서에서 지우거나 "폐기됨" 표기(코드에 없는 걸 있다고 두지 마라).
- 확신 없는 사실은 **코드를 열어 확인 후** 쓴다.

### 4. 검증 (무비용)
- **spec-sync 안 깨졌는지**: `OPENAI_API_KEY= STORE_BACKEND=file EVAL_OFFLINE_ONLY=1 npm run eval:english` (실호출 0). 프롬프트↔스펙 바이트 일치 항목이 통과해야 한다 — 실수로 프롬프트 블록을 건드렸으면 여기서 잡힌다. 수학 쪽 변경이 있었으면 `eval:math`도 `EVAL_OFFLINE_ONLY=1`로.
- `git diff` 를 다시 읽어 **지어낸 사실·모순·낡은 파일명**이 없는지 자기 점검(brainstorming 스펙 자기검토 요령).
- 코드는 안 건드렸으니 tsc/build는 불필요(단, 실수로 .ts를 만졌으면 원복).

### 5. 커밋 (사용자 승인 후)
- **`.md`만 스테이징**한다(`git add`로 문서 파일만 — 코드가 섞이면 멈추고 사용자에게 알린다).
- 변경 요약(어느 문서·무엇을·왜)을 사용자에게 보여주고 **승인**을 받는다. 기본 브랜치(main)면 push가 곧 프로덕션 배포다 — **문서-only라 앱 동작은 안 바뀌지만 CI/배포가 돈다**는 점을 알린다.
- 커밋 메시지: `docs(<scope>): <요지>` + 프로젝트 트레일러(`Co-Authored-By: …`, `Claude-Session: …`).
- 승인받으면 커밋. push는 사용자가 원할 때만.

## 스코프 밖 / 안전
- **코드(.ts/.tsx/.css/스크립트) 변경 금지.** 문서-코드 불일치에서 **코드가 틀린** 경우는 고치지 말고 사용자에게 보고한다(이 스킬은 문서만 맞춘다).
- 프롬프트 블록·§번호·next.js 자동블록 불가침(위 함정).
- 확인 안 된 사실을 문서에 쓰지 마라 — 없는 기능을 있다고 적는 것이 낡은 문서보다 나쁘다.
- 이 저장소는 로컬 실행이 프로덕션 DB를 향할 수 있다(CLAUDE.md 서문) — eval 검증은 반드시 `OPENAI_API_KEY= STORE_BACKEND=file`로.
