# Card Eval — 프롬프트 튜닝과 회귀 평가

프롬프트도 코드다: 수정 → eval → 통과 → 커밋. eval 없이 프롬프트를 커밋하지 않는다 (docs/harness/english.md §6 운영 규칙).

## 튜닝 루프

1. `docs/harness/english.md` §3-1·§6에서 바꿀 다이얼을 확인한다.
2. 아래 동기화 표에 따라 관련 파일을 **한 번에 같이** 수정한다.
3. `npm run eval:english` 실행 — `OPENAI_API_KEY` 필요, 실호출 2회 발생. 키가 없으면 실행하지 말고 정적 검증(동기화 지점 대조)만 한 뒤 "eval 미실행"을 리포트에 명시한다. 비용 승인 없이 반복 실행하지 않는다.
4. 전 항목 pass 확인 후 커밋을 권고한다.

## 다이얼 → 동기화 지점

다이얼 하나를 바꾸면 해당 행의 모든 위치를 같이 바꾼다. 하나라도 빠지면 eval 또는 런타임 검증이 어긋난다.

| 다이얼 | english/prompts.ts (§3-1) | zod 검증 (english/schemas.ts) | eval-english.ts |
|--------|-------------------|----------------------|---------------|
| vocab 개수 | [vocab] 개수 규칙 | 길이 검증 | 점검 항목 1 |
| challenge 비율 | difficulty 규칙 | (검증 있다면 함께) | (검증 있다면 함께) |
| 질문 개수·필수 유형 | [questions] | 길이·유형 중복 검증 | 점검 항목 1 |
| 질문/예문 길이 제한 | "15단어 이하"·"4~8단어" 문구 | — | 점검 항목 3 |
| hintKo 밀도 | "절반 정도" 문구 | — | 점검 항목 4 (30~70%) |
| 사이트워드 목록 | 서술만 (변경 불필요) | 공유 상수 import | 같은 상수 import — 목록 자체는 english/schemas.ts 한 곳만 수정 |

수정 후 study-qa 스킬의 정합성 매트릭스로 대조하면 누락을 잡을 수 있다.

## 픽스처 (docs/SPEC.md §12 원본 값 — 임의 변경 금지)

| 필드 | Wolves | Pooh Gets Stuck |
|------|--------|-----------------|
| title | Wolves | Pooh Gets Stuck |
| author | Laura Marsh | Isabel Gaines |
| series | National Geographic Kids Readers, Level 2 | A Winnie the Pooh First Reader |
| isFiction | false | true |
| arLevel | 3.3 | 2.0 |
| lexile | 570 | 430 |
| wordCount | 864 | 551 |
| arQuizNo | "148832" | "41866" |
| topic | 늑대 — 무리(pack) 생활, 하울링, 사냥, 새끼 키우기 | 푸가 꿀을 너무 많이 먹고 토끼네 집 구멍에 끼는 소동 |

분기 커버리지: 두 픽스처 모두 AR≥2라서 vocab 12·질문 8 경로다. 픽션/논픽션 분기(funFacts null vs 4개)는 둘이 나눠 커버한다. **AR<2 경로(vocab 10·질문 6)는 픽스처가 커버하지 않는다** — AR<2 관련 다이얼을 바꿀 때는 AR 1점대 임시 메타데이터로 수동 스팟 체크를 1회 수행하고 결과를 리포트에 남긴다.

## 결과 해석 가이드

| 실패 항목 | 먼저 볼 것 | 통상 원인 · 조치 |
|-----------|-----------|-----------------|
| vocab/질문 개수 | 프롬프트 개수 규칙 vs zod 값 | 동기화 누락이 먼저 의심. 값이 맞는데 실패하면 모델이 규칙을 놓친 것 → 개수 규칙을 해당 섹션 첫 줄로 올린다 |
| 사이트워드 검출 | 검출된 단어 목록 | 프롬프트 제외 규칙에 해당 단어 계열의 예시를 추가한다 |
| hintKo 비율 | 실제 비율 수치 | "절반 정도"를 구체 숫자로 바꾼다 (예: "8개 중 4개에만") |
| 15단어/8단어 초과 | 초과한 문장 | 길이 제한을 예시와 함께 강조한다 |
| ko에 영어 잔존 | 해당 질문 쌍 | ko는 번역이 아니라 우리말 재표현임을 프롬프트에 명시한다 |

같은 항목이 2회 연속 실패하면 프롬프트를 더 조이는 대신, 실패 사례를 리포트에 담아 다이얼 자체(개수·비율)가 현실적인지 사용자와 논의한다. 프롬프트가 길어질수록 다른 규칙 준수율이 떨어진다.

## 하지 말 것

- 스키마 구조 변경(필드 추가/삭제/타입 변경)은 튜닝이 아니다 → ai-engineer 영역. 오케스트레이터에 위임 요청으로 반환한다.
- eval을 CI에 넣지 않는다 (실호출 비용, §5). 수동 실행 전용.
- 표지 판독 프롬프트(§2-1)는 정확성 파이프라인이므로 카드 품질 튜닝에서 건드리지 않는다.
